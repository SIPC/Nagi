# Nagi（凪）

> 风平浪静的 Docker 项目面板。

Nagi 是一个开源的 Docker 项目面板，自用优先。目标是**简单、好看、好部署**，能直接用于生产，并支持高可用。

> 状态：开发中。MVP 的功能都已实现并在多节点环境里实测过，界面还是临时的，尚未发布。

## 为什么是 Nagi

Coolify、Dokploy、Komodo、Portainer、1Panel 这些面板功能都很多，但也复杂、难上手，界面不够好看。Nagi 不打算在某个单项功能上胜出，它的差异在于**简单**：

- **只有三个概念**：节点、项目、成员。项目是一组一起工作的成员（前端、后端、数据库……），每个成员是一个容器或一份 compose。
- **compose 是唯一的底层定义**：每个成员都是一份 compose，随时可以导出，脱离 Nagi 照样运行。
- **默认值就能上生产**：高级选项默认折叠。
- **一个项目，一个页面**：部署、日志、终端、域名、备份都在同一页完成。
- **不依赖外部平台**：不需要域名、外部 CA 或任何云服务就能跑起来。

## 快速开始

> 尚未发布，命令可能会变。

运行在 Linux（amd64 / arm64）上，唯一的前置依赖是 Docker 和 compose 插件（2.24 或更新版本）。

单机使用（server 自带一个内嵌 agent）：

```bash
nagi server
```

面板首次启动时会随机选一个端口并记住，启动日志里会输出面板地址；也可以用 `--port` 指定。80/443 留给项目域名的 HTTPS。

添加更多节点：在面板里复制安装命令，到新机器上执行。命令会从面板下载 nagi 并完成加入，全程用面板的公钥指纹校验身份，令牌一次性、1 小时内有效：

```bash
curl --pinnedpubkey "sha256//<面板公钥指纹>" -k https://<地址:端口>/install.sh | sh -s -- --token <令牌>
```

换面板或多个面板一起管理：在新面板上生成接入码，粘贴到旧面板，选择"移交"或"共同管理"。旧面板已经挂了的话，在节点上执行：

```bash
nagi panel add <接入码>
nagi panel remove <旧面板地址>
```

## 功能（MVP）

- 节点一键加入
- 项目全流程：一个项目放多个成员，各自部署和回滚，也可以一起部署、整个项目回到某次部署时的状态；修改先存草稿再部署；日志、终端
- 项目内网：成员之间用名字互相访问，项目之间默认隔离
- 两种加成员的方式：直接写 compose；或者填镜像表单，直接运行在线镜像，也可以附带文件
- 镜像更新提醒、版本回滚到当时的镜像、国内节点镜像加速
- 对外访问统一走内嵌 Caddy：域名与自动 HTTPS，TCP/UDP 端口转发，界面上按服务开关
- 环境变量（项目共享、成员、服务三层）与密钥、私有镜像仓库认证、健康检查、资源限制
- 监控与告警：节点、容器、健康检查和访问指标；webhook 和 Telegram 告警，面板挂了照常发送
- 快照：定时备份、恢复；可指定备份节点作为异地副本；手动迁移项目不丢数据
- 节点间 WireGuard 组网；共享网络可以跨节点连接，不同节点上的项目照常按名字互相访问
- 项目数据存在节点上，面板只是遥控器和备份：面板挂掉不影响业务，换一个面板数据自动回来；节点彻底坏了还能用面板上的配置备份重建项目
- 为项目指定顶替节点：所在节点挂了，由顶替节点接手；不指定就不动
- 多面板：一个节点可以同时被多个面板管理；换面板需要旧面板授权，旧面板挂了可以在节点上用本地命令处理
- 面板安全：可选 TOTP 两步验证、登录限速、可选安全入口
- 面板一键升级节点

暂不支持：项目跨节点部署、自动调度、多用户、恢复演练、接管已有项目、在节点上构建、应用模板。

一个项目的所有容器只运行在同一个节点上。

## 架构概览

```
            浏览器
              │ HTTPS :<面板端口>
   ┌──────────▼──────────┐
   │     nagi server      │  Web UI + 接口 + SQLite
   │  (遥控器 + 备份)    │  也加入 mesh
   └──▲──────────────▲───┘
      │ mTLS         │ mTLS           控制面：agent 主动连入面板端口
 ┌────┴─────┐   ┌────┴─────┐
 │nagi agent│◄─►│nagi agent│          数据面：WireGuard 全连接 mesh
 │ compose  │   │ compose  │
 │ Caddy    │   │ Caddy    │          所有对外流量从 Caddy 进入
 └──────────┘   └──────────┘
```

只有一个二进制 `nagi`，通过子命令区分角色。详见 [设计文档](docs/README.md)。

## 技术栈

- 后端：Go，gRPC（反向调用，yamux 复用），Connect-RPC，SQLite（modernc 纯 Go 实现），wireguard-go（用户态），内嵌 Caddy（含 layer4 模块），内嵌 kopia
- 前端：Vite + React + TypeScript + TanStack Router/Query + shadcn/ui，支持深浅色，适配移动端
