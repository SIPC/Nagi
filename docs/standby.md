# 主备面板

一个**主面板**加任意个**备用面板**。主面板负责所有修改和下发；备用面板实时同步主面板的数据，平时只读。主面板坏了，在备用面板上点"提升为主面板"，数据是完整的（草稿、版本记录、部署记录都在），不用从节点缓存拼回。

主备面板是同一个面板的几份副本，不是几个面板一起管理：同一时间只有一个主面板能修改和下发，所以不会出现两份配置。和别的面板之间照常只有[移交](control-plane.md#信任的面板列表)。

## 配对

1. 在主面板的设置页"备用面板"里点"添加备用面板"，生成一个**配对码**（`nagi-standby:...`，包含主面板的地址、公钥指纹和一次性令牌，1 小时内有效，用一次就作废）。
2. 在新机器上用配对码启动：`nagi server --standby <配对码>`（数据目录须为空）。备用面板钉住主面板的公钥指纹连上去，用令牌登记，拿到：
   - **主密钥**：数据库里的加密数据要用它解开；
   - **面板 CA**：主备面板共用一个 CA，节点的客户端证书在每个面板上都有效，节点不用重新加入；
   - 第一份完整的数据库。
3. 备用面板生成自己的服务端密钥（自己的公钥指纹）和 mesh 密钥，有自己的对外地址。配对完成后，主面板把它加进各节点的信任列表（不需要令牌：节点的证书本来就是这个 CA 签的），节点开始同时连接它。

备用面板用 `--no-agent` 之外的方式启动时，内嵌节点照常是一个普通节点，由主面板管理。

## 同步

- 备用面板一直连着主面板，主面板的数据库有变化（几秒内），就把一份一致的数据库快照发给它（`VACUUM INTO` 生成，数据量很小）。备用面板原子地替换自己的数据库。
- **不同步的本地数据**：每个面板自己的设置（对外地址、绑定的域名、面板端口）、登录会话、自己的 TLS 和 mesh 密钥。替换数据库时保留这些。
- 备用面板记下最近一次同步的时间，界面上显示"已同步（3 秒前）"；连不上主面板超过 1 分钟时告警。

## 谁是主面板：任期

- 主面板有一个**任期号**（存在数据库里，随同步传给备用面板）。提升备用面板时任期号加一。
- 面板连上节点时告诉节点自己的任期和是不是主面板。节点记下见过的最大任期和那个任期的主面板，**只执行这个主面板发来的修改和操作**（部署、下发配置、删除、终端……）；其他面板只能查询（状态、日志、监控）。
- 旧主面板回来时，节点告诉它当前的主面板和任期。旧主面板发现自己的任期落后，自动降为备用：丢弃自己在离开期间的修改（没有下发出去，节点也不会执行），然后从新的主面板同步。

## 提升

- 在备用面板上点"提升为主面板"（确认框说明：主面板还在运行时不要提升；提升后原主面板回来会自动降为备用，它最后几秒内的修改可能丢失）。
- 备用面板把任期加一，成为主面板，通知各节点；其他备用面板改为从它同步。
- **只支持手动提升**：面板坏了业务本来就照常运行，不急；自动提升要处理网络分区时两边都以为对方挂了的情况，暂不做。

## 只读的备用界面

- 备用面板的网页能登录（账号和主面板一样），看项目、节点、日志、监控；修改按钮置灰，顶部提示"这是备用面板，修改请到主面板 <地址>"，并显示同步状态和"提升为主面板"按钮。
- 备用面板的接口拒绝所有修改，返回"这是备用面板"。

## 顶替的见证人

见证人是"面板"时，由**当前的主面板**担任。提升后，新主面板按[换面板时的做法](failover.md#实现)把这些容器的见证人换成自己（换之前 A、B 两票照常构成多数）。

## 移除备用面板

在主面板的"备用面板"列表里移除：主面板从各节点的信任列表移除它，并拒绝它再同步。备用面板上的数据目录由用户自己删除。
