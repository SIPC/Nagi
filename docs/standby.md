# 主备面板

一个**主面板**加任意个**备用面板**。主面板负责所有修改和下发；备用面板实时同步主面板的数据，平时只读。主面板坏了，在备用面板上点"提升为主面板"，数据是完整的（草稿、版本记录、部署记录都在），不用从节点缓存拼回。

主备面板是同一个面板的几份副本，不是几个面板一起管理：同一时间只有一个主面板能修改和下发，所以不会出现两份配置。和别的面板之间照常只有[移交](control-plane.md#信任的面板列表)。

## 配对

1. 在主面板的设置页"备用面板"里点"添加备用面板"，生成一个**配对码**（`nagi-standby:...`，包含主面板的地址、公钥指纹和一次性令牌，1 小时内有效，用一次就作废）。
2. 在新机器上用配对码启动：`nagi server --standby <配对码>`（数据目录须为空；配过对以后这个参数不再起作用，可以留在服务配置里）。备用面板钉住主面板的公钥指纹连上去，用令牌登记，拿到：
   - **主密钥**：数据库里的加密数据要用它解开；
   - **面板 CA**：主备面板共用一个 CA，节点的客户端证书在每个面板上都有效，节点不用重新加入；
   - 第一份完整的数据库。
3. 备用面板生成自己的服务端密钥，配对时把它的公钥指纹和自己的对外地址一起交给主面板登记。配对完成后，主面板把它加进各节点的信任列表（不需要令牌：节点的证书本来就是这个 CA 签的），节点开始同时连接它。

配对来的面板不带内嵌节点（相当于 `--no-agent`），提升为主面板以后也不带；第一个主面板带着内嵌节点，降为备用面板以后内嵌节点照常运行。

备用面板一直连着主面板同步（面板端口，TLS ALPN `nagi-standby/1`，钉住主面板的公钥指纹）。它出示的客户端证书用的是自己的服务端密钥（面板 CA 签发，各面板都有 CA），主面板按公钥指纹认出是登记过的哪个备用面板：所以降为备用的原主面板不用重新配对就能同步。在主面板上移除以后，同步连接立即断开，之后的连接被拒绝。

## 同步

- 备用面板一直连着主面板，主面板的数据库有变化（几秒内），就把一份一致的数据库快照发给它（`VACUUM INTO` 生成，数据量很小）。备用面板原子地替换自己的数据库。
- **不同步的本地数据**：每个面板自己的设置（对外地址、绑定的域名、面板端口）、登录会话、自己的 TLS 和 mesh 密钥。替换数据库时保留这些。
- 备用面板记下最近一次同步的时间，界面上显示"已同步（3 秒前）"；连不上主面板超过 1 分钟时告警。

## 谁是主面板：任期

- 主面板有一个**任期号**（存在数据库里，随同步传给备用面板）。提升备用面板时任期号加一。
- 面板在上报的回复里告诉节点任期、主面板和所有成员（主面板和备用面板的地址、公钥指纹）。节点按面板 CA 分组（同一组面板共用 CA；节点同时信任别的面板时互不影响）记下见过的最大任期和那个任期的主面板（`identity/cluster.json`），**只执行这个主面板发来的修改和操作**（部署、下发配置、删除、终端……）；其他面板只能查询（状态、日志、监控、快照列表、mesh 状态），修改返回"这是备用面板，只能查询；修改请到主面板 <地址>"。
- 成员列表只听当前主面板的：列表里新出现的备用面板，节点自动加进信任列表（证书沿用主面板签发的那张），标记为"由主面板管理"；列表里没有了就移除。主面板本身不在节点的信任列表里了（例如节点移交给了别的面板），它的备用面板一起移除。
- 节点上报时带上自己记下的任期和主面板，面板据此发现自己落后（第 3 步用）。
- 节点认了新的主面板以后马上再上报一次。面板在节点上报里看到节点认的是自己，才下发告警配置、面板域名、补推容器配置（之前发的会被节点拒绝）。
- 旧主面板回来时，节点在上报里告诉它当前的任期和主面板。**面板不直接相信节点的说法**（节点可能被攻破，随便报一个任期就能让面板降级、去同步攻击者的地址）：
  - 只考虑本组登记过的面板（`standby_panels` 里有的），地址也只用数据库里记的，不用节点报的；
  - 用这个地址、钉住那个面板的公钥指纹，请求它的 `GET /api/standby/status`（任期、主面板、自己是不是主面板；公开信息，不用登录），它自己确认是主面板、任期不比本面板小，才改为跟随它；
  - 核实过的任期记在本面板自己的设置里（`seen_term`，同步时不覆盖），以后提升时任期比它大。节点报的任期不算。
- 确认以后，旧主面板自动降为备用：写下 standby.json，面板在进程内按备用面板重新启动，从新的主面板同步，丢弃自己在离开期间的修改（没有下发出去，节点也不会执行）。其他备用面板也是这样发现新的主面板、改为从它同步。
- 主备信息只由主面板在上报的回复里告诉节点，备用面板不发。

## 提升

- 在备用面板上点"提升为主面板"（顶部提示条和设置页都有；确认框说明：主面板还在运行时不要提升；提升后原主面板回来会自动降为备用，它最后几秒内的修改可能丢失）。
- 备用面板停止同步，把任期加一、记下自己是主面板，把原主面板登记为备用面板（名称"原主面板"），删掉 standby.json，然后在进程内按主面板重新启动（登录会话保留，页面几秒后自动刷新）。节点下次上报时收到新的任期，只接受它的修改；其他备用面板从节点那里知道新的主面板，改为从它同步。
- 节点缓存的配置里记着写它的面板；同一组主备面板写的都算自己写的，提升以后不会触发"以节点为准拼回"。组里出现过的面板记在 `panel_members` 里（配对、提升时加入，只增不减），移除备用面板以后它写过的配置也照样算自己的。新的主面板看到节点缓存的配置是别的面板写的，会重新推一次，记上自己。
- 提升的数据库改动在一个事务里；没提升成时按备用面板重新启动，恢复同步。
- **只支持手动提升**：面板坏了业务本来就照常运行，不急；自动提升要处理网络分区时两边都以为对方挂了的情况，暂不做。

## 只读的备用界面

- 备用面板的网页能登录（账号和主面板一样），看项目、节点、日志、监控；修改按钮置灰，顶部提示"备用面板 · 只能查看，修改请到主面板 <地址>"，并显示同步状态和"提升为主面板"按钮。
- 备用面板的接口只放行查询（方法名以 Get、List、Query、Stream、Check、Ping 开头的，以及登录、退出），其余返回"这是备用面板，只能查看；修改请到主面板 <地址>"；webhook、上传、终端也拒绝。
- 备用面板不给节点下发任何东西（不补推配置、不下发告警配置和面板域名），不进 mesh。节点上的"受信面板"里标出主面板和备用面板。

## 顶替的见证人

见证人是"面板"时，由**当前的主面板**担任。提升后，新主面板按[换面板时的做法](failover.md#实现)把这些容器的见证人换成自己（换之前 A、B 两票照常构成多数）。

## 移除备用面板

在主面板的"备用面板"列表里移除：主面板从各节点的信任列表移除它，并拒绝它再同步。备用面板上的数据目录由用户自己删除。
