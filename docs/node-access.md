# 节点访问：终端和文件

管理员可以在节点页直接打开节点的终端、管理节点上的文件。不需要 SSH 账号，不需要开放端口，节点在 NAT 后面也能用。

这等于把节点的 root 权限交给了浏览器，所以默认开启的同时要守住三件事：只给管理员、打开前再验证一次身份、全程留痕。

## 通道

| 操作 | 通道 | 原因 |
| --- | --- | --- |
| 终端 | 控制连接 | 流量小；mesh 坏了也能用来排查；mesh 上有别的节点，shell 不放上去 |
| 浏览目录、读写小文本、删除、新建目录 | 控制连接 | 都是小请求，`primaryGuard` 统一拦截备用面板 |
| 上传、下载 | mesh | 大文件不占用控制连接；直连不通时自动经面板中转 |

```
浏览器 ──WebSocket──► 面板 ──控制连接（mTLS）──► nagi agent ──PTY──► 节点上的 shell
```

mesh 上的上传下载接口要自己检查调用方：公钥必须属于节点信任的面板，而且是当前的主面板（`primaryGuard` 只挂在控制连接上）。节点之间互相调用一律拒绝。

## 权限

- **只有管理员**：终端和文件接口都在服务端判断角色。操作员、只读账号的节点页看不到入口，接口也拒绝。
- **高权限确认**：打开终端、浏览文件前要再验证一次身份：开了两步验证的账号输验证码，没开的输密码。验证通过后这个会话 15 分钟内不再询问（`sessions.elevated_until`，只记在服务端）。失败次数和登录共用限速。已经打开的终端不因为确认过期而断开。
- **接口命名**：`auth.Allowed` 按方法名前缀放行查询，所以 `ListNodeDir`、`ListNodeFileBackups` 必须登记在 `adminReads` 里。读文件内容叫 `ReadNodeFile`，不用查询前缀：默认只有管理员能调用，也会记入活动记录。
- **节点本地开关**：`nagi node access disable` 在节点上关闭这个功能（标记文件 `identity/node-access-disabled`），终端和文件都拒绝，立即生效。面板没有接口能重新打开，所以面板被攻破也开不了；要打开得登录节点执行 `nagi node access enable`。节点随上报告诉面板当前状态，界面按它显示说明。
- **备用面板**：不能打开终端，也不能访问节点文件。

### 操作员不能借 compose 拿到节点 root

只给管理员的前提是操作员没有别的路拿到 root。容器能以特权运行或者挂载主机目录时，就等于拿到了 root，所以这类配置只有管理员能保存（`spec.PrivilegeReasons`）：

- `privileged`，`cap_add`、`devices`、`security_opt` 等扩大权限的字段
- `network_mode`、`pid`、`ipc`、`uts`、`userns_mode`、`cgroup` 设为 `host`
- 挂载绝对路径、`~`、带 `..` 的路径（包括 `docker.sock`）；`env_file`、`secrets`、`configs` 读取容器目录以外的文件
- `include`、`extends` 引用文件，`build`，指定了 driver 的 volume，`external` 的 volume 和网络
- 上面这些字段的值里有变量：变量的值操作员能改

规则按"读不懂就当作有特权"判断。管理员保存过的配置，操作员可以部署和回滚，也可以改和这些字段无关的部分；但配置里的特权字段用了变量时，操作员不能改容器变量和项目共享变量。操作员也不能把容器目录放到节点的项目根目录以外。已有的配置不受影响。

## 留痕

- **活动记录**：打开和关闭终端（时长、来源 IP）、读写删除文件（路径）都记入 `activity`，失败和被拒绝的也记。文件内容、终端内容不记。容器终端的打开也记入。
- **告警**：打开节点终端时，向告警配置里的所有渠道发一条通知，所以账号被盗用时用户能马上知道。
- **节点本地日志**：节点也记一条日志，带面板指纹和面板传来的用户名。面板的记录被篡改时还能在节点上查。
- **不录像**：终端的输出里可能有密钥，录下来本身就是风险；命令也可以编码、从文件执行，录制做不到完整。不做命令黑名单，一样能绕过，还会让人误以为安全。

## 终端

- **shell**：节点上 root 用户的登录 shell，没有时依次试 `bash`、`sh`。身份就是 nagi 的运行身份（root）。
- **环境变量**：不继承节点进程的环境变量，只设 `PATH`、`HOME`、`USER`、`LOGNAME`、`SHELL`、`TERM`、`LANG` 和 `NAGI_NODE_SHELL=1`。
- **cgroup**：节点用 systemd 运行时，shell 用 `systemd-run --scope` 放进单独的 scope，否则 `systemctl restart nagi-agent` 或 Nagi 升级会连带杀掉在 shell 里启动的 `tmux`。没有 systemd（或调用失败）时直接启动。
- **结束**：连接断开就结束 shell，第一版不做断线续连，长任务用 `tmux` 或 `nohup`。
- **时长**：没有输入输出 1 小时后断开，最长 12 小时。每 30 秒重查一次会话和角色，被踢出或者降权就断开。每个节点同时最多 8 个终端。
- **容器里的节点**：节点跑在容器里时，shell 进的是这个容器，不是主机。节点上报 `in_container`，界面上说明。
- **局限**：完全依赖 agent，agent 挂了或者节点断开时用不了，机器上的 SSH 要留着救场。

## 文件

路径一律先解析成真实路径（符号链接解开）再判断规则，界面上显示真实路径。

| 区域 | 规则 |
| --- | --- |
| `/proc`、`/sys`、`/dev`、Nagi 自己的数据目录 | 禁止访问（Nagi 的数据目录里有私钥；面板自带的节点，面板的数据目录也算） |
| 容器目录 | 只读：部署时会重写其中的文件，写入也绕过了容器的锁和租约。要改文件用容器页的文件管理 |
| `/etc/passwd`、`/etc/shadow`、`/etc/sudoers`、`/etc/ssh`、`/etc/fstab`、`/etc/pam.d`、`/etc/cron*`、`/etc/docker/daemon.json`、`/boot`、任何 `.ssh` 目录 | 可以改，保存前要确认（接口带 `confirmed`） |
| 其他 | 可以浏览、下载、上传、编辑 1 MB 以内的文本 |

这些规则防误操作、减轻会话被盗的影响，不是安全边界：管理员能用终端绕过。

- **写入**：同目录写临时文件再改名，沿用原文件的权限和属主；新文件跟随所在目录的属主。父目录用 `os.Root` 打开，并再次核对真实路径，防止中途被换成符号链接。
- **挂载的单个文件**：改名会失败（`EBUSY`、`EXDEV`），改为原地写入，界面提示这次不是原子写入。
- **防止覆盖别人的修改**：保存时带上打开时内容的 SHA-256，文件已经变了就拒绝，界面显示差异，用户决定覆盖还是放弃。
- **备份**：覆盖 1 MB 以内的文件前保留旧内容，放在 `<节点目录>/file-backups/`（权限 0600），每个文件最近 10 份，整个节点最多 200 份。可以在编辑页查看并恢复。超过 1 MB 的文件和删除不备份，界面上说明。
- **删除**：符号链接只删链接。不能删 `/` 和一级目录；不能删禁止或只读的路径，也不能删包含它们的目录；不能删挂载点或者包含挂载点的目录。删目录要输入目录名。
- **下载**：目录打包成 tar.gz，跳过符号链接、特殊文件和禁止访问的路径。不能下载 `/` 整个打包。
- **上传**：单个文件最大 8 GB，先写到 `<节点目录>/node-files-staging/`，传完才写到目标位置。

## 界面

节点页多两个标签：**终端**、**文件**。只有管理员能看到，节点离线、在本地关闭或者版本过旧时显示原因。

- 终端顶部一直显示 `root · 节点名`，防止敲错机器；节点跑在容器里时说明进的是容器。手机上终端上方有 Esc、Tab、方向键和 Ctrl。
- 文案简短、正式，不解释来龙去脉。
- 文件页可以"在此打开终端"。终端打开过以后，切到别的标签不断开。
- 没开两步验证的管理员，确认框里提醒开启。

## 无法消除的风险

- **管理员账号或面板被攻破**：相当于节点 root 泄露。这个功能只能缩小窗口、留下痕迹。没开两步验证时，高权限确认只能防 cookie 被盗，防不了密码泄露。
- **面板被攻破**：攻击者本来就能借 compose 控制节点，所以节点访问不算全新的攻击面，只是更方便；不放心的节点用本地开关关闭。
