# 节点访问：终端和文件

管理员可以在节点页直接打开节点的终端、管理节点上的文件。不需要 SSH 账号，不需要开放端口，节点在 NAT 后面也能用。

这等于把节点的 root 权限交给了浏览器，所以默认开启的同时要守住三件事：只给管理员、打开前再验证一次身份、全程留痕。

## 通道

| 操作 | 通道 | 原因 |
| --- | --- | --- |
| 终端 | 控制连接 | 流量小；mesh 坏了也能用来排查；mesh 上有别的节点，shell 不放上去 |
| 浏览目录、读写小文本、删除、新建目录、改名、移动、复制、压缩、解压、目录大小 | 控制连接 | 只有请求和进度，内容在节点本地处理；`primaryGuard` 统一拦截备用面板 |
| 上传、下载 | mesh | 大文件不占用控制连接；直连不通时自动经面板中转。节点有公网 IP 时下载由浏览器直接从节点获取，见 [agent.md](agent.md#直连下载) |

```
浏览器 ──WebSocket──► 面板 ──控制连接（mTLS）──► nagi agent ──PTY──► 节点上的 shell
```

mesh 上的上传下载接口要自己检查调用方：公钥必须属于节点信任的面板，而且是当前的主面板（`primaryGuard` 只挂在控制连接上）。节点之间互相调用一律拒绝。

## 权限

- **只有管理员**：终端和文件接口都在服务端判断角色。操作员、只读账号的节点页看不到入口，接口也拒绝。
- **高权限确认**：打开终端、浏览文件前要再验证一次身份：开了两步验证的账号输验证码，没开的输密码。验证通过后这个会话 15 分钟内不再询问（`sessions.elevated_until`，只记在服务端）。失败次数按 IP 和登录共用，另外按账号计数（见 [panel.md](panel.md) 的登录限速）。已经打开的终端不因为确认过期而断开。同样要先确认的还有：导入现有目录、生成访问令牌、OAuth 授权页上点允许、确认从节点缓存恢复的高可用设置、指定副本的存放位置（见 [snapshot.md](snapshot.md#副本的存放位置)）、开启两步验证（否则拿到会话的人能换上自己的密钥，再用它通过确认，账号主人也登不上了；已开启时确认用的是当前的验证码）。还有新建成员和修改成员（角色、访问范围、重置密码、清除两步验证和通行密钥），否则拿到会话的人能建一个自己知道密码的管理员，再用它通过确认；生成备用面板的配对码（配对会交出 CA、主密钥和整个数据库）、把节点移交给别的面板、提升备用面板，这三项和生成访问令牌一样只认密码或验证码做的确认，手机的确认密钥不算（`auth.passwordElevation`），备用面板上也能做确认。
- **接口命名**：`auth.Allowed` 按方法名前缀放行查询，所以 `ListNodeDir`、`ListNodeFileBackups`、`ListNodeDirSizes` 必须登记在 `adminReads` 里。读文件内容叫 `ReadNodeFile`，不用查询前缀：默认只有管理员能调用，也会记入活动记录。
- **节点本地开关**：`nagi node access disable` 在节点上关闭这个功能（标记文件 `identity/node-access-disabled`），终端和文件都拒绝，立即生效。面板没有接口能重新打开，所以面板被攻破也开不了；要打开得登录节点执行 `nagi node access enable`。节点随上报告诉面板当前状态，界面按它显示说明。
- **备用面板**：不能打开终端，也不能访问节点文件。
- **MCP**：在节点上执行命令（`node_exec`）和节点文件的工具，只有管理员生成访问令牌或者 OAuth 授权时单独勾了「节点终端」才有。令牌做不了高权限确认，勾这一项前已经确认过身份，所以这样的令牌调用节点文件这类接口时算确认过；每次执行命令、每次修改文件都要用户在 agent 里确认，执行命令还会告警，节点本地开关同样生效（见 [mcp.md](mcp.md#高权限确认)）。

### 操作员不能借 compose 拿到节点 root

只给管理员的前提是操作员没有别的路拿到 root。容器能以特权运行或者挂载主机目录时，就等于拿到了 root，所以这类配置只有管理员能保存（`spec.PrivilegeReasons`）。能碰到别的项目的容器、卷和网络的写法也一样（限定了项目范围的操作员不能借此越过范围）：

- 服务字段按白名单判断：`image`、`command`、`environment`、`ports`、`healthcheck`、`restart`、资源限制这类不碰节点的字段直接放行（`safeServiceFields`），下面单独检查值的字段按规则判断，其余字段一律算有特权，`x-` 开头的扩展字段除外。例如 `privileged`，`cap_add`、`devices`、`security_opt`、`gpus`、`blkio_config`，以及把节点的 docker.sock 挂进容器的 `use_api_socket`。compose 还在不断增加字段，节点上的版本也不由 Nagi 决定，所以不按「已知危险的字段」逐个列。顶层段同样按白名单，`services`、`volumes`、`networks`、`secrets`、`configs`、`name`、`version` 和 `x-` 以外的（例如 `models`）算有特权
- `container_name`（能抢占别的项目的容器名）、`annotations`（交给容器运行时）；`oom_score_adj` 为负数、`oom_kill_disable`（内存不够时内核先杀节点进程和别的容器）；`ulimits` 里的 `rtprio`、`rttime`、`nice`、`memlock`（能抢占整个节点的 CPU 和内存）
- `logging` 必须写驱动，只放行 `json-file`、`local`、`none`，选项只放行 `max-size`、`max-file`、`compress`、`labels`、`env`、`tag` 等（不写驱动时用节点 daemon.json 的默认驱动）：`syslog`、`gelf`、`fluentd` 这类由 dockerd 在节点的网络里发送，能绕过[出站限制](agent.md#出站限制)访问节点所在的内网；`deploy` 里的设备（`resources.reservations.devices`）；`label_file` 和 `env_file` 一样只能是容器目录里的相对路径
- YAML 写法上：多个文档、显式标签（包括 `!!merge` 这类标准标签）、`%TAG` 这类指令，普通的 YAML 解析和 compose 理解不一样，一律算有特权；另外按 compose 自己的解析库（`compose-go`）读出的结果再检查一遍，解析不了的也算有特权
- `network_mode`、`pid`、`ipc`、`uts`、`userns_mode`、`cgroup` 设为 `none`、`bridge`、`default`、`private`、`shareable` 和指向同一个 compose 里的服务的 `service:<服务>` 以外的值：`host` 和节点共用，`container:<名字>` 和节点上任意一个容器（包括别的项目的）共用，`network_mode` 写网络名时直接接进那个网络
- `volumes_from`
- 一个挂载的源路径包含另一个挂载的源路径或 `secrets`、`configs` 的文件（例如同时挂载 `.` 和 `./uploads`）：能写上级目录的容器可以把下级换成符号链接，Docker 下次启动容器时会跟着它挂载宿主机的目录
- 挂载绝对路径、`~`、带 `..` 的路径（包括 `docker.sock`）；`env_file`、`secrets`、`configs` 读取容器目录以外的文件
- `include`、`extends` 引用文件，`build`，指定了 driver 的 volume，`external` 的 volume 和网络，指定了 `name` 的 volume 和网络（不加 compose 项目的前缀，节点上有同名的就直接用它）
- 顶层 `networks` 里 `bridge` 以外的 `driver`、`driver_opts`、`ipam`：macvlan、ipvlan 让容器直接接入节点所在的局域网，流量不经过宿主机的 forward 链，[出站限制](agent.md#出站限制)管不到；`driver_opts` 能指定宿主机的网桥（`com.docker.network.bridge.name`），`ipam` 能指定和局域网重叠的网段
- 上面这些字段的值里有变量：变量的值操作员能改

容器目录里的路径可能是容器写的、或者从 git 仓库同步来的符号链接，所以部署时和代管重启前节点还会检查：挂载的源路径和 `env_file`、`secrets`、`configs` 的文件在容器目录以下不能经过符号链接，否则拒绝部署。

节点执行 `docker compose` 时不继承节点进程的环境变量，只传 `PATH`、`DOCKER_HOST` 这类 docker 命令自己要用的，compose 里的 `${变量}` 只能取到容器变量和项目共享变量。

规则按"读不懂就当作有特权"判断。管理员保存过的有特权的配置，操作员可以部署和回滚，也可以改依赖关系、保留路径这类无关的部分；但不能改 compose、现有目录、容器变量、服务级环境变量和文件来源（git 仓库），也不能改这个容器引用的项目共享变量：容器以特权运行时，这些决定了它以 root 运行什么（例如 `LD_PRELOAD`、启动命令里引用的变量、仓库里的脚本）。操作员也不能把容器目录放到目标节点的项目根目录以外（按目标节点自己的设置判断，节点离线时不能用自定义目录）。已有的配置不受影响。

管理员部署的特权容器，操作员不能打开终端，也不能通过 MCP 执行命令（`checkPrivilegedEntry`），不能上传或修改它的文件（卷文件、上传的压缩包、MCP 写文件）：进入这样的容器、或者往里放它会运行的文件，就等于拿到了节点的 root。按当前部署的版本判断，从未部署时按最新版本；打开着的终端每 30 秒重查，管理员降为操作员或者重新部署成特权容器后断开。

## 留痕

- **审计日志**：打开和关闭终端（时长、来源 IP）、读写删除文件（路径）都记入审计日志（见 [audit.md](audit.md)），失败和被拒绝的也记。文件内容不记。容器终端的打开和关闭也记入。
- **告警**：打开节点终端时，向告警配置里的所有渠道发一条通知，所以账号被盗用时用户能马上知道。
- **节点本地日志**：节点也记一条日志，带面板指纹和面板传来的用户名。面板的记录被篡改时还能在节点上查。
- **录制**：终端的输出默认录下来，只录输出、不录输入，用面板主密钥加密，管理员先做高权限确认才能回放（见 [audit.md](audit.md#终端与命令录制)）。录制做不到完整（命令可以编码、从文件执行），用途是事后取证。不做命令黑名单，一样能绕过，还会让人误以为安全。

## 终端

- **shell**：节点上 root 用户的登录 shell，没有时依次试 `bash`、`sh`。身份就是 nagi 的运行身份（root）。
- **环境变量**：不继承节点进程的环境变量，只设 `PATH`、`HOME`、`USER`、`LOGNAME`、`SHELL`、`TERM`、`LANG` 和 `NAGI_NODE_SHELL=1`。
- **cgroup**：节点用 systemd 运行时，shell 用 `systemd-run --scope` 放进单独的 scope，否则 `systemctl restart nagi-agent` 或 Nagi 升级会连带杀掉在 shell 里启动的 `tmux`。没有 systemd（或调用失败）时直接启动。
- **结束**：连接断开就结束 shell，第一版不做断线续连，长任务用 `tmux` 或 `nohup`。
- **时长**：没有输入输出 1 小时后断开，最长 12 小时。每 30 秒重查一次会话和角色，被踢出或者降权就断开。每个节点同时最多 8 个终端。
- **容器里的节点**：节点跑在容器里时，shell 进的是这个容器，不是主机。节点上报 `in_container`，界面上说明。
- **局限**：完全依赖 agent，agent 挂了或者节点断开时用不了，机器上的 SSH 要留着救场。

## 文件

路径一律先解析成真实路径（符号链接解开）再判断规则，界面上显示真实路径。

| 区域 | 规则 |
| --- | --- |
| `/proc`、`/sys`、`/dev`、Nagi 自己的数据目录、副本的存放位置 | 禁止访问（Nagi 的数据目录里有私钥；面板自带的节点，面板的数据目录也算；副本可以放在数据目录以外，见 [snapshot.md](snapshot.md#副本的存放位置)，整个存放位置（还没有副本的也算）、正在移入的位置和移动用的临时目录照样禁止访问，免得存放位置被删掉或换成符号链接） |
| 容器目录 | 只读：部署时会重写其中的文件，写入也绕过了容器的锁和租约。要改文件用容器页的文件管理 |
| `/etc/passwd`、`/etc/shadow`、`/etc/sudoers`、`/etc/ssh`、`/etc/fstab`、`/etc/pam.d`、`/etc/cron*`、`/etc/docker/daemon.json`、`/boot`、任何 `.ssh` 目录 | 可以改，保存前要确认（接口带 `confirmed`） |
| 其他 | 可以浏览、下载、上传、编辑 1 MB 以内的文本 |

这些规则防误操作、减轻会话被盗的影响，不是安全边界：管理员能用终端绕过。

- **写入**：同目录写临时文件再改名，沿用原文件的权限和属主；新文件跟随所在目录的属主。父目录用 `os.Root` 打开，并再次核对真实路径，防止中途被换成符号链接。
- **挂载的单个文件**：改名会失败（`EBUSY`、`EXDEV`），改为原地写入，界面提示这次不是原子写入。
- **防止覆盖别人的修改**：保存时带上打开时内容的 SHA-256，文件已经变了就拒绝，界面显示差异，用户决定覆盖还是放弃。
- **备份**：覆盖 1 MB 以内的文件前保留旧内容，放在 `<节点目录>/file-backups/`（权限 0600），每个文件最近 10 份，整个节点最多 200 份。可以在编辑页查看并恢复。超过 1 MB 的文件和删除不备份，界面上说明。
- **删除**：符号链接只删链接。不能删 `/` 和一级目录；不能删禁止或只读的路径，也不能删包含它们的目录；不能删挂载点或者包含挂载点的目录。删目录要输入目录名。
- **下载**：目录打包成 tar.gz，跳过符号链接、特殊文件和禁止访问的路径。不能下载 `/` 整个打包。单个文件支持 HTTP Range（断点续传、多线程下载工具），见 [agent.md](agent.md#存储)。经面板下载用面板签发的签名链接（`/api/download/…`，5 分钟内有效，只能从第一次使用的地址使用），下载工具截下下载也不会让人退出登录；签发时要求管理员和高权限确认，每次使用再查一次会话和角色，见 [panel.md](panel.md#会话)。
- **上传**：分块上传、断点续传，规则和卷文件一样（见 [agent.md](agent.md#存储)）：每块核对 SHA-256，写到 `<节点目录>/node-files-staging/uploads/`，提交时核对整个文件的 SHA-256，再写到目标位置（同一个文件系统时直接改名，否则复制；挂载的单个文件原地写入），覆盖 1 MB 以内的文件前保留历史版本。大小只受磁盘剩余空间限制。节点同时最多接收 4 个上传（和项目压缩包的上传合计，按正在传的块算），多的直接拒绝；界面一次选多个文件时同时传 3 个；暂存目录所在磁盘剩余不到 2 GiB 或 5% 时拒绝或停下，写到目标位置之前再查一次目标磁盘。旧版本的节点照旧整个文件一次上传，最大 8 GB。
- **改名、移动、复制**：源和目标都按上面的规则判断：禁止访问的不能碰；容器目录可以复制出来，不能移走、改名，也不能往里移、复制、解压；动到敏感路径（源或目标）要确认（接口带 `confirmed`，界面看得出来时先问，看不出来的由节点拒绝后再问）。不能移动 `/` 和一级目录，不能移走包含 Nagi 数据目录、容器目录或挂载点的目录。覆盖同名时，被替换掉的旧内容按删除的规则检查（`checkReplace`）：不能覆盖根目录下的项目，被替换的旧目录里不能有 Nagi 数据目录、容器目录或挂载点（复制、移动、解压都一样）。复制跳过符号链接、特殊文件和禁止访问的路径。移动在共同的上级目录里改名，跨文件系统时复制过去再删掉原来的。复制、打包、解压先写到目标目录里的临时名字（`.nagi-tmp-`），做完才改名。同名的处理和卷文件一样（覆盖、保留两者、跳过），覆盖 1 MB 以内的文件前保留历史版本。
- **压缩、解压**：和卷文件同一套规则（见 [agent.md](agent.md#存储)），只能压缩同一个目录里的几项，打包时跳过禁止访问的路径。解压到当前目录时，压缩包顶层的每一项按目标路径的规则判断。
- **目录大小**：和卷文件一样在列表出来以后统计，跳过禁止访问的路径，有时间和项数的限额。

## 界面

节点页多两个标签：**终端**、**文件**。只有管理员能看到，节点离线、在本地关闭或者版本过旧时显示原因。

- 终端顶部一直显示 `root · 节点名`，防止敲错机器；节点跑在容器里时说明进的是容器。手机上终端上方有 Esc、Tab、方向键和 Ctrl。
- 文案简短、正式，不解释来龙去脉。
- 文件页可以"在此打开终端"。终端打开过以后，切到别的标签不断开。
- 没开两步验证的管理员，确认框里提醒开启。

## 无法消除的风险

- **管理员账号或面板被攻破**：相当于节点 root 泄露。这个功能只能缩小窗口、留下痕迹。没开两步验证时，高权限确认只能防 cookie 被盗，防不了密码泄露。
- **面板被攻破**：攻击者本来就能借 compose 控制节点，所以节点访问不算全新的攻击面，只是更方便；不放心的节点用本地开关关闭。
