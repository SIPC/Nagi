# WireGuard mesh

mesh 是节点和面板之间的数据通道。管理操作走控制面（见 [control-plane.md](control-plane.md)），不依赖 mesh。

## 组网

- 节点之间组成全连接（full mesh）网络。
- **面板也加入 mesh**。
- **范围**：节点和它信任的每个面板、以及这些面板管理的其他在线节点互联。例如面板 P1 管节点 1、2，P2 管节点 2、3：节点 2 和 1、3、P1、P2 都互联，节点 1 和 3 之间不互联。设置顶替、备份节点或迁移时，相关节点都必须信任发起设置的那个面板，所以它们一定在同一个面板下，互相能连通。
  - 原计划节点之间互相同步 peer，把所有面板下的成员合并成一个大 mesh。目前没有功能需要跨面板互联，先不做。
- **成员列表的传播**：节点每次上报（连上时、状态变化时、每 15 秒）都带上自己的 mesh 信息（公钥、UDP 端口、本机地址、别人看到的公网地址）；面板在响应里返回成员列表：面板自己加上它所有在线节点。节点合并所有信任面板的列表后使用。
- **用途**：快照传输、租约投票、项目文件上传（面板 → 节点），以及以后的跨节点容器通信。
- **密钥**：每个 agent 和面板都在本地生成自己的 WireGuard 私钥，私钥不离开本机。

## 实现：全部使用用户态 wireguard-go

不使用内核 WireGuard，只有一套代码路径，也不需要内核模块。mesh 只传快照、上传和投票，用户态的性能完全够用。

**进程内网络栈**：mesh 用 wireguard-go 自带的用户态网络栈（gVisor netstack），不建网卡、不改路由、不需要 `/dev/net/tun`，在容器里也能跑。只有 Nagi 自己的流量走 mesh，机器上的其他程序看不到 mesh 地址。以后做跨节点容器通信时再加网卡。

**UDP 端口**：节点首次启动时随机选一个并记在 `identity/mesh-port`，可以用 `nagi agent --mesh-port` 指定；记住的端口被占用时重新随机选。面板的 UDP 用和面板端口相同的号码。端口不通时自动改走面板中转，不影响可用。

wireguard-go 的底层收发由 Nagi 自己实现（`internal/pkg/mesh`），按顺序尝试三种路径：

1. **UDP 直连**
2. **UDP 经面板中转**：直连不通时（例如双方都在 NAT 后面）
3. **套在 TLS 里经面板中转**：UDP 完全不通时，WireGuard 数据包经控制连接传输（`PanelService.MeshRelay` 双向流）

mesh 坏了只影响数据传输和投票，不影响管理。

### 路径选择

- WireGuard 眼里每个对端的"地址"就是对端本身（公钥），每个包走哪条路径由收发层决定，所以路径切换不会打断 WireGuard 会话。
- **探测包**：和 WireGuard 共用 UDP 端口，以 `NAGI` 开头（WireGuard 包的第一个字节是 1～4，不会混淆）。ping/pong 用双方 WireGuard 密钥协商出的共享密钥做 MAC，别人伪造不了；只有收到对自己 ping 的 pong（事务号对得上）才认为直连可用，重放旧包也没用。
- 直连不可用时，每 5 秒向对方所有候选地址（面板告诉的地址、从对方 ping 学到的地址）发 ping；可用时每 10 秒保活一次，25 秒没收到 pong 就认为断了。收到对方的 ping 会立刻反向 ping，加快 NAT 打洞。
- pong 里带着"我看到的你的地址"，节点由此知道自己经过 NAT 以后的公网地址，上报给面板，面板再告诉其他节点。
- 发送顺序：直连可用就直连；对方就是控制连接的另一端时走控制连接；否则经共同面板 UDP 中转（要求到这个面板的直连可用）；再不行经共同面板的控制连接中转。
- **面板中转**：面板只替自己的在线节点中转。UDP 中转按来源地址认出发送方（地址必须是 ping/pong 确认过的）；控制连接中转一律按连接所属的节点算发送方，不信任包里写的来源。WireGuard 本身还会再校验一次。
- 来源地址没确认过的 WireGuard 包直接丢弃。

### mesh 上的服务

每个成员在自己 mesh 地址的 7000 端口提供 `MeshService`（gRPC）。流量已经由 WireGuard 加密和认证，gRPC 不再加 TLS；调用方身份就是来源 mesh 地址对应的公钥。方法有：

- `Ping`：连通测试。面板上可以查看每个节点的 mesh 状态（到每个成员走哪条路径、握手时间、收发字节）并测试连通。
- `Upload`：面板把项目文件上传到节点（客户端流）。
- `ReplicaManifest` / `ReplicaPut` / `ReplicaCommit`：把项目同步给顶替节点或备份节点（见 [snapshot.md](snapshot.md#备份节点的实现)）。
- `LeaseVote`：顶替的租约投票（见 [failover.md](failover.md#实现)）。

## 地址

### mesh 地址：由公钥推导的 IPv6

- 每个成员的 mesh 地址由它的 WireGuard 公钥计算得出：固定前缀 `fd4e:6167::/32`（"Nagi" 的 ASCII），后 96 位取公钥的哈希。
- **不需要分配**：加入时不用分配地址，多个面板各自加节点、两个 mesh 合并，都不会冲突（重复概率可以忽略）。
- **不能冒用**：收到 peer 列表时，每个成员都校验"地址 = 由公钥算出的值"，对不上的直接丢弃。别人无法往 mesh 里塞一条冒用他人地址的 peer。
- IPv6 只在隧道内部使用，节点之间的外层网络照常走 IPv4。

### 容器网段：只在节点内分配

- 每个节点有一个本地的容器网段池，默认 `10.200.0.0/16`，按 /26 分配（62 个可用地址），每节点一共 1024 个：每个项目的项目内网一个，每个 compose 成员的默认网络一个，每个共享网络一个；单容器成员只在项目内网里，不另占（项目内网关闭时才另占一个）。
- 只在节点内保证不重复，不需要全局协调。分配时跳过和 Docker 现有网络重叠的网段。如果和节点所在的局域网冲突，可以按节点修改。
- 只有成员的默认网络、项目内网和共享网络使用这个网段；compose 里用户自定义的其他网络仍由 Docker 分配。
- 项目迁移或顶替到其他节点时，在新节点上重新分配。共享网络只在本节点存在，项目搬走后在新节点上要重新加入。
- 以后做跨节点容器通信时，再通过 mesh 的 IPv6 或地址转换解决，不影响现在的设计。

## mesh 连通不等于授权

在同一个 mesh 里，只说明网络能通。每个操作都要单独校验调用方身份（调用方公钥对应的是哪个面板或节点）：

- 项目文件上传：只接受该节点信任列表里的面板。
- 租约投票和快照同步：只接受该项目配置里的 A、B（或备份节点）和见证人。

这样 P2 的管理员不能借 mesh 操作只归 P1 管理的节点 1。
