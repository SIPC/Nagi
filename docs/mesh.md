# WireGuard mesh

mesh 是节点和面板之间的数据通道。管理操作走控制面（见 [control-plane.md](control-plane.md)），不依赖 mesh。

## 组网

- 节点之间组成全连接（full mesh）网络。
- **面板也加入 mesh**。
- **范围**：所有通过面板连通的节点和面板组成一个大 mesh。例如面板 P1 管节点 1、2，P2 管节点 2、3，那么 1、2、3、P1、P2 都在同一个 mesh 里，网络上互通。但设置顶替、备份节点或迁移时，相关节点都必须信任发起设置的那个面板，否则不接受这个角色。
- **peer 列表的传播**：面板把自己新加入的节点告诉自己的节点，节点之间再互相同步各自知道的 peer，最终每个成员都有整个 mesh 的完整列表。
- **用途**：快照传输、租约投票、项目文件上传（面板 → 节点），以及以后的跨节点容器通信。
- **密钥**：每个 agent 和面板都在本地生成自己的 WireGuard 私钥，私钥不离开本机。

## 实现：全部使用用户态 wireguard-go

不使用内核 WireGuard，只有一套代码路径，也不需要内核模块。mesh 只传快照、上传和投票，用户态的性能完全够用。

wireguard-go 的底层收发由 Nagi 自己实现，按顺序尝试三种路径：

1. **UDP 直连**
2. **UDP 经面板中转**：直连不通时（例如双方都在 NAT 后面）
3. **套在 TLS 里经面板中转**：UDP 完全不通时，WireGuard 数据包经控制面的 TLS 连接传输

mesh 坏了只影响数据传输和投票，不影响管理。

## 地址

### mesh 地址：由公钥推导的 IPv6

- 每个成员的 mesh 地址由它的 WireGuard 公钥计算得出：固定前缀 `fd4e:6167::/32`（"Nagi" 的 ASCII），后 96 位取公钥的哈希。
- **不需要分配**：加入时不用分配地址，多个面板各自加节点、两个 mesh 合并，都不会冲突（重复概率可以忽略）。
- **不能冒用**：收到 peer 列表时，每个成员都校验"地址 = 由公钥算出的值"，对不上的直接丢弃。别人无法往 mesh 里塞一条冒用他人地址的 peer。
- IPv6 只在隧道内部使用，节点之间的外层网络照常走 IPv4。

### 容器网段：只在节点内分配

- 每个节点有一个本地的容器网段池，默认 `10.200.0.0/16`，每个项目分一个 /26，每节点最多 1024 个项目，每个项目 62 个可用地址。
- 只在节点内保证不重复，不需要全局协调。如果和节点所在的局域网冲突，可以按节点修改。
- 只有项目的默认网络使用这个网段；compose 里用户自定义的其他网络仍由 Docker 分配。
- 项目迁移或顶替到其他节点时，在新节点上重新分配。
- 以后做跨节点容器通信时，再通过 mesh 的 IPv6 或地址转换解决，不影响现在的设计。

## mesh 连通不等于授权

在同一个 mesh 里，只说明网络能通。每个操作都要单独校验调用方身份：

- 项目文件上传：只接受该节点信任列表里的面板。
- 租约投票和快照同步：只接受该项目配置里的 A、B（或备份节点）和见证人。

这样 P2 的管理员不能借 mesh 操作只归 P1 管理的节点 1。
