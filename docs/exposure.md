# 对外访问：Caddy 统一出口

所有对外流量都从节点上的内嵌 Caddy 进入，容器自身不映射任何端口。Caddy 占用节点的 80/443，面板使用自己的随机端口，两者不冲突。

## 端口映射目录

- 每条映射是项目目录 `config/routes/<名字>.yml` 一个文件，跟着项目走（迁移、顶替、备份都会带上）。节点汇总所有项目的映射生成 Caddy 配置。
- **改了立即生效，不需要重新部署**：映射只影响 Caddy，不动容器，所以不走草稿和版本。
- 可以在界面上改，也可以直接在节点上改文件。界面上的修改写到同一个文件；直接改文件时，节点最迟 15 秒内发现并生效。
- 映射指向"成员 + 服务 + 容器端口"。有些镜像没在 compose 里写端口，需要手动添加映射才能访问。手动添加的映射和从成员 compose 导入的映射完全一样。成员被删除后，指向它的映射标为无效。
- 文件格式（每个文件开头有注释说明）：

  ```yaml
  member: umami      # 成员名
  service: web       # 服务名（单容器成员可以不写）
  port: 80           # 容器内端口
  protocol: http     # http、tcp 或 udp
  published: 8080    # 节点上对外的端口（tcp/udp 必填；http 没绑域名时必填）
  domains: [a.com]   # 绑定的域名（只用于 http）
  http_only: false   # 只开 HTTP，不申请证书
  ```

- 无效的文件（无法解析、字段不对、端口或域名重复）不生效，界面上标出原因，不影响其他映射。

## HTTP 服务

- **没绑域名**：Caddy 开一个端口（用户填写或自动分配），用 `IP:端口` 访问。
- **绑了域名**：先开 HTTP。拿到证书以后（自动申请或用户上传），同时开启 HTTPS，并自动把 HTTP 跳转到 HTTPS。
  - 实现：关闭 Caddy 自带的自动跳转。域名始终放在 443 上，让 Caddy 去申请证书；80 端口上，还没拿到证书的域名直接转发，已经拿到证书的域名跳转到 HTTPS。节点每 15 秒检查一次证书状态。
  - 这样证书申请失败时（例如域名还没解析到节点），网站仍然能用 HTTP 访问，不会被跳转到打不开的 HTTPS。
- **只开 HTTP**：可以为域名关闭 HTTPS（例如前面还有 CDN 终结 HTTPS），这时不申请证书、不跳转。
- 80 端口上没匹配到任何域名的请求返回 404。

## TCP / UDP 服务

数据库、游戏服、MQTT 等，同样经 Caddy 转发，使用内嵌的 layer4 模块。

**已知限制**：经 Caddy 转发后，容器看到的来源 IP 是 Caddy 的地址，不是真实客户端。HTTP 服务不受影响（Caddy 会在请求头里带上真实 IP）。需要按客户端 IP 做限制的 TCP/UDP 服务，需要应用支持 PROXY protocol；以后可以考虑提供"该端口直接映射"的例外选项。

## compose 里写的 `ports`

每次部署时，把 compose 里**新出现的** ports 导入成映射文件，之后可以在界面上修改协议或绑定域名。协议：compose 里写了 `app_protocol: http` 就按 http；否则容器端口是常见的网站端口（80、8000、8080、8081、8888、3000、3001、4000、5000、5173、8096）时按 http 开放（能统计请求、能绑域名），部署日志里注明是猜的；其余按 tcp/udp 原样开放。9000（php-fpm 等）和 443（容器内一般是 HTTPS）不算网站端口。运行时由 override 去掉容器的端口映射（见 [agent.md](agent.md#override-叠加配置)）。

- 导入过哪些端口（成员 + 服务 + 容器端口 + 协议）记在项目数据库里。已经导入过的端口不会再导入：用户改过的映射不会被覆盖，删掉的映射也不会被加回来。
- 和其他项目冲突、或者没写对外端口的 compose 端口不导入，只在部署日志里提示，可以之后手动添加。

`network_mode: host` 的服务例外：它直接使用宿主机网络，不经过 Caddy，端口直接对外，项目页面上醒目提示（见 [agent.md](agent.md#部署方式)）。

## 端口冲突

保存映射时检查（从 compose 导入时也检查，冲突的不导入）：

- 80 和 443 留给域名访问，不能作为其他开放方式的端口。
- 端口和域名不能和本节点所有项目的其他映射重复。
- 本项目还没在用的端口，尝试监听一下，确认没有被节点上的其他程序（包括面板端口、sshd 等）占用。

冲突时拒绝保存并提示。

## Caddy 如何找到容器

Caddy 运行在 agent 进程里，直接通过容器的 IP（compose 成员优先用它默认网络里的地址，单容器成员用项目内网或它自己网络里的地址）转发流量，不经过端口映射。容器重建后 IP 会变，agent 监听 Docker 事件，容器变化时立即更新 Caddy 的转发目标。

## 为什么统一出口

- 出口只有一套，不会出现 Docker 端口映射绕过 ufw 防火墙的问题。
- 以后做顶替后的流量切换，也只需要改 Caddy。
