# 对外访问：Caddy 统一出口

所有对外流量都从节点上的内嵌 Caddy 进入，容器自身不映射任何端口。是否开放、怎么开放，都在界面上按服务设置。Caddy 占用节点的 80/443，面板使用自己的随机端口，两者不冲突。

## HTTP 服务

- **没绑域名**：Caddy 开一个端口（用户填写或自动分配），用 `IP:端口` 访问。
- **绑了域名**：先开 HTTP。拿到证书以后（自动申请或用户上传），同时开启 HTTPS，并自动把 HTTP 跳转到 HTTPS。

## TCP / UDP 服务

数据库、游戏服、MQTT 等，同样经 Caddy 转发，使用内嵌的 layer4 模块。

**已知限制**：经 Caddy 转发后，容器看到的来源 IP 是 Caddy 的地址，不是真实客户端。HTTP 服务不受影响（Caddy 会在请求头里带上真实 IP）。需要按客户端 IP 做限制的 TCP/UDP 服务，需要应用支持 PROXY protocol；以后可以考虑提供"该端口直接映射"的例外选项。

## compose 里写的 `ports`

创建项目时自动识别，转成界面上的"经 Caddy 开放该端口"设置。运行时由 override 去掉容器的端口映射（见 [agent.md](agent.md#override-叠加配置)）。

`network_mode: host` 的服务例外：它直接使用宿主机网络，不经过 Caddy，端口直接对外，项目页面上醒目提示（见 [agent.md](agent.md#部署方式)）。

## 端口冲突

Caddy 开放端口前，先检查这个端口在节点上是否已被占用，包括面板端口、其他项目已开放的端口、`host` 网络的服务，以及节点上其他程序（如 sshd）。冲突时拒绝保存并提示。

## Caddy 如何找到容器

Caddy 运行在 agent 进程里，直接通过容器在项目网络里的 IP 转发流量，不经过端口映射。容器重建后 IP 会变，agent 监听 Docker 事件，容器变化时立即更新 Caddy 的转发目标。

## 为什么统一出口

- 出口只有一套，不会出现 Docker 端口映射绕过 ufw 防火墙的问题。
- 以后做顶替后的流量切换，也只需要改 Caddy。
