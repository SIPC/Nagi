# 审计日志

审计日志记下谁在什么时候、从哪里、通过什么、对什么、做了什么、结果如何。安全事件先写成审计记录，再由检测规则判断要不要告警（见 [security.md](security.md)）。

## 记录范围

| 类别 | 内容 |
| --- | --- |
| `operation` | 会改变状态的接口调用，包括失败和被拒绝的 |
| `read` | 敏感查询：查看环境变量和共享变量的值（`GetProject`、`ListProjects`）、备份密钥、告警配置，读取或下载卷文件和节点文件，导出审计记录 |
| `mcp` | MCP 的工具调用；被拒绝的调用记为 `denied` |
| `session` | 节点终端、容器终端、`exec`、`node_exec` |
| `login` | 登录成功、密码错误、验证码错误、退出、会话过期 |
| `alert` | 节点和面板发出的告警 |
| `security` | 安全事件 |

普通查询（列表、状态、监控、日志流）不记，量太大且不涉及敏感内容。敏感查询登记在 `store.SensitiveReads`：`api` 包的测试列出所有回复里带密钥、变量值或文件内容的查询，没登记的测试失败。界面定时刷新的 `GetProject`、`ListProjects` 每个会话、每个项目每小时只记一条。

不用登录就能调的接口里，初始化以后的 `Setup` 失败、被限速拒绝的登录不记录，免得被拿来刷掉记录。用户名或密码错误按 IP 汇总：每个 IP 每小时第一次失败单独记一条（`login_failed`），之后的只计数，下一个整点写一条汇总（`login_failed_summary`，次数和被尝试最多的 5 个用户名）。密码正确、验证码错误的（`totp_failed`）每次都记。来源检查拒绝的跨站请求（`cross_origin_request`）也不用登录就能触发，同样汇总：每个 IP 每小时第一次单独记一条，每小时最多单独记 100 条（IPv6 的攻击者可以换很多地址），其余只计数，过了整点写一条 `cross_origin_summary`（次数、IP 数和次数最多的 10 个 IP）；参数里的路径和来源截到 256 字节。

## 字段

| 字段 | 内容 |
| --- | --- |
| `id`、`time` | 自增编号；毫秒时间 |
| `category`、`action` | 类别；接口方法名或事件名，例如 `Deploy`、`mcp:deploy`、`totp_failed` |
| `actor_type`、`actor_id`、`actor_name` | 操作者：`user`、`token`、`node`、`panel`、`system`。用户名改了以后仍能按 ID 查 |
| `via` | `web`、`mcp`、`cli`、`system`、`node` |
| `token_id`、`client` | 访问令牌；MCP 客户端（`User-Agent`） |
| `session` | 登录会话 ID 的哈希前 12 位，把一次登录里的操作串起来 |
| `ip`、`user_agent` | 来源。经本机 Caddy 转发时按 [panel.md](panel.md#访问) 核对后的地址 |
| `project_id`、`target_type`、`target_id`、`target_name` | 对象：`container`、`node`、`member`、`file`、`tool` |
| `params` | 请求参数（JSON，按下一节脱敏），不超过 4 KB |
| `result`、`error` | `ok`、`failed`、`denied`（没登录、没权限）；错误说明。说明里提到节点时存的是引用标记：`\x02node:<节点 ID>\x1f<名称>\x03`（`i18n.Marked`），界面显示时换成名称，查看的成员看不到这台节点时换成「其他节点」；导出和外送的是存的原文（哈希按原文算） |
| `duration_ms` | 耗时 |
| `parent_id` | 上级记录：MCP 工具调用触发的接口调用指向那次工具调用 |
| `recording_id` | 会话的录制 |
| `prev_hash`、`hash` | 哈希链：`hash = SHA-256(prev_hash ‖ 记录的规范化 JSON)`，规范化 JSON 包含 `id` |

记录由 `internal/server/audit` 写入。接口调用由 `api` 包的拦截器记（`activity.go`），不走 Connect 的入口（终端、上传下载、`exec`、`node_exec`）和登录由处理函数自己记。

## 参数脱敏

- 请求消息里的敏感字段用 protobuf 的字段选项 `debug_redact = true` 标记，记录时替换为 `"[已隐藏]"`。`audit` 包的测试遍历浏览器接口的所有请求消息（包括嵌套的），字段名包含 `password`、`token`、`secret`、`key`、`code`、`env`、`value`、`content`、`data` 的字符串字段，既没有标记、也没有登记为内容字段（`audit.ContentFields`）或安全字段（`audit.SafeFields`）的，测试失败。另一个测试把所有请求里这类字段填上同一个值，记录的参数里出现这个值就失败。
- 环境变量（`EnvVar`）只记名字，不记值。
- compose、节点文件内容这类内容字段只记 SHA-256 和长度，内容本来就在版本记录里。所有 `bytes` 字段同样只记 SHA-256 和长度。
- 超过 4 KB 的参数截断，包成 `{"truncated": true, "head": …}`。

## MCP 调用

- 每次 `tools/call` 写一条 `mcp` 记录（`mcp/tools.go` 的 `def`）：动作是 `mcp:<工具名>`，参数（按下面的规则脱敏）、结果、返回的字节数、耗时、令牌、客户端（`User-Agent`）。工具把失败写在结果里的（部署这类返回 `success: false`）也记为失败。
- 参数里有项目（名称、网络名或 ID）时，记录挂到这个项目上，只认调用者访问范围内的项目：范围外的项目名称是调用者自己写的文字，不会让记录出现在那个项目的活动记录里；范围内有几个项目同名时不挂。
- 工具在进程内调用的接口照常由拦截器记录。工具执行期间 ctx 里带一个收集器（`audit.WithCollector`），这些记录先收集起来，工具结束后先写工具调用的记录，再写它们，`parent_id` 指向工具调用。界面上把它们收在工具调用下面，可以展开。面板在工具执行中途崩溃时，这次调用和它触发的记录都会丢失。
- 工具的参数是 JSON，按字段名脱敏（`audit.JSONParams`）：`password`、`token`、`confirm`、`code` 这类字段替换为 `"[已隐藏]"`；`env`、`set`、`variables`、`service_env` 只记变量名；`compose`、`content`、`files` 只记 SHA-256 和长度。`node_exec` 的预览和确认是两次调用，都记录，确认码不记。
- 记录以后要给看不到某些节点、没有某些权限的成员看，所以写的时候就处理好，显示时不用在文字里猜（`mcp/denied.go` 的 `record`）：
  - 节点参数（键名含 `node`，或者是 `peer`）按调用者看得到的节点列表换成节点 ID，重名的写成各台 ID 的数组（成员看不到其中一台时，去掉的是数组里的那一项，不会剩下半截的值），对不上的原样留着（那是调用者自己写的文字），拿不到节点列表时清空；对象是节点时记 ID 和名称。显示时成员看不到的节点 ID 由面板去掉。新加的工具参数用来指定节点时键名要含 `node`（`mcp` 的 `TestNodeArgKeys` 检查）。
  - 失败详情带节点的引用标记（见[字段](#字段)）。工具经进程内的 Connect 客户端拿到的报错只剩文字，接口这边把每次失败「返回的文字 → 带标记的文字」记在 ctx 上（`api.FailureNotes`），工具失败后按返回的整段文字找回带标记的那一份；工具自己的报错提到节点时用 `nodeErrorf`；按名称找到几台重名节点时，报错里的名称和各台的 ID 也是引用，成员看不到的那台显示「其他节点」。只按整段报错对，调用者写进报错里的词不会变成节点。
  - 参数里的 `perms` 是用这个工具要的权限（工具用到的接口的权限，加上执行命令、文件这类不走 Connect 的）。查看记录的成员要有「查看配置」和其中「查看、查看配置、控制、部署」以外的各项，才看得到参数和失败详情；只给管理员的接口记成 `admin`。
  - 没有 `perms` 的是以前的记录：参数和失败详情是工具的原文，可能写着节点名称，只给管理员；它下面的接口调用记录照常按各自的规则显示。
- 被拒绝的工具调用（令牌没有权限、备用面板上的修改、调用过于频繁）记为 `denied`；令牌看不到的工具被客户端按名字调用时，同样记一条。
- Nagi 看不到 agent 和用户的对话，只能看到工具调用和参数。

## 终端与命令录制

范围是节点终端、容器终端、`exec` 和 `node_exec`。终端数据本来就经面板中转（`api/terminal.go` 的 `bridgeTerminal`），面板边转发边写，节点不用改。`exec`、`node_exec` 也边收边录完整的输出流（返回给 agent 的只有开头和结尾），录制开头先写上目录和命令（灰色的 `$` 提示符），结尾写退出码或「超时」。

- **输出、输入和窗口大小**：输出和窗口大小照录。浏览器发来的按键记成 asciicast 的 `i` 事件（`audit/recording_input.go`）。面板看不到终端的回显状态（容器终端的 pty 在容器里），所以按回显判断，而且判断得很严，宁可把有回显的当成没有回显，也不把密码录下来：回车之前，敲的字符要由紧接着的输出原样开头（去掉颜色等控制序列）才算回显，一个个敲的字符还要求这段输出正好就是它们的回显，开头对上、后面还有别的（先敲了密码、提示符才出来，或者恰好到达的后台日志）也算没有回显；粘贴的一整段可以只是输出的开头。fish 这类会在回显后面接着显示补全建议的 shell，敲的字符会记成未回显；按回车时，还在等回显的字符合成一整串，要由回车后的输出原样开头、并且紧跟着换行才算回显（粘贴一条命令再回车就是这样）；中间有别的输出、开头对不上、超时（回车前 2 秒、回车后 0.5 秒）都算没有回显。输密码时回显关着，回车后的输出是程序打印的换行、「Sorry, try again」或新的提示符，开头对不上，整串记成一串 `•`，回放时显示「未回显的 N 个字符」，不留内容。回车、退格、方向键、Ctrl 组合这类控制键记名称。回放下方按行列出输入，点一行跳到那个时间。
- **每次连接一段**：断开后重新连接是新的一段录制，审计里各有一对打开、关闭的记录。打开终端的记录也带着录制 ID，终端还开着时就能回放已经录下的部分（每 5 秒写一块）。
- **格式**：asciicast v2（asciinema 的格式）。每 256 KB 或每 5 秒切一块，zstd 压缩后用面板主密钥加密（AES-256-GCM，附加数据是录制 ID 和序号，块不能挪用），存为 `<面板数据目录>/audit/recordings/<年月>/<录制 ID>/<序号>`。面板中途崩溃最多丢最后 5 秒。
- **上限**：单个会话保留开头 8 MB 和最后 56 MB，中间丢掉并标记「已截断」，回放时在断开处插一条提示。只保留开头的话，攻击者先刷屏超过上限，后面的操作就不会被录下。
- **完整性**：会话结束的记录（`CloseNodeShell`、`CloseTerminal`、`ExecCommand`、`NodeExec`）带上 `recording_id` 和各块的 SHA-256，进入哈希链。被改动的块解不开。
- **回放**：只有管理员能看，要先做高权限确认（`SettingsService.GetRecording` 登记在 `elevationRequired`，流式接口也检查）。回放本身记一条 `read` 记录。界面用 asciinema-player，支持倍速和拖动；上方的筛选框在输出里找文字，点结果跳到那个时间。播放器用 WebAssembly 解析终端输出，所以面板的 CSP 在 `script-src` 里加了 `'wasm-unsafe-eval'`（只允许编译 WebAssembly，不允许 `eval`）。
- **保留**：90 天，总量超过 10 GB 时从最旧的删起，每小时清理一次。
- **开关**：「设置 → 安全 → 终端录制」，默认开启（设置项 `audit_recording`）。关闭要高权限确认，发一条告警，记入审计；开启也发告警。

## 存储与保留

- 审计记录存在本机日志目录下的 `logs/audit/audit.db`（SQLite，WAL，只追加；v0.37.1 起），和面板业务库 `panel/panel.db`、主备快照分开。备用面板每次同步都传整份主库（见 [standby.md](standby.md#同步)），不带审计库。
- **格式**：每条记录保存规范化后的全部字段（参数按 [参数脱敏](#参数脱敏) 在写入前脱敏，这是记录本身的内容，不是另一份副本）和 `prev_hash`、`hash`，见 [防篡改](#防篡改)。审计库能单独完成整条链的校验和导出，不依赖统一日志库里的脱敏副本（统一日志页上看到的审计事件只是便于查询的副本，有大小上限）。
- **加密**：审计库本身不另外加密，和面板业务库一样依赖数据目录的文件权限（0700）；终端录制的正文用面板主密钥加密，存在 `logs/panel-recordings.db`。
- **容量**：审计库计入本机日志的共享额度（`logs/config.json` 的 `capacity_gib`，5–10 GiB），属于最高优先级（和统一日志里的审计、安全、告警副本同一级），额度不够时先清理运行日志、访问日志、容器日志、监控和任务记录，这些都清完仍超额才删审计：先删最旧的普通记录，`security`、`session`、`login`、`mcp` 类最后删。旧版本迁移还没完成时不删。v0.37 以前建的审计库要先整份重写一次（VACUUM，才能把删除的空间还回去），这一步不在启动时做（大库要几十秒，会挡住入口），而是容量第一次清到审计时才做，期间审计写入等待、不丢。每次删除都留下墓碑并在链上写 `audit_pruned`，所以按容量删除和按保留时间删除一样可以校验、会外送，不会悄悄缺一段。
- **从旧版本升级**：v0.37.0 及以前的审计库在面板目录（`panel/audit.db`、`audit-standby.db`、`audit-term*.db`、`audit-standby-*.imported.db`）。面板启动时逐个搬到 `logs/audit/`，原来的 `id`、`prev_hash`、`hash`、墓碑、清理记录和外送游标原样保留，不重算哈希，新记录接着旧链最后一个哈希写。
  - **同一个文件系统**（通常如此，`logs/` 在数据目录下）：先把预写日志合并进主文件，再把文件整个改名过去（`legacy.cleanup.audit.moved`）。改名是原子的、文件的字节不变，也没有删除任何东西，所以入口不等校验：面板起来以后在后台校验整条链，通过记 `legacy.cleanup.audit.verified`；不通过（文件在升级前就被改过）时文件原样保留，日志页「旧数据清理」和「设置 → 安全 → 哈希链」都报出第一条对不上的记录，和不搬时一样。演练里 186 MB、40 万条的库改名不到 1 秒，后台校验约 10 秒。
  - **跨文件系统**：用 `VACUUM INTO` 整份复制，副本自己通过整条链的校验、并且和原库逐行一致（摘要相同）以后才换成正式文件，然后记日志（`legacy.cleanup.audit.copied`、`deleting`、`done`）删除原库。原库自己校验不通过（被篡改、损坏）时不搬也不删，本次继续在原处使用，日志页提示失败，下次启动重试。
  - 任何一步被强杀都能重来：改名前被杀，文件还在原处，下次再搬；复制时正式文件不在就丢掉没写完的临时副本重新复制，正式文件已在时以它为准，只要原库和复制时核对过的摘要一致就删除原库。
  - 搬完以后原处又出现审计库（例如退回过旧版本、旧版本又写了一条新链），它和搬走的链分开，同样核验后作为 `audit-rollback-<摘要>.db` 归档搬过来，并按旧角色归档导入统一日志。
  - `nagi audit verify` 先找 `logs/audit/audit.db`，没有时找 `panel/audit.db`。
- 保留：普通记录 90 天；`security`、`session`、`login`、`mcp` 类 365 天，都可以在「设置 → 安全 → 审计记录保留」里改（7–3650 天，安全记录不短于普通记录）。缩短任何一项都要先做高权限确认，记一条 `security` 事件（`audit_retention_shortened`，参数里是改前和改后的天数）并告警：只偷到会话的人不能借此删掉更早的安全和登录记录。数据库超过 2 GB 时先删最旧的普通记录。每小时清理一次。删掉的记录留下 ID 和哈希（`tombstones` 表），哈希链还能接上；比所有剩下的记录都旧的墓碑一起删掉。
- 更早的升级：面板启动时把主库 `activity` 表的记录复制进 `audit.db`，缺少的字段留空，中断了下次从断点继续。原来的接口 `ListActivity`、`ListProjectEvents`、`ListContainerEvents` 改为查询审计库，返回格式不变。`activity` 表不再写入，下一个版本删除。
- 界面和接口都没有删除审计记录的功能。

## 安全告警

安全事件先写成审计记录，再按规则判断要不要告警。告警走现有的渠道和面板代发（见 [monitoring.md](monitoring.md#告警)），备用面板不发。

**登录异常**：由面板判断，在「设置 → 告警 → 安全告警」里有开关，默认开启（设置项 `alert_totp_failures`、`alert_login_ratelimit`、`alert_admin_network`，`"0"` 表示关闭）。

| 事件 | 告警内容 |
| --- | --- |
| 密码正确但验证码连续错误 5 次 | 账号 `<用户名>` 的密码可能已泄露，来源 IP。验证成功以前不重复 |
| 密码正确但登录的手机确认连续 5 次没有通过（过期没人确认、数字输错作废，见 [android.md](android.md#手机确认)） | 同上，和验证码连续错误用同一个开关。登录成功以前不重复 |
| 按 IP 的登录限速开始等待 | 每小时汇总一条：涉及的 IP 数、失败次数、被尝试的用户名（前 5 个） |
| 管理员从新的网段登录 | 用户名、IP、浏览器。网段按 IPv4 /24、IPv6 /48 计，记最近 90 天登录过的网段（`login_networks` 表）；成员第一次登录（还没有任何记录）不告警 |

**账号、凭据和集群变更**：一次性通知，不能关（`api/security_alerts.go`，接口调用成功并记入审计以后判断）。这些正是攻击者拿到管理员后最先做的事：关掉告警、生成令牌留后门、关掉两步验证、加节点、部署特权容器。

## 备用面板

备用面板每次同步都传整份主库（见 [standby.md](standby.md#同步)），不带审计库。审计记录另走一条连接（ALPN `nagi-standby-audit/1`，同样的 mTLS 客户端证书）：备用面板报上自己已有的最大 ID，主面板按 ID 把之后的记录（原来的 `id`、`prev_hash`、`hash`）、这一段里的墓碑、引用到的录制块（加密的原样内容）一批批发过来，追上以后每秒看一次，空闲时发心跳。断线后从备用面板已有的最大 ID 续传。录制块从主面板的录制库读出（旧录制文件核验后已删除），备用面板原样写进自己的录制库，先写块再提交引用它们的记录，重发的块和已有内容相同时什么也不做。

- 备用面板的 `audit.db` 只存同步来的记录，界面上看的是它；备用面板自己的记录（登录、查看）写进 `audit-standby.db`。活动记录的迁移只在主面板上做。
- 提升以后接着原来的哈希链写（自增序号跟上同步来的最大 ID），`audit-standby.db` 里的记录作为新记录并进来，原文件改名为 `audit-standby-<时间>.imported.db` 保留。
- 原来的主面板降为备用面板时，`audit.db` 里有新主面板没有的记录，改名归档为 `audit-term<任期>-<时间>.db` 保留，不并入新主面板，再从新主面板重新同步。
- 只有主面板外送。主面板把各外送目标的游标随同步连接发给备用面板（v0.37.1 起，追上以后游标变了就发），备用面板只接受不超过自己已有记录的游标、只往前走；提升以后从这些位置接着外送，主面板提升前还没送到的记录、提升本身和并入的备用面板记录都会送出，送到的不重发。v0.37.0 的备用面板收不到游标，提升后从当时最新的记录开始，主面板最后没送到的几条只能用导出补。

## 防篡改

- **哈希链**：每条记录的 `hash = SHA-256(prev_hash ‖ 记录的规范化 JSON)`，规范化 JSON 包含 `id`。在面板机器上执行 `nagi audit verify` 校验整条链（只读，面板运行中也能用），校验失败时打印第一条对不上的记录并返回非零；界面的「设置 → 安全 → 哈希链」可以立即校验，显示最近一次校验的结果。
- **锚点**：每个外送目标启动时、之后每小时和每 1000 条，把链上最新的 `id`、`hash` 和墓碑个数发到外送目标（`{"type":"anchor", …, "tombstones": N}`），界面显示最近一次锚点。
- **清理记录**：按保留时间删掉记录时留下墓碑（`id` 和 `hash`），链还能接上。墓碑本身没有认证，能写 `audit.db` 的人可以删掉中间一条、补一个墓碑。所以每次清理在同一个事务里往链上写一条 `audit_pruned`（类别 `security`），参数 `ids` 列出这次删掉的 ID（连续的写成区间，例如 `1-5,7`），太长时切成几条（每条不超过 4 KB），随外送发出。清理记录自己被删掉、它列出的墓碑还在时（普通记录保留得比 `security` 还久），由新的清理记录接着列出。校验时要求每个墓碑都被某条清理记录列出。升级前留下的墓碑由主面板第一次启动新版本时写一条 `legacy: true` 的清理记录覆盖，只写一次；出现多条 legacy 记录也算校验失败。
- **能发现的**：中间的记录被修改；中间的记录被删除（没有墓碑，或者墓碑没有清理记录列出）。**发现不了的**：面板被攻破后从某处起重写后面所有的记录，或者在链的末尾追加伪造的记录（包括一条列出被删记录的清理记录）。能写审计库的人就能算出新的哈希，这种情况只能靠外送目标上的副本对比：外送目标上会出现一条时间对不上的 `audit_pruned`，或者锚点之间墓碑个数的增加和清理记录列出的个数对不上。

## 外送

外送才是面板被攻破、机器被格式化以后真正的保障。目标在「设置 → 安全 → 日志外送」中配置，可以配多个：

| 目标 | 方式 | 适合 |
| --- | --- | --- |
| syslog | RFC 5424，TCP + TLS（RFC 5425 的长度前缀分帧），facility 13，可以填自签服务器的 CA | 已有日志服务器 |
| HTTP | 每 2 秒批量 POST 一次 JSON Lines（`application/x-ndjson`），可以带固定请求头 | Vector、Loki、Elasticsearch、自建接收端 |
| S3 兼容存储 | 每批一个对象（`<前缀>/panel/<年>/<月>/<日>/<时>-<第一条 ID>.jsonl`，录制在 `<前缀>/panel/recordings/`），路径风格、SigV4 签名；可选同时上传录制（加密的原样内容） | 长期保存，建议开启对象锁（Object Lock） |

- 每行和导出的格式一样：全部字段，带 `prev_hash` 和 `hash`。新添加的目标从当时最新的记录开始发，以前的记录用导出拿。
- 每个目标一个游标（审计库的 `meta` 表）。发送失败时游标不动，恢复后从游标处补发，不另存一份数据。连续失败超过 10 分钟告警，恢复时再发一条。
- 外送配置用主密钥加密后存在设置里（`audit_sinks`），返回界面时 Secret Key、Access Key 和请求头的值留空，保存时留空表示不变。这些值和 HTTP 接收地址（查询串里常带令牌）都不写进审计参数。
- 修改外送目标和「发送测试消息」都要先做高权限确认：只偷到会话的人不能加一个自己的目标、也不能借测试把保存的凭据发到别处。把已有目标的类型或地址（接收地址、syslog 地址、S3 地址、存储桶、区域）改掉时，不沿用已保存的 Secret Key、Access Key 和请求头的值，要重新填写。
- 修改外送配置是 `security` 事件（`audit_sinks_changed`）：先记下这条，等原来的目标都发到这一条（最多 15 秒，正在失败的目标不等），再换成新的配置，并发一条告警。攻击者拿到管理员后改外送，改之前的记录已经送出去了。
- 「发送测试消息」发一条 `{"type":"test"}`，S3 写一个 `<前缀>/panel/nagi-test.json`。
- 外送不跟随重定向：接收端返回 3xx 算发送失败，审计正文和自定义请求头不会被转到别的地址。S3 出错时失败原因只带状态码和 S3 的错误码（如 `AccessDenied`），不带响应体，地址填成内网服务时读不到它的内容。
- **存储桶的设置**：开启版本控制或对象锁（Object Lock），给 Nagi 的凭据只授予 `PutObject`，不给读取、删除和覆盖已有版本的权限，这样被攻破的面板最多写入新对象，改不掉已经外送的记录。凭据只在面板上，节点的记录由面板代发（见下面的「节点本地审计」）。HTTP 接收端同理，只接受写入，按 `source`、`node_id` 区分来源。
- 传输（syslog、HTTP、S3 的 SigV4）在 `pkg/auditsink`，面板和节点共用。

## 节点本地审计

面板被攻破时，面板上的记录不可信，所以节点自己也记一份（`agent/auditlog`）。

- **存储**（v0.37.1 起）：本机日志目录下的 `logs/audit/node-audit.db`（SQLite，WAL，`synchronous=FULL`），和节点业务库 `node.db`、统一日志库 `logs.db` 分开。每条记录是一行 JSON：`seq`（递增的序号）、`time`、`panel`（发起的面板指纹，控制连接确认过的）、`actor`（面板说的成员和令牌）、`ip`（成员的来源地址，面板说的）、`action`、`target`、`detail`、`result`（`ok`、`failed`、`denied`）、`error`，单个字段最长 2000 字节。库里原样保存这一行（`ReadAuditLog` 返回、面板外送的就是这些字节，没有脱敏）和 `prev_hash`、`hash`：`hash = SHA-256(prev_hash ‖ 这一行)`。统一日志页上的节点审计是脱敏后的查询副本。
  - **加密**：不另外加密，依赖数据目录的文件权限（0700）。
  - **容量**：计入本机日志的共享额度，属于最高优先级，其他日志清完仍超额才删；另外节点审计自己最多 100 MB。每次删除最旧的一批（最新一条不删），留下墓碑（序号和哈希）并在链上写一条 `audit_pruned`（`detail` 是 `ids=` 加上所有还在的墓碑区间），所以按容量删除可以校验、会被面板外送。旧文件还没导入完、或统一日志副本还没导入完时不删。
  - **校验**：`nagi audit verify --data-dir <数据目录>` 只读校验节点审计库（和面板审计库一起，存在哪个校验哪个）。每条的哈希要对得上内容、行里的 `seq` 要等于库里的序号、相邻的记录（中间隔着墓碑时按墓碑的哈希）要接得上、每个墓碑都要被某条 `audit_pruned` 或导入记录列出；只剩墓碑也算失败。
- **从旧版本升级**：v0.37.0 及以前是 `<数据目录>/audit/audit.jsonl`（满 10 MB 改名为 `audit.<最后的序号>.jsonl`）。
  - 节点启动后在后台（不挡节点连面板，演练中 28 万行约 1 分钟）按文件和序号顺序把每一行原样（字节不变、序号不变）导入新库并依次算哈希链，每 512 行一个事务；导入期间新记录照旧追加到旧文件、序号接着旧文件，最后在锁内收下这几行再切换到新库；旧文件之间缺的序号（旧版本按个数删掉的文件）留下墓碑，最早一个文件以前缺的不用接。最后在链上写一条 `audit_legacy_import`（`detail` 里有导入到的序号、行数、缺口区间、文件名），缺口的墓碑靠它通过校验。序号和行都不变，面板的外送游标照用，不重发也不漏发。
  - 导入没完成（例如旧文件有无法识别的行或序号乱序）时，新记录照旧追加到旧文件、序号接着旧文件，`ReadAuditLog` 暂时不返回记录（面板游标不动），日志页「旧数据清理」提示失败，下次启动接着导入。中途被强杀：已提交的批次在库里，下次从库里最大的序号接着导入。
  - 导入完成以后不再写旧文件。升级确认（第一次连上面板，此后不会再被自动换回旧版本）以后再核对一遍：新库整链校验通过、统一日志副本导入完、旧文件的每一行都和库里同一序号的内容逐字节相同（或已被本库的容量清理删掉、有墓碑），才删除旧文件和 `relay-start.json`、`cursors.json`。删除前后各记一条日志（`legacy.cleanup.node.audit.deleting`、`done`），完成后记检查点；核对不通过就保留旧文件，日志页提示，下次启动重试。删除做到一半被杀，下次只删剩下的。
  - 能发现的篡改：旧文件本身没有哈希，导入只是从这一刻起把它们串进链里；导入以前就被改过的行会被原样接受（演练中改过的一行导入后整链校验照样通过），只能靠面板已经外送出去的副本对比发现。导入以后再改库里的记录、或者改了旧文件再删除之前的核对，都会被发现（核对不通过就保留旧文件）。\n  - 删除以后旧文件又出现（手动退回过旧版本、旧版本又写了一些）：这些行的序号和新库冲突，作为新记录追加（`action` 是 `legacy_line`，`target` 是文件名，`detail` 是原样的一行），同样核对后删除。
- **记录范围**：
  - 节点终端的打开和关闭（`node_shell_open`、`node_shell_close`，带时长），`node_exec` 的命令、工作目录和退出码。成员和来源地址由面板随请求带来（`NodeShellStart.actor`、`ip`，`NodeExecRequest.actor`、`ip`）。
  - 面板下发的修改类指令：控制连接上 AgentService 的方法，除了名字以 Get、List、Query、Read、Check、Stream 开头的查询、心跳类的（`MeshPing`、`MeshSpeedTest`）和轮询类的（升级期间面板每秒问一次的 `UpgradeProgress`）。部署、删除、升级、信任列表、告警配置、节点文件、代理计划、外送配置都在里面；对象从请求里的项目、容器、路径等字段取（`agent/audit.go` 的拦截器）。被拒绝的（不是主面板、节点访问关着）也记，`result` 是 `denied`。
  - 被本节点拒绝的越权请求（见 [mesh.md](mesh.md#越权识别)），`actor` 是 `mesh:<调用方公钥>`。和上报一样每 10 分钟最多 200 条。
  - 浏览器直接从节点下载文件（`direct_download`，见 [agent.md](agent.md#直连下载)）：`panel` 是签发链接的面板，`actor` 是链接里写的签发成员，`ip` 是下载的来源地址，`target` 是 `项目/容器/卷:路径` 或节点上的路径，`detail` 写种类、链接编号（`link=`，和面板活动记录参数里的 `direct_link` 一样）、`Range`、快照。整个文件的下载每次都记，同一个链接同一个地址的分段请求 10 分钟内只记第一次；过期链接和节点访问关着时被拒绝的也记（`denied`），签名对不上的和探测不记。每 10 分钟最多 500 条，超出的只计数，写进下一条的 `dropped=`。[加密 HTTP 下载](agent.md#加密-http-下载)记在同一个 `direct_download` 里，`detail` 多一个 `transport=http`；目录打包的链接第二次使用时记 `denied`（「下载链接已使用」）。内容密钥不记。
- **外送**：由面板代发，节点不持有外送凭据。面板对「设置 → 安全 → 日志外送」的每个目标，按游标用 `AgentService.ReadAuditLog` 读走每个节点的新记录（每 5 秒一次，S3 同面板每小时一次；每次最多 500 条、2 MB），发到同一个目标。
  - 只读已经批准、认本面板是主面板的在线节点；待批准的节点不读。被隔离的节点照常读，它的记录正是要留证的。只有主面板外送，备用面板不读。
  - 每行加上 `source: node`、`node_id`、`node`，由面板按登记的节点填写，覆盖节点自己写的，被攻破的节点冒充不了面板和别的节点。
  - S3 每批一个对象，键是 `<前缀>/node/<节点 ID>/<年>/<月>/<日>/<时>-<本地序号>.jsonl`，和面板（`panel/`）、其他节点分开。不发锚点、不上传录制（录制在面板上）。
  - 游标按目标和节点存在面板审计库的 `meta` 表（`sink:<目标>:node:<节点>:cursor`）。节点连不上（离线、面板不可用）时记录留在节点的审计库里，恢复后从游标处补发；节点连不上不算目标失败，发往目标失败才算。新目标、新节点从当时最新的记录开始。节点审计库最多 100 MB，面板长时间不可用时超出的部分按上面的容量规则清理（留下墓碑和 `audit_pruned`，这条清理记录本身会被代发）。
  - 节点不一定可信，面板检查它返回的每一批：第一条的序号要大于游标、最后一条不小于第一条，每批不超过 500 条、2 MB，每行不超过 64 KB，不满足就丢弃这一批、记日志。S3 键里的序号用面板自己的游标（游标 + 1），不用节点给的：节点报一个用过的序号，也覆盖不了这一小时早些时候的对象。
  - 一个节点的这一批发不出去（例如接收端拒收）时只记日志，接着代发别的节点，不算目标失败；目标本身连不上时面板自己的记录也发不出去，由它算失败、告警。
  - 节点的本地序号被清空过（游标比最新的序号还大）时，节点从头返回，面板丢弃序号不大于游标的部分，等节点的序号超过游标后接着代发；清空前没读走的记录不再代发。
- **升级**：v0.29.1 以前节点自己外送，面板把外送目标连同凭据下发给节点，存在 `identity/auditsinks.json`。
  - 新节点第一次启动时删掉这个文件和 `audit/cursors.json`，记下以前外送到的位置（各目标游标的最小值），面板 7 天内第一次读时从那里开始，升级前后的记录不漏发。
  - 新面板连上节点时下发空的外送目标列表（`SetAuditSink`），旧版本的节点收到后删掉保存的凭据，之后只写本地文件，升级后由面板接着代发。
  - 旧版本的面板仍然下发带凭据的目标，新节点不保存，只删掉以前保存的，返回成功；旧面板不会读，节点只写本地文件，面板升级后接着代发。
- **局限**：
  - 节点被拿到 root 以后可以删改本地审计库：删改中间的记录会被链校验发现，但从某处起重写后面所有的记录、在末尾追加，只能靠已经外送的副本对比；面板还没读走的记录可能被删改，已经外送的记录还在。
  - 被攻破的节点可以往自己的记录里写假内容，但只能写在自己的 `node_id` 下。

## 混跑版本

v0.37.1 没有改接口（proto 不变），审计的线上格式和 v0.37.0 相同，只是两端各自把存储换成了新库。

- **v0.37.0 节点、v0.37.1 面板**：节点照旧写 `<数据目录>/audit/` 的 JSON Lines，面板照旧用 `ReadAuditLog` 按游标代发，行的格式相同。节点升级到 v0.37.1 时导入旧文件，序号不变，面板游标接着用，不重发不漏发。
- **v0.37.1 节点、v0.37.0 面板**：`ReadAuditLog` 返回的行和序号与旧文件一样，旧面板照常代发。旧面板仍会下发带凭据的外送目标，新节点照旧不保存。
- **主备版本不一致**：主备同步的审计连接（`nagi-standby-audit/1`）格式不变，传的是原来的 `id`、`prev_hash`、`hash`、墓碑和录制块。
  - v0.37.1 主面板、v0.37.0 备用面板：备用面板把记录写进面板目录的 `audit.db`，录制块写成它自己的录制文件；备用面板升级时按上面的「从旧版本升级」搬到 `logs/audit/`，链不变。
  - v0.37.0 主面板、v0.37.1 备用面板：备用面板写进 `logs/audit/audit.db`，从已有的最大 ID 续传。
  - 任一方向提升以后都接着同步来的最后一个哈希写，链能接上。外送游标存在审计库里随库搬动，搬动不会重发、漏发。v0.37.1 的主面板把游标随同步发给备用面板，v0.37.1 的备用面板提升后接着这些游标外送；只要有一方是 v0.37.0（不发或不收游标），提升后的面板从当时最新的记录开始外送，旧主面板最后没送到的记录（通常是最近几秒的）不会自动补发，要用导出补。

## 界面

左侧导航改为「日志」（`/logs`），原审计记录与能力集中在「审计与录制」。旧 `/audit` 书签保留筛选条件并跳转，不再维护独立审计页面。入口仍要「审计日志」权限（见下面的[权限](#权限)）；没有时导航和搜索里都没有入口，直接打开地址回到概览，权限在使用中被收回时也一样。

管理员另有「全部日志」，按节点、类别、项目、起止时间和关键字查询统一日志，见 [logging.md](logging.md#日志页面)。非管理员即使有「审计日志」权限，也只进入原审计能力，不开放跨项目统一日志 API；原审计接口本身的权限和可见范围不变。下面的筛选、列表和导出均指「审计与录制」。

- **筛选**：筛选框（动作、对象、IP、参数、错误）和时间范围在一行，类别、来源、成员、项目、节点、只看失败放在「筛选」对话框里，生效的条件列在下面，可以单独移除。筛选条件和打开的记录写进地址，可以分享。
- **列表**：每条两行。第一行是动作和对象（「部署 shop / web」「MCP 调用 deploy」）；第二行是灰色的成员 · 来源 · IP · 时间，右边是结果。`security` 类在动作前显示状态标记。有下级记录的可以展开。
- **详情**：点击一条记录，从右侧打开 `Sheet`（手机上从底部）：全部字段、参数 JSON、上级和下级记录。
- **导出**：按当前筛选导出 JSON Lines（带哈希）。
- **校验**：「立即校验」沿用 `VerifyAudit`，只验证原审计库的哈希链，不验证统一日志或近期副本，也不替导出时的脱敏改写背书。「设置 → 安全」原校验入口仍保留。
- 筛选对话框里的成员、项目、节点各要「成员」「查看」「查看节点」才列出，没有的那一项不显示；记录本身不受影响。
- 项目页和容器页的「事件」照旧，只显示这个项目或容器的操作和告警，要「查看」，不要「审计日志」。容器页的「查看全部」（跳到日志页的审计标签）、部署失败提示里的「查看记录」只给有「审计日志」的成员。

## 权限

审计是单独的一项权限「审计日志」（`panel.audit`，见 [panel.md](panel.md#权限)）：管理员默认有，可以勾进自定义角色和预置角色，不要别的权限做前提。有它的成员和管理员看到的一样：全部记录（包括访问范围以外的项目、节点和登录、安全事件），IP、`user_agent`、参数和失败详情，能导出、校验哈希链、回放终端录制（要先做高权限确认）。审计设置（终端录制、保留时间、外送目标、登录安全告警的开关）不在其中，归「安全设置」（暂时只给管理员）：只能看审计的人不能关掉录制、缩短保留时间或改外送的去向。

没有「审计日志」时，`ListAuditEvents`、`GetAuditEvent`、`ExportAuditEvents`、`VerifyAudit`、`ListActivity`、`GetRecording` 一律拒绝（`permission_denied`），MCP 的 `query_audit`、`export_audit`、`verify_audit`、`list_activity` 不在工具列表里。只有一种例外：有「查看」的成员可以用 `ListAuditEvents` 查访问范围内一个项目的告警（筛选条件只有这个项目和 `alert` 类别，可以带时间和关键字），项目设置里的出站限制用它列出最近被记录的目标；内容和项目的事件一样，按下表「其他成员」的规则清理。

| 角色 | 能看 |
| --- | --- |
| 管理员、有「审计日志」的成员 | 全部记录、导出、校验 |
| 其他成员 | 项目和容器的事件，以及上面说的本项目告警：访问范围内项目的记录（和其他页面同一个范围：直接给的项目，加上范围里的分组中的项目），要「查看」；不显示 IP、`user_agent` 和其他成员的会话，参数里地址类的键（`issued_ip` 等）去掉，看不到的节点换成「其他节点」（操作者、对象按类型和 ID，失败详情按引用标记；参数和失败详情里的节点 ID 去掉；不在文字里找名称，升级前的记录里写着的节点名照原样显示），只能按看得到的节点筛；没有「查看配置」的看不到失败详情和参数；有「查看配置」时，还要有做这个操作要的权限才看得到（`audit_api.go` 的 `detailPerms`）：查看、控制、部署类的操作有「查看配置」就够，执行的命令和终端要「终端」，文件的上传下载要「文件查看 / 文件修改」（没有时对象里的路径也不给，搜索也只按容器匹配），端口映射和域名要「网络和域名」，快照、备份、顶替、迁移、告警规则、镜像仓库各要相应的权限；项目设置（包括新建项目、MCP 的 `update_project`）有「项目管理」就能看，其中内部端口和出站限制、告警规则、快照的几项另要「网络和域名」「告警规则」「快照」，没有的从参数里去掉，这时也不给失败详情；认不出的动作只给管理员；项目的事件页用同一套规则。出站告警的标题和键里容器尝试连接的 `IP:端口` 要「查看访问地址」，没有时标题里换成「…」、键只留到容器。搜索只匹配自己看得到的字段：操作员匹配动作、成员、对象、客户端、参数和失败详情，只读成员只匹配动作、成员、对象和客户端（`audit.SearchOperator`、`SearchViewer`），否则按有没有结果就能逐字猜出隐藏的内容 |
| 访问令牌 | `query_events` 只返回项目的记录 |

## 接口

| 服务 | 方法 | 用途 |
| --- | --- | --- |
| SettingsService | `ListAuditEvents` | 按条件查询，或按 `parent_id` 查下级记录。要「审计日志」（没有时只能查本项目的告警，见[权限](#权限)） |
| SettingsService | `GetAuditEvent` | 详情，带上级和下级记录。要「审计日志」 |
| SettingsService | `ExportAuditEvents` | 导出 JSON Lines（服务端流）。要「审计日志」 |
| SettingsService | `GetRecording` | 按块读取录制（服务端流）。要「审计日志」，要先做高权限确认 |
| SettingsService | `VerifyAudit` | 校验哈希链。要「审计日志」 |
| SettingsService | `GetAuditSettings`、`SetAuditSettings` | 终端录制、保留时间、外送目标，以及哈希链状态。要「安全设置」 |
| SettingsService | `TestAuditSink` | 测试外送目标。要「安全设置」 |
