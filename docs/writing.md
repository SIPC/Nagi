# 文档写法

项目文档的写法，适用于 README、使用教程（[guide](guide/README.md)）和设计文档。界面文字见 [ui.md](ui.md#文案)，更新日志见 [development.md](development.md#发布)。

依据是 Apple Style Guide 和 Apple 支持文章：语气平实直接，先说读者能做什么，再说怎么做。

## 语气

- **书面语，平实直接**。不用口语、俚语、习语，不用感叹号，不用表情符号。不夸大：不写「轻松」「只需」「强大」。
- **中文省略主语**，用祈使句：「在「节点」页复制安装命令」。必须有主语时用「你」，不用「您」「用户」。设计文档的读者是开发者，「用户」指使用面板的人。
- **不用「我们」**。主语换成读者或产品：写「建议……」「Nagi 会……」，不写「我们建议」「我们会」。
- **现在时、主动语态**。写「面板保留容器目录」，不写「容器目录将会被面板保留」。只有尚未实现的功能才用「将」，设计文档里标明「未开始」。
- **以读者为主语**。写「可以在备用面板上提升为主面板」，不写「Nagi 允许你……」。
- **少用「请」**。说明步骤直接写动作；只在提醒对方配合时用，例如「请保持连接」。
- **用词准确**。「可以」表示能做，「可能」表示不确定；「开启 / 关闭」用于开关，「启用」只用于让后续操作成为可能的设置。
- **包容用语**。不用 kill、master/slave、黑名单 / 白名单（写「拒绝列表 / 允许列表」），不用颜色表示好坏。

## 使用教程的结构

1. **标题是一件事**，用动词开头：「添加节点」「升级与卸载」。
2. **第一段说明做完能得到什么**，有几种做法时一并列出。前提条件放在最前面（「开始前确认服务器满足系统要求」）。
3. **步骤用编号列表**，一步一个动作，每步是完整的句子，句末加句号。只有一步时不编号。
4. **动作之后写会看到什么**：「完成后终端输出面板地址、公钥指纹和初始化链接。」
5. **意外情况就地处理**，用「如果……，……」接在相关步骤后面，不另开一节。
6. **结尾给下一步**：「下一步：[添加节点](add-node.md)。」
7. 中英各一份，英文为 `<名字>.en.md`，结构和内容一致。

## 格式

- **界面元素的名字和界面上完全一致**。中文用「」：「节点」页、「立即同步」；英文用粗体：**Nodes**。路径用 → 连接：「设置 → 成员」，**Settings → Members**。
- **命令、文件名、目录、选项、字段名用代码格式**：`nagi agent`、`/srv/nagi`、`--no-agent`。命令不当动词用：写「执行 `nagi version`」。
- **占位符用尖括号和有含义的名字**：`<配对码>`、`<镜像地址>`，不用 foo、bar。
- **列表**：没有顺序的用项目符号，有顺序的用编号。列表前用冒号引出，各项结构平行；短语不加句号，完整的句子加句号。
- **提示**少用，不紧跟在标题后面，不连着放两个：
  - 「注意」：只与部分读者有关的信息。
  - 「重要」：容易出错但不会丢数据的地方。
  - 「警告」：可能丢数据或损坏服务的操作。
- **表格**：列标题简短，在表格前一段提到它。
- **链接文字写目标是什么**：「见 [系统要求](../README.md#系统要求)」，不写「点这里」。
- **数字和单位之间留空格**：10 分钟、4 MB。英文范围用 en dash：1–65535。

## 英文

- 用 **you** 称呼读者，不用 the user（设计文档中 users 指终端用户）。不用 we。
- 用缩约形式：don't、isn't、can't。不从名词缩约（不写 "The node's offline"）。
- 现在时：写 "The panel keeps…"，不写 "will keep"。
- 不用 please、e.g.、i.e.、etc.、via、in order to，分别换成省略、for example 或 such as、that is、and so on、through、to。
- 写 "Turn on"，不写 "Enable"。写 "You can … with Nagi"，不写 "Nagi allows / enables you to…"。
- 标题用句首大写：Add a node、Upgrade and uninstall。术语对照见 [ui.md](ui.md#多语言)。

## 设计文档

- 每个模块一个文件，加功能时只改对应的文件（见 [README](README.md)）。
- 先写结论和规则，再写原因；原因只写决定性的那一条。
- 写现状，不写变更过程。改了设计就改正文，历史留在 git 和 [decisions.md](decisions.md)。

## 参考

- [Apple Style Guide](https://support.apple.com/guide/applestyleguide/welcome/web)：contractions、future tense、passive voice、please、we、user、lists、Note / Important / Warning 等条目。
- Apple 支持文章，例如 [如何通过 iCloud 备份 iPhone 或 iPad](https://support.apple.com/zh-cn/108366)：任务式标题、编号步骤、动作后的结果、就地处理意外情况。
