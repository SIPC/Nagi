# 安卓 App

状态：进行中。首版做了添加手机（扫码）、解锁 App 和首页概览，见[进度](#进度)。下面是设计，已实现的部分写的是现状。

用手机管理集群：收告警推送，看项目、容器和节点的状态与监控，部署、重启、回滚，看日志，打开终端，管理文件和设置。功能和网页一致，权限和成员在网页上的一样。

## 范围

- **代码**：在本仓库的 `android/` 目录，Kotlin 和 Jetpack Compose。接口用 Connect（`connect-kotlin`），代码由同一份 proto 生成（`buf.gen.yaml` 加 Kotlin 的插件），接口改动和 App 改动放在同一个提交里。
- **系统要求**：Android 9（API 28）及以上。原因是密钥要用到 `setUnlockedDeviceRequired` 和完整的密钥证明（见[密钥](#密钥)）。
- **版本**：App 和面板使用同一个版本号，随面板一起发布在 GitHub Releases，APK 用固定的签名密钥签名，发布说明里写签名证书的 SHA-256。不上架应用商店。兼容和更新见[版本兼容](#版本兼容)和[更新](#更新)。
- **手机上存什么**：面板列表（名称、地址、公钥指纹）、设备 ID、App 自己的设置，以及加密的状态缓存（见[缓存](#缓存)）。配置、环境变量、日志、文件内容、审计和成员只放在内存里。显示环境变量、密钥的页面禁止截屏和出现在最近任务的缩略图里（`FLAG_SECURE`）。

## 功能

和网页一致，按成员的角色和访问范围显示。下表是各部分在手机上的做法，没有写的和网页相同。

| 部分 | 手机上的做法 |
| --- | --- |
| 首页 | 概览和告警合并：需要处理、关键数字、流量趋势、最近告警（见[首页](#首页)） |
| 项目 | 列表、分组、筛选、长按拖动排序；新建项目；项目概览、网络、设置 |
| 容器和服务 | 概览、日志、终端、配置、版本和回滚、网络、存储和文件、高可用、告警；添加容器、部署、重启、启动、停止、更新镜像 |
| 节点 | 列表、详情和监控；批准节点；添加节点时显示安装命令，可以复制或分享；节点终端、文件和镜像（管理员）。网络和高可用的拓扑图只在宽屏上显示 |
| 设置 | 网页的全部子页，最上面多一组「本机」（见[本机设置](#本机设置)）。审计在设置里 |
| 告警推送 | App 自己的长连接（见[告警推送](#告警推送)） |
| 小组件 | 桌面小组件（见[小组件](#小组件)） |

只在网页上做的：初始化面板、添加手机（见[扫码](#扫码)）、回放终端录制（审计详情里写明「在网页上回放」）。

## 界面和交互

视觉沿用网页，交互按安卓的习惯。设计稿在 `android/design/mockups.html`（截图为同目录的 `s1.png` 到 `s9.png`），改了设计先改设计稿。

### 视觉

组件都在 `core/ui`，各页面用这些组件拼，清单和用法见 [android-ui.md](android-ui.md)。

- 颜色变量、灰阶、状态色、圆角和间距档位取 [ui.md](ui.md#视觉) 的值，三条总则照样适用：常态黑白灰，颜色只表示状态，能不用框就不用框。字体用 MiSans（400 用 Normal，500 用 Regular）。
- 整体偏紧凑，下面是手机上的取值。
- **字号**：正文、列表行、按钮、标签 14，次要文字 13，等宽文字 13，和网页一致；区块标题 15 / 600，顶部栏标题 16 / 600；首页关键数字 22 / 500，数值块 18 / 500。
- **尺寸**：按钮高 36，列表行尾的小按钮（批准、更新）高 32；输入框高 36；页内标签高 40；单行列表行高 48，两行 56，首页「需要处理」更紧（单行 44，两行 52）。
- **间距**：页面左右 20；顶部栏到内容 4；大区块之间一条细线，线上下各 16，区块标题行高 36；卡片内边距 16，卡片里的容器行之间 6，卡片之间 12；设置的各组之间 24，组标题到第一行 4；并排按钮之间 12（网页是 8，手指比鼠标粗）；顶部栏右侧的图标按钮宽 48，图形对齐内容的右边缘 20。
- 放在 `muted` 底上的次要文字（日志的时间戳、选择栏、提示条）用 `muted-foreground-strong`，保证 4.5:1 的对比度。
- 状态点和文字：列表行里的状态点是独立的一列，和文件图标一样，到文字 12；跟在文字里的状态（「● 运行中」）点到文字 6。
- 可点区域至少 48 × 48（首页「需要处理」的行至少 44），看得见的部分可以更小（按钮高 36 和 32、胶囊里每项高 40），可点区域按 48 算。
- **选择项**：时间范围、日志级别、告警历史的筛选、高可用里选节点，都用下划线样式：文字靠左排，间距 20，选中的是主文字色加 500 字重，下面一条 2 的下划线，其余是次要文字色；不用带底色的分段控件。
- 浅色、深色跟随系统，可以在本机设置里固定。语言跟随系统（中文、英文），词条和网页共用：由脚本从网页的词条生成 `strings.xml`，`check:i18n` 一并检查。
- 图表用 Vico（Compose 的图表库），样式按 ui.md 的「监控图表」。
- 状态不只靠颜色：正常时可以只有状态点，异常、停止、离线时在名称后面写短状态（「异常」「已停止」「离线」），项目卡片里的容器行也一样。
- 开关和网页的 `SettingSwitch` 一样写成设置行：第二行开头写「已开启」或「已关闭」，右边一个有框按钮「关闭」或「开启」，不用安卓的开关控件。

### 交互

- **弹出面板**：下拉菜单和小对话框改用底部弹出面板。危险操作的确认（填名称、勾选同时恢复数据）也在底部弹出面板里，按钮变红的规则和网页一样。
- **操作确认**：重启、停止、重新部署在手机上都要先确认（网页上重启直接执行），面板里写清对象和影响，例如「重启 web，服务会中断几秒」。它们会中断服务、撤销不了，手机上误触又比鼠标多。启动不中断任何东西，直接执行。
- **长按**：不做左右滑动的操作。长按列表行打开这一行的操作面板；文件列表里长按进入多选（见[文件](#文件)）。
- **新建**：新建项目、添加节点、添加容器的入口是顶部栏的加号，不用悬浮按钮，免得和底部的胶囊导航互相挡。
- **刷新**：页面上的数据和网页一样定时查（见[数据刷新](#数据刷新)），只在页面打开、App 在前台时查；下拉、点「重试」立即查一次。平时不写更新时间，只在显示缓存或连不上面板时写。
- **断网时的操作**：连不上面板时点重启、部署这类操作，直接提示「连不上面板，没有执行」，不排队，网络恢复后也不自动执行：那时情况可能已经变了。
- **结果和进度**：操作结果用 Snackbar（在胶囊导航上方），例如「已重启 web」。长操作（部署、拉取镜像、上传、复制文件）的进度显示在页面顶部，和网页一样；离开 App 时在通知栏显示进度，完成或失败时变成结果，点开回到对应页面。部署由面板执行，离开不影响；上传由 App 在后台继续。
- **复制**：等宽字的值（地址、镜像、路径、ID）点一下就复制，轻振一下并提示「已复制」。访问地址这类链接点一下打开，长按复制。
- **时间**：和网页一致。告警、事件写相对时间（「4 分钟前」），文件、快照、版本写具体的日期和时间；长按相对时间显示具体时间。
- **图表**：按住图表出现竖线和提示框，左右滑动切换时间点，松手消失。轻点不触发，不影响页面滚动。
- **搜索**：点顶部栏的搜索打开全屏搜索页，输入框在顶部并弹出键盘。没输入时列出最近打开的项目、容器、节点；结果按项目、容器、节点、设置分组，支持拼音和首字母，规则和网页的搜索一样。
- **加载和出错**：加载用骨架，查询失败显示红字和「重试」，规则同网页的状态表。
- **动画**：和网页同一套（[ui.md](ui.md#动画)），实现集中在 `core/ui` 的 `Motion.kt`，曲线和时长从那里取：
  - 进入下一级页面时从右侧滑入，返回时滑出，支持安卓的预测性返回手势；切换主导航左右滑入并淡入，和导航同方向（选右边的标签，新页面从右边进来、旧页面往左让开）：进来 32、透明度先到（120ms），共 300ms；旧的同方向移开 16、100ms 淡出。网页规范里手机主导航只淡入淡出，App 按用户的要求改为左右滑入。
  - 每一页都铺满页面底色（不透明），进下一级时新的一页盖住旧的一页滑进来，返回时滑出去露出下面的一页，滑动中两页的内容不会叠在一起。预测性返回在 Manifest 里打开（`enableOnBackInvokedCallback`），Android 14 起拖返回手势时跟着手指预览上一页，松手才切换。
  - 整页的状态切换（添加完成进首页、解锁、锁定、退出）：新的一页晚 60ms 淡入，同时从 98% 放大到原大小（300ms）；旧的一页 120ms 淡出。不硬切。
  - 换浅色、深色时每个颜色 300ms 过渡过去。
  - 骨架换成内容、提示出现：淡入 160ms。
  - 会变的数据（关键数字、数量、速率）用跳字（`Roll`）：只有变了的那几位上下滚动，变大从下面上来，变小从上面下来，从右往左错开 16ms，宽度也过渡；第一次显示不滚。
  - 高度变化（`autoHeight`）：条目增减、数据加载完时过渡到新高度，下面的内容跟着移动，360ms。
  - 多出、少掉的一块（`Collapse`，例如「连不上面板」）：高度和透明度一起过渡，360ms。
  - 选中指示器（胶囊的底色、选择项的下划线）：从上一项滑过去，用弹簧，非线性并带一点回弹；朝移动方向的边快、另一条边慢，中途略微拉长。中途换了目标从当前位置接着滑。
  - 占用条长度 220ms，状态点颜色 300ms。
  - 系统开了「移除动画」时，位移、缩放和弹簧都直接到位，只剩淡入淡出。
- **振动**：只在长按进入多选、拖动排序、危险操作确认、操作失败、复制时轻振，跟随系统的触感设置。
- **字号**：跟随系统的字体大小，最大 2 倍。字号变大时列表行、数值块、设置行从左右排列改为上下排列，不截断文字；布局按 1 倍、1.3 倍、2 倍检查。终端、日志和图表的坐标不跟随，终端和日志用双指缩放调整。
- **返回**：返回手势和系统返回键按安卓习惯。编辑器、表单里有没保存的修改时，返回前问「放弃修改」还是「继续编辑」。

### 导航

- 底部是悬浮的胶囊导航，四项：首页、项目、节点、设置，图标是 House、Folder、Server、Settings（Lucide），网页主导航用同样的图标。平时只显示图标；选中的一项在图标右边写出名称，底色是 `muted` 的胶囊。胶囊按内容宽度在底部居中，距底部手势条 12，高 52，内边距 4；每项高 44、左右各 13，图标 22，图标和名称之间 4；可点区域是胶囊的整个高度。
- 胶囊宽度不跳变：没选中的一项宽 48，选中的一项按最长的名称留宽度（名称较短时居中）。切换时旧的一项收起、新的一项展开用同一条弹簧，一减一加正好抵消；底色同时从旧的一项滑到新的一项（见[交互](#交互)「动画」）。外框和底色的回弹联动：切到最左、最右一项（点击或拖动）时，底色回弹越出内容区，外框在那一侧按越出的距离撑开（最多 6），回弹结束一起收回；中间几项不动。底色滑动时后面跟一小段拖尾（比两条边都慢、不回弹的弹簧），从底色渐变到透明，最长 20，到位时缩回。
- 长按胶囊后左右拖动：手指经过哪一项就切到哪一项（名称展开、页面切换，和点击一样），每切一次轻振一下；按住时胶囊放大 4%，松手回弹。手指下是哪一项按胶囊等分来算：各项宽度在变，但总宽度不变，等分是稳定的。`card` 底色、1px 边框、浅阴影，滚动时不收起。图标都有无障碍标签，读屏会读出名称；长按图标显示名称提示。
- 胶囊只在四个一级页面显示。进入二级页面（项目页、容器页、节点页、设置的子页等）时隐藏，顶部栏有返回；键盘弹出时也隐藏。
- 胶囊后面不加渐隐，内容直接从胶囊两侧露出来；页面内容最后留出 104 的空白，滚到底时不被胶囊挡住。一级页面的内容铺满整页、从顶部栏下面开始，往上滚时从顶部栏下面经过；顶部栏自己的最下面 20 从背景色渐变到透明，内容滚到那里变淡，渐变收在顶部栏里面，不盖住内容。
- 可点的整行（列表行、设置行、数值块）按下时的底色比内容左右各宽出 12（伸进页面边距），圆角 8，和网页列表行悬停的底色一样，不贴着内容边缘截断。
- 有严重告警（见[通知](#通知)）时，首页图标右上角一个红点。
- 每个标签保留自己的页面栈，切换标签不丢失位置（滚动位置放在标签外面）；再点当前标签回到它的第一页、滚回顶部。不在首页时按返回先回首页，在首页再按才退出 App。
- 四个一级页面的顶部栏：左边是当前面板的名称和下拉箭头（见[多个面板](#多个面板)），右边是新建（有的话）和搜索。搜索的范围和规则和网页的搜索一样（项目、容器、节点、设置项）。
- 二级页面的顶部栏是返回、标题、⋯。
- 深链接 `nagi-app://<面板 ID>/<网页地址的路径>`，例如 `nagi-app://<面板 ID>/projects/<项目>/c/<容器>`。通知、小组件用它打开页面，路径和网页的地址一一对应。

### 宽屏

窗口宽度达到 600 dp（平板、横屏、折叠屏展开、分屏较宽的一侧）时：

- 底部的胶囊导航换成左侧竖向的悬浮胶囊，样式和动效相同（选中底色滑动、长按后上下拖动切换，和底部的胶囊共用一套手势）：最上面是 logo（不可点，没有分割线），下面是四个图标，选中的一项在图标下面写名称。左侧是 88 宽的一栏：上面是当前面板（名称首字的圆标，点开面板列表，代替顶部栏），胶囊在左下角，离底部手势条 12。一级和二级页面都显示。
- 右边没有顶部栏，整块给内容：内容从状态栏下面 12 开始，状态栏那一条从背景色渐变到透明，内容滚到那里变淡。
- 列表和详情并排：项目页左边是项目栏（概览、各个容器和服务、网络、设置），和网页一致；节点页左边是节点列表，右边是节点详情；设置页左边是二级菜单。
- 首页的内容区宽度达到 720 dp 时：需要处理整行在最上面；下面左边一栏从上到下是关键数字（两行两列）、流量趋势、节点状态（两个一行）、流量最大的映射，右边是实时流量的桑基图（约 60%），高度铺满左边一栏。不到 720 时和手机一样从上到下排。
- 桑基图的高度自适应：并排时右边一栏和左边一样高，桑基图铺满标题行以下的空间，最后一行的速率和左边一栏的底部对齐。比它矮时把行距加大（行和行之间最多 72）；比它高时一档一档收紧行距（每次 2，行和行之间最少 6，一行最少 34，刚好放下名称和速率），还放不下才少列几个节点，流量小的合并成「其他」（至少留 2 个）。手机上从上到下排，不限高度，超过 8 个节点时合并。
- 宽度达到 840 dp 时，容器页显示全部九个标签（和网页一样），节点页显示网络和高可用的拓扑图。

只按窗口宽度判断，不按设备类型；旋转、展开折叠屏、调整分屏时布局跟着变，当前页面和输入的内容不丢。

现在做到的：左侧一栏（面板圆标和竖向的胶囊 `PillRail`，在导航外面，二级页面也显示；在二级页面点胶囊先回到一级页面再切换），设置页左右两栏（左边菜单宽 360，选中的一行有底色；右边是选中的一项，有自己的导航，默认是个人资料，子页里再点进去也在右边）。

### 首页

从上到下：

1. **需要处理**：未恢复的告警、待批准的节点、待确认的顶替、可更新的镜像、面板和 App 的新版本，一行一项，点击打开对应页面。严重的排在前面，最多显示 5 条，超过时最后一行是「还有 N 项」，点开看全部。没有时整块隐藏（连同下面的分隔线），最后一项处理掉时高度和透明度一起收起。能一步做完的行尾直接放按钮：待批准的节点是「批准」，可更新的镜像是「更新」，待确认的顶替是「确认」；会中断服务的（更新、确认顶替）点了仍先确认。
2. **关键数字**：节点在线、容器运行中、对外入站、对外出站，两行两列。点数字打开对应的明细：「节点在线 5 / 6」打开只显示离线节点的列表，「容器运行中」打开没在运行的容器。
3. **实时流量**：和网页概览一样的桑基图（`SankeyChart`，见 [android-ui.md](android-ui.md#图表)）。左边发出、右边接收，每个节点和外部网络一行，离线的节点变灰；选择项（全部、对外、节点之间）和标题在同一行、靠右。路径和网页一样在手机上算（`core/data` 的 `HomeData.kt`，算法同网页的 `overview.tsx`），约 10 秒一份。动效和网页一致：位置、线宽在 360ms 内过渡，中途变了接着走；切换视图时不属于这个视图的路径和行淡出、其余换位；新路径从所在的行长出来；淡出在前半段、淡入在后半段；断流的路径留 30 秒（显示 0 B/s）；超过 8 个节点时其余合并成「其他」。点一下线显示「发出 → 接收 速率」，点别处收起；接鼠标时悬浮就显示，移出收起。每一行的高度取这一行的线叠起来的高度和名称、速率两行字的高度（手机 36、宽屏 40）中较大的，行和行之间再留 12（宽屏 18），线和线之间 2：节点多时一行有很多条细线，只按线算行距会很大。两边留给名称和速率的宽度按实际的文字量：最宽的那一项再加 12，线从这里开始（最多占宽度的 28%，宽屏 24%）；速率一直在变，留的宽度只增不减，图不会跟着数字左右抖。手机上（窗口宽度不到 600）线宽系数 0.18、最粗 20（网页 0.24、不封顶），名称用 13 号字。
4. **流量趋势**：对外和节点之间，时间范围的选择项（1 小时、24 小时、7 天）和标题在同一行、靠右。点一下图看那一刻的时间和两条线的速率（同网页的提示），再点一下收起；长按后左右拖动逐个看；接鼠标时悬浮就看。
5. **节点状态**：和网页概览的节点表一样，精简成一个节点一行：状态点、名称，右边是 CPU、内存、磁盘三个占用环（26，线宽 2.5，中间是这一项的图标 Cpu、MemoryStick、HardDrive，不写数字；读屏读出名称和百分比；CPU 按核数折成 100%；到 80% 变警告色、90% 变红）。离线、待批准的在名称下面写出来，没有占用环。宽屏左边一栏两个一行。点一个去节点页。
6. **流量最大的映射**：和网页一样，最近 24 小时流量合计最多的 3 个端口映射，标题右边写「24 小时」；一行是地址和合计流量，下面一条横向的条形（品牌色，长度按最大的一个算）。
7. **最近告警**：最近 20 条，包括已恢复的，一行是状态点、标题、对象和时间。点「全部」打开告警历史（见[列表和图表](#列表和图表)）。

### 项目和容器

- **项目列表**：和网页一样按分组分段，卡片写状态、容器数、CPU 和内存。卡片里最多列 3 个容器：异常和停止的一定列出，其余按名称补满，多出来的写「还有 N 个」。⋯ 菜单里多一项「在本机关闭推送」（见[内容](#内容)）。
- **项目页**：标题、状态和网络名；监控数字；容器列表（容器组可以展开服务）；最后是「网络」「设置」两行入口。容器按状态排序，异常、已停止的在前面，同一状态按名称。
- **长按容器**：项目页里长按容器行，弹出这个容器的快捷操作：重启、日志、终端、更多（更多里是停止、重新部署等其余操作）。不用先进容器页。
- **容器页**：顶部是标题、状态和节点，下面是「重启」（已停止时是「启动」）和「重新部署」两个按钮，重命名、停止、删除在 ⋯ 里。标签只有概览、日志、终端、配置四个，可以左右滑动切换；在终端和日志里滑动留给内容本身（选择文字、横向滚动），不切换标签。版本、网络、存储、高可用、告警列在概览的最下面，一行一项，行尾写当前状态（例如「v12」「2 个映射」「已设置顶替」），点击进入。
- **服务页**：标签是概览、日志、终端、监控，和网页一样。
- **节点列表**：有问题的排在前面：离线、待批准、用量超过阈值的，其余按名称。一行是状态点、名称（离线、待批准时后面写状态），第二行等宽字写地址，第三行是 CPU、内存、磁盘三条并排的细占用条（高 3），上面写名称和百分比；平时灰色，75% 起琥珀，90% 起红，和网页的占用指示一样。右边是容器数；待批准的节点右边是「批准」按钮，离线的不画占用条。
- **节点页**：和容器页同一种写法。标签是监控、容器、终端、文件（终端和文件只有管理员有），镜像、节点网络、副本、面板、设置列在监控的最下面。宽度达到 840 dp 时显示全部标签。
- **节点网络**：手机上不画拓扑图。最上面一行写节点数、连接数和有问题的条数；下面先列有问题的连接（不可达、经面板中转，写原因和延迟），再列直连，按延迟从低到高。点一条连接看两个方向的延迟历史。
- **高可用**：手机上不画拓扑图。上面是选节点的选择项（节点多了横向滚动），下面按网页的模拟规则，分组列出「这个节点故障时」它上面的容器：自动顶替、确认后顶替、可从备份恢复、数据无法恢复、无状态可重新部署，每行写去向或原因。
- 宽度达到 840 dp 时，节点网络和高可用显示拓扑图，和网页一样。
- **添加容器**：整页表单，单列，按钮撑满，字段顺序和网页一样。

### 日志、终端和编辑器

- **日志**：流式显示，默认跟随最新；可以暂停、搜索、选择服务、复制选中的行、分享。工具栏里有级别的选择项：全部、警告、错误（按行里的 `WARN`、`ERROR` 等关键字和日志流判断），选「全部」时多一个「下一个错误」，跳到下一条错误并高亮。默认自动换行，工具栏里可以切换为不换行、横向滚动，选择记在本机。双指缩放调整字号。
- **终端**：用 Termux 的 `terminal-emulator` 和 `terminal-view` 库（Apache 2.0）。配色跟随 App 的深浅色：浅色时是白底深字，ANSI 颜色换成在白底上看得清的一套。键盘上方一行按键：Esc、Tab、Ctrl、Alt、方向键、`|`、`/`、`-`、`~`。每个键 44 × 44，放不下时这一行横向滚动，常用的排在前面。双指缩放调整字号，横屏可用。连接后状态里一直写用户和对象（例如 `root · node1`），和网页一样。
- **离开前台**：终端和日志流保持 5 分钟，期间用前台服务保持连接，通知写「终端仍在连接」和剩余时间；超过 5 分钟断开，回来时显示「重新连接」。长时间的任务建议在终端里用 tmux。
  - 终端还没有做。实现时注意：面板在手机超过解锁时长后断开终端（见[换取令牌](#换取令牌)），解锁时间只在换取令牌时往后延，App 在后台不换取。所以离开前台时先换一次令牌，保持的时长取 5 分钟和解锁时长里较小的那个并留出余量，通知里的剩余时间按它写；解锁时长设为最小的 5 分钟时不能照 5 分钟保持。
  - 做完在真机上验证两种情况：在终端和别的 App 之间频繁切换（每次停留不到 4 分钟）超过 15 分钟；解锁时长设为 5 分钟时离开前台到保持结束。终端都不应被提前断开。
- **编辑器**：compose、容器配置、卷文件和节点文件的编辑用 Sora Editor（LGPL-2.1，以库的方式引用，开源许可里写明）。等宽字体、行号、撤销和重做；YAML、JSON、Shell、INI、Dockerfile 按语法高亮，其他文件按纯文本显示。键盘上方一行按键：Tab、缩进、取消缩进、`:`、`-`、`"`、`#`、`{}`、`[]`、撤销、重做，尺寸和滚动同终端的按键行。保存前显示和当前版本的差异。超过 1 MiB 的文件不能编辑，和网页一样。

### 列表和图表

- **时间范围**：所有监控区块的时间范围用下划线样式的选择项（1 小时、24 小时、7 天，见[视觉](#视觉)），和区块标题在同一行、靠右，选项之间 16；没有区块标题的（节点详情的用量、展开的图表）单独一行、靠左。不用下拉。
- **数值块展开**：监控平时只显示数值块（名称、当前值、小折线）。点一个数值块，它变成选中的底色，在这一组数值块下面展开完整图表；再点收起，点另一个换成它的图表。按住图表看各时间点的数值（见[交互](#交互)）。
- **按天分组**：告警历史、版本、事件、审计按天分组（今天、昨天、11 月 16 日），滚动时日期标题停在顶部。告警历史上面是选择项：全部、未恢复、严重。

### 文件

- 卷文件和节点文件同一种写法，和网页的文件管理对应：顶部是面包屑，一行是图标、名称、第二行的修改时间、右边的大小和 ⋯（下载、复制下载链接、编辑、重命名、复制、剪切、压缩、解压、删除）。
- 长按一项进入多选：每行前面出现复选框，顶部栏变成「已选择 N 项」和复制、删除、⋯，返回或点 × 退出。平时不显示复选框。
- 复制、剪切后，列表上方一行写「已复制 N 项」和「粘贴到此处」，规则同网页的剪贴板。
- 上传从系统的文件选择器选，可以多选，用现有的分块上传，网络切换后从断点接着传。
- 下载由 App 自己做，不交给系统的下载管理器：系统的下载管理器只认系统信任的证书，用 IP 和自签证书的面板下载不了。App 用和其他请求一样的连接（校验公钥指纹）请求签名链接，存到系统的「下载」目录；前台服务在通知栏显示进度，支持断点续传。签名链接第一次使用后只认这个来源地址（见 [panel.md](panel.md#会话) 的「下载」），手机换了网络（Wi-Fi 和移动数据之间切换）后接着下载要重新请求链接。节点直连下载时，节点证书的指纹由面板在 `Info` 里给出，App 同样校验。
- 在移动网络下上传或下载超过 100 MB 时先问一次：「现在传」或「等连上 Wi-Fi 再传」。

### 敏感值

- 环境变量里的密钥、deploy key、webhook 令牌等默认显示为圆点。点眼睛时先验证指纹、面容或锁屏密码，切到后台时重新隐藏。这些值本来就随配置返回到手机上，所以这是本机的验证（`BiometricPrompt`，不经过面板），用来防止别人拿着已经解锁的手机查看。
- 复制敏感值时把剪贴板内容标记为敏感（`EXTRA_IS_SENSITIVE`，系统的剪贴板提示里不显示内容），60 秒后清空剪贴板。

### 缓存

- 缓存的内容：项目、容器、服务、节点的名称、状态和占用，首页的「需要处理」和关键数字。不缓存配置、环境变量、日志、文件、审计和成员。
- 打开 App 时先显示缓存，标明「更新于 10:02」，同时向面板刷新。
- 缓存按面板分开存，用 Keystore 里的 AES-256-GCM 密钥加密（只在手机解锁时能用，放在 TEE，不用 StrongBox：每次打开都要解密，要快）。退出一个面板、或者面板说这台手机已经退出时，删除这个面板的缓存和密钥。
- 现在缓存的是首页的数据（`SessionCache`）：打开 App 时直接显示上次的首页，同时查面板，查到就覆盖；连续 5 秒查不到才显示「连不上面板」和缓存的时间。
- 另外记下面板给的下一次换取用的挑战（15 分钟内有效），下次打开少一次往返。挑战不是凭据：没有硬件里的设备密钥签名，拿到它也换不到令牌。

### 多个面板

- 一个 App 可以添加多个面板，最多 10 个。每个面板有自己的设备 ID、三把密钥（密钥别名里带面板 ID）、缓存和推送连接，互不影响。
- 点顶部栏的面板名称打开面板列表（底部弹出面板）：每个面板写名称、成员和需要处理的数量，选中一个即切换。列表下面是「添加面板」和「管理面板」（改本机上的显示名称、排序、退出）。
- 点通知、小组件打开的是别的面板的页面时，App 自动切到那个面板。
- 推送同时连接所有面板。通知和小组件上写面板名称。

### 通知

- **渠道**：每个面板一个渠道组，组里是「严重告警」「告警」「已恢复」「连接状态」。另有一个「后台连接」渠道，用于前台服务的常驻通知。用户可以在系统设置里按面板、按渠道调整。
- **严重告警**：节点失联、顶替相关的告警、安全告警。本机设置里有「严重告警在勿扰模式下也提醒」，默认关闭，打开时请求系统的勿扰权限。
- **内容**：标题是告警标题，正文是对象（项目和容器，或者节点）和时间。同一条告警的触发和恢复更新同一条通知，不另发一条。锁屏上显示多少按系统的锁屏通知设置，App 不另设选项。
- **操作**：点通知打开对应的页面（需要时先解锁 App），通知上不再放「查看」。唯一的按钮是「静音 1 小时」：本机 1 小时内不再提醒同一条告警（同一个对象的同一条规则），恢复的消息照常显示；不改动面板上的任何设置。
- **正在看的不提醒**：App 在前台、正打开着某个容器或节点的页面时，它的告警只更新页面，不弹通知。

### 小组件

- 添加时选一个面板。显示面板名称、需要处理的数量、节点在线数和容器运行数，不显示项目、节点的名称：小组件在桌面上，任何能看到手机的人都能看到。
- 数据来自推送连接：面板每次数量变化时在推送流上发一条摘要（见[接口](#接口)）。关闭推送时小组件显示「需要开启告警推送」。
- 点击打开这个面板的首页；有需要处理的事项时打开需要处理的第一项。
- 用 Jetpack Glance 实现，跟随系统的深浅色。

### 本机设置

设置页从上到下：账号（头像、名称、角色）、「本机」一组、面板的设置。「本机」一组是：

- **面板**：面板列表和管理，和顶部栏的面板列表相同。
- **告警推送**：总开关；按类别（节点、容器、安全）和按项目关闭；恢复的消息；严重告警在勿扰模式下也提醒；后台运行的检查和引导（电池优化、自启动）。
- **外观**：浅色、深色、跟随系统。
- **语言**：跟随系统、中文、English。

下面才是面板的设置：我的账号、面板、节点、审计，和网页的二级菜单一样，不是管理员时只有我的账号。

最下面单独一项「关于」，App 和面板的合在一起：上面一组是 App（版本、签名证书指纹、检查更新、崩溃日志的查看和分享、开源许可，包括 MiSans 的署名和 Sora Editor 的 LGPL 说明），下面一组是面板（版本）。

现在做到的（`feature/settings`）：

- 账号一行：头像、名称、角色，来自 `AppService.Info`；名称先用本机记下的，角色和头像回来后显示，面板的几组知道权限后展开。`Info` 还返回当前成员的权限（`permissions`，见 [panel.md](panel.md#权限)）和角色（`role_id`、`role_name`、`role_builtin`），App 按权限隐藏入口（`core/data` 的 `Access`），和网页一样；`role` 是给旧版本看的角色名（管理员是 `admin`，其余按权限算 `operator` 或 `viewer`）。面板不返回权限时（旧版面板，`role_id` 为 0）按以前三种角色能做的事算。设置里各项要的权限：面板访问、告警要「面板设置」，安全策略要「安全设置」，成员要「成员」，备用面板、接收节点、节点网络只给管理员；面板访问里对外地址、指纹、主密钥、安全入口只给管理员；关于里更新面板要「面板设置」，让面板联网检查只给管理员。
- 本机：面板（名称、成员、地址、域名和「退出这台手机」，顶部栏的面板列表也是它）、外观、语言。告警推送等推送做了再加。
- 关于（最下面）：App 的版本、签名证书的 SHA-256（点一下复制，和发版说明里 `apksigner` 的写法一样；这是安装包自己读出的值，被改过的安装包可以显示任意值，说明文字写明要在安装前用 `apksigner verify --print-certs` 校验）、崩溃日志、开源许可；面板的版本。检查更新要 `Info` 先返回最新的 App 版本。
- 外观选了马上生效，状态栏和导航栏的图标颜色跟着变。语言：Android 13 起交给系统的「应用语言」（`locales_config.xml`，系统设置里也能改），更早的版本在 Activity 创建时换掉语言，切换后重建界面，停在语言页。
- 面板页：每台手机可以给面板起本机显示名称（只存在本机，优先于面板名称显示，顶部栏、解锁页、面板列表都用它）；管理员还能改面板名称（所有成员看到的都变）。两个都是一个输入框加「保存」，留空恢复默认。
- 面板设置的各项都接了面板的接口，和网页一样（`feature/settings`）：
  - 个人资料：头像（选图片，裁成正方形、缩到 128，存成 WebP）、显示名称（`UpdateProfile`）。
  - 账号安全：更改密码（之后这个成员的所有手机都会退出，包括这台，写明后再改）、关闭两步验证（验证码或密码）、通行密钥（列出、删除）、登录设备（列出、让别的设备退出）、访问令牌（列出、吊销）。
  - 面板访问：面板名称、对外地址、绑定和解除域名、公钥指纹和主密钥（复制）、安全入口（开启后给出地址）。
  - 安全策略：终端录制、审计记录保留（缩短时先确认）、日志外送的状态、哈希链（立即校验）、会话（空闲超时、有效期、网络绑定）、管理员登录地址（只显示）。
  - 成员：列表；一个成员的角色（从角色列表 `SettingsService.ListRoles` 选，填 `role_id`）和访问范围（项目「全部 / 指定」，节点「全部 / 跟随项目 / 指定」，逐个勾选；网页上按分组、标签选的保留不动）、重置密码、清除两步验证和通行密钥、删除；添加成员。角色的新建和编辑只在网页上做。要「成员」权限；不是管理员时，包含自己没有的权限的角色和管理员角色置灰、不能选。旧版面板没有角色列表（`ListRoles` 返回未实现）时仍按 `admin`、`operator`、`viewer` 三种选，节点范围没有「跟随项目」。v0.35.0 起的面板上添加和修改成员只能在网页上做（见下面「手机上不做的」）：不显示「添加成员」，成员页的角色、访问范围和通行密钥数量只读，不显示保存、重置密码、清除两步验证和通行密钥，只留删除，并写明「请在网页上修改」。
  - 告警：通知渠道（webhook、Telegram，加、改、测试、删除）和登录安全告警的三个开关。
  - 备用面板：主面板上列出、添加（给出命令）、移除；备用面板上写同步状态，可以提升为主面板。v0.35.0 起的面板上不显示「添加」和「提升为主面板」，写明在网页上操作。
  - 接收节点：有效的接入码，生成、撤销。
  - 节点网络：面板自己在节点网络里的连接，每 5 秒刷新。
  - 关于：管理员能检查更新、看更新说明、更新面板，更新中显示进度。
- 手机上不做的（写明在网页上操作）：开启两步验证、添加通行密钥、生成访问令牌、添加手机、添加备用面板、提升为主面板、添加成员、修改成员（角色、访问范围、重置密码、清除两步验证和通行密钥）（只认密码或验证码做的高权限确认）：面板要求验证时不弹系统验证框，直接提示「这一项只能用密码或验证码验证身份，请在网页上操作」，确认框里的操作把提示写在确认框里。其他要先做高权限确认的操作（编辑管理员登录地址、编辑日志外送目标、关闭终端录制、缩短保留时间）在手机上弹出系统验证框，确认后完成（见[高权限确认和重新验证](#高权限确认和重新验证)）；确认后面板仍然要求验证的，同样提示到网页上操作。不要求确认的旧面板照常完成。
  - 其中有入口的几项（添加和修改成员、添加备用面板、提升为主面板）从 v0.35.0 起只认密码或验证码。App 按 `Info` 的版本号判断（`Access.webOnlyChanges`）：v0.35.0 及以后的面板上入口做成只读或隐藏，旁边写「请在网页上操作」；更早的面板照常显示、照常能做。认不出的版本号（开发构建）按当前代码算；`Info` 查不到时入口照常显示，面板拒绝时再提示。
  - 删除成员走普通的高权限确认：面板要求验证时弹系统验证框，确认后完成。角色的新建、编辑和删除 App 里没有入口。

### 更新

- 面板本来就会检查新版本（见 [panel.md](panel.md#更新面板)）。App 从 `AppService.Info` 拿到最新的 App 版本和下载地址，比自己新时在首页的「需要处理」里出现「App 有新版本」。
- 点击后在 App 里下载 APK，核对签名证书和当前安装的一致，再交给系统安装器。第一次需要用户允许「安装未知应用」。签名不一致时不安装，提示原因。

## 为什么不用网页的会话

网页的会话靠 cookie，防盗靠浏览器标识、TLS 指纹和浏览器里的会话密钥（见 [panel.md](panel.md#会话)）。原生 App 的 HTTP 客户端在面板看来就是脚本工具，会被直接退出；而且手机有更好的办法：Android Keystore 能在硬件里生成不能导出的密钥，并由硬件出具证明。所以 App 用单独的会话：

- 凭据是**硬件里的密钥**，不是能被复制的令牌。手机上只有设备 ID，没有长期有效的秘密。
- 请求用**短期令牌**：用硬件密钥签名换取，只放在内存里，10 分钟过期，只能从换取时的网段使用。
- 不做 TLS 指纹和浏览器标识的检查。这些检查用来发现 cookie 被偷到别处使用，App 的令牌偷到也只能在同一网段用几分钟。

## 密钥

每台手机在 Android Keystore 里生成三把 ECDSA P-256 密钥，都要求在硬件里（TEE 或 StrongBox，有 StrongBox 时优先用）：

| 密钥 | 用途 | 使用条件 |
| --- | --- | --- |
| 设备密钥 | 换取请求用的短期令牌 | 手机解锁时才能用（`setUnlockedDeviceRequired`） |
| 确认密钥 | 解锁 App、高权限确认、重新验证 | 每次使用都要验证指纹、面容或锁屏密码（`setUserAuthenticationParameters(0, BIOMETRIC_STRONG or DEVICE_CREDENTIAL)`） |
| 推送密钥 | 打开告警推送的长连接 | 没有限制，锁屏时也能用 |

推送密钥单独一把，是因为锁屏时也要收告警；它只能打开推送连接，不能调用任何接口。

Android 9 和 10 上，每次使用都要验证的密钥只支持指纹和面容（`setUserAuthenticationValidityDurationSeconds(-1)`），Android 11 起才能用锁屏密码。没有录入指纹或面容的 Android 9、10 手机不能添加。

**密钥证明**：添加手机时，App 提交三把密钥的证明证书链（Key Attestation），证明的挑战是配对码的 SHA-256。面板核对：

- 证书链能追溯到 Google 的硬件证明根证书（`internal/server/auth/attestation/roots.pem`，取自 `https://android.googleapis.com/attestation/root`）。按根证书的公钥比较：同一把根密钥签发过不止一张证书，旧手机的链可能以旧证书结尾。根证书随面板版本更新。
- 链里每张证书由下一张签发；除第一张（叶子）外每张都必须是 CA（`BasicConstraints` 的 `cA` 为真），证明扩展只能出现在第一张。否则任何一把 Keystore 密钥（不是 CA，但私钥能对任意数据签名）都能给一张伪造的叶子签名，把链延长一张，冒充硬件密钥（「链延长」）。链最多 10 张，每张最多 16 KiB（`attestation.MaxChain`、`MaxCertBytes`）。
- 布尔值按 BER 读：有的手机（例如部分小米机型）把扩展的 `critical`、证明里的 `deviceLocked` 写成 0x01，DER 只允许 0xFF，Go 的解析会拒绝。解析前把这类值改成 0xFF（只改这一个字节，意思不变），签名仍按手机发来的原样字节校验，所以不会让改过的证书通过。
- 密钥在硬件里（`attestationSecurityLevel` 是 TrustedEnvironment 或 StrongBox），不能导出。
- 每把密钥的使用条件和上表一致（`unlockedDeviceRequired`、`userAuthType`、`authTimeout`、`noAuthRequired`），密钥是在硬件里生成的（`origin` 为 GENERATED）。`unlockedDeviceRequired` 在有的手机上由 Keystore 软件实现、记在 softwareEnforced 里，所以两组都认；其余几项只认 hardwareEnforced。
- 证明里的应用包名是 Nagi 的包名 `ink.sipc.nagi`（`auth.AppPackage`）。
- 证明里的公钥和提交的公钥一致。
- 链里叶子以外的证书都不在 Google 的吊销列表里（见[吊销列表](#吊销列表)）。开发模式下也检查。

任何一项不符合时拒绝添加，提示原因。证明里的 bootloader 状态（`verifiedBootState`）和系统安全补丁日期记在设备上：bootloader 没有锁定时照样允许添加（有人会在自己 root 过的手机上用），但在设备列表和添加通知里标明。

### 吊销列表

证明私钥（出厂写入的 keybox）泄露后，拿到它的人能给任意密钥签出有效的证明，冒充「密钥在硬件里」。Google 把泄露的证书列进吊销列表（`https://android.googleapis.com/attestation/status`，按证书序列号列出，约 180 KiB），面板按它检查：

- **查哪几张**：链里叶子以外的每一张。被吊销的是证明密钥的证书，有时是更上面的中间证书；叶子证书由证明密钥随意签发，不会列进去。Google 的列表里两种写法都有：128 位的序列号写成十六进制，64 位的（多数出厂写入的 keybox）写成十进制（例如 `14223735860583184979`，即 `c564dc67950bba53`），所以每个序列号按十六进制和十进制各查一次，忽略大小写和前导 0。列在里面的都算吊销（`REVOKED`、`SUSPENDED`）。
- **列表从哪来**：
  - 发布时 CI 取当时的列表放进面板（`scripts/attestation-status.sh`，在 `release.yml` 编译之前运行；取不到、面板读不了、不比仓库里的新时用仓库里的那份）。中国大陆的面板通常连不上 Google，靠这一份，随面板升级更新。
  - 主面板运行时每天从 Google 取一次（取不到时 6 小时后再试），取到的比当前的新（按 `Last-Modified`，晚于现在时按现在算）就换上，存进数据目录的 `attestation/status.json` 和 `status.updated`，重启后先读它；存下的日期晚于现在时（面板的时钟曾经快过）不用这份并删掉它，改用随面板发布的。取到了却解析不了时记警告（Google 可能改了格式）。备用面板不取。
- **添加时**：链里有被吊销的证书就拒绝添加，提示序列号和原因，和其他证明不通过一样记审计、发通知。通过后记下这些证书的序列号（`attestation_serials`），三把密钥的证明都追溯到 Google 的根证书时 `revocation_checked` 为 1（开发模式下自己的根证书不算）。检查之后、写入之前换了列表时，写入后叫复查的后台任务按新列表再复查一遍（不占添加手机的请求）。
- **添加以后**：每次换上新的列表（包括面板升级后启动时），把记了序列号的手机复查一遍。新查到被吊销的，记下原因（`revoked_reason`），在已登录的设备里标明「证明证书已被吊销」，记审计（`app_attestation_revoked`）并告警一次；不自动退出：整批 keybox 被吊销时同一批的真手机也在里面，由成员或管理员确认后退出。之后不再在列表里的清掉标明。复查失败时 6 小时后重试。
- 这个功能之前添加的手机没有记序列号，不能复查，仍标明「未检查吊销」，重新添加后才会检查。

## 添加手机

两种方式：在网页上扫码，或者在 App 里用密码登录。

### 扫码

1. 在网页的「设置 → 账号安全 → 手机 App」点「添加手机」，先做高权限确认。
2. 页面显示二维码（224×224），内容是 `nagi-app://pair?v=2&a=<对外地址:面板端口>&d=<面板域名>&k=<公钥指纹的前 128 位>&c=<配对码>`。没有绑定域名时没有 `d`。内容尽量短，二维码的格子少、每格大，离远一点也好定位：配对码 128 位（base64url，22 个字符），公钥指纹只放前 128 位（SPKI 的 SHA-256 的前 16 字节，base64url），`:` 不转义，约 100 个字符（以前约 170 个），格子从 49×49 减到 37×37 至 41×41（看地址和域名的长短）。App 用前 128 位校验面板证书，连上后记下完整的指纹，之后都按完整的校验；确认页显示的也是完整的。App 也认旧版面板的 `v=1`（`fp=<完整的公钥指纹>`）。
3. 在 App 里扫码。取景框跟着画面里的二维码移动、改变大小（几乎不回弹的弹簧；每次的位置和上一次加权平均，框不发抖），框外半透明遮罩，二维码离开画面 0.6 秒后回到中间：每一帧先用 ZXing 的定位器（`Detector`）只找三个定位图形，不解内容（离得远、有点糊时也常常能找到），找到就移框；再用定位的结果解内容。预览和分析绑在同一个取景范围（`ViewPort`）上，分析图像的裁剪范围就是预览看得到的部分；定位点按裁剪范围、旋转角度和铺满方式自己换算到屏幕（CameraX 的 `CoordinateTransform` 实测没算旋转，框会跑到屏幕外）。分析图像用 16:9、约 1280×720（默认 640×480 离远就糊），定位器打开 `TRY_HARDER`；预览只要求 16:9、分辨率不限；帧率固定，摄像头支持 60 就用 60，否则（或和分析图像一起绑定失败时）用 30，暗处不自动降帧。很多手机普通预览最高 30，60 只在高速录像模式里有。对焦：一打开就对画面中心对焦，没找到二维码时每 2 秒再对一次；找到后对二维码的中心对焦和测光，最多每 1.5 秒一次。两种黑白化（`HybridBinarizer`、`GlobalHistogramBinarizer`，后者对屏幕摩尔纹和反光更稳）：先用上一帧成功的那种，没找到或解不出内容时同一帧换另一种再试，不等下一帧。扫到的不是 Nagi 的二维码时框变红并提示。解出 Nagi 的二维码后，要已经连续跟踪了 0.15 秒才算成功（所以一定能看到框先跟上二维码），然后依次：框对准二维码、边框加粗表示锁定，同时轻振一下；停 80ms；从二维码展开到全屏（380ms，四边和圆角同一条曲线），展开到 35% 开始铺页面底色、和展开同时铺满；这时跳转，确认页的内容在同样的底色上淡入、上移 8，扫码页不淡出、一直垫在下面直到确认页完全显示（两页同时半透明会透出窗口背景）。返回键和提示在成功时淡出。一锁定就开始查配对信息，展开期间数据基本就到了；确认页的骨架换成内容时淡入。App 用二维码里的公钥指纹校验面板的证书，然后向面板查询配对码，显示「添加到 <面板名称>，成员 <显示名称>」和成员的头像（面板上传的，没有时是首字母）。
4. 在 App 里点「添加」。App 生成三把密钥，弹出系统验证框（用确认密钥签一次，确认是机主在操作），然后提交公钥和证明。
5. 网页显示「已添加 <手机名称>」。

规则：

- 配对码是 32 字节随机数，5 分钟内有效，只能用一次，绑定生成它的成员和网页会话；这个会话退出时配对码作废。每个成员同时只有一个有效的配对码，重新生成时旧的作废。
- 配对的接口（`AppService.GetPairing`、`Pair`）和备用面板配对一样，不受安全入口限制（只认 App 发的格式，见[换取令牌](#换取令牌)），对不认识的配对码返回 `not_found`。按 IP 限速，和登录共用计数。
- 二维码里没有面板名称：App 查询配对码时面板返回名称。面板名称取 settings 表的 `panel_name`，没有设置时是面板机器的主机名。管理员在网页「设置 → 面板访问」或 App「设置 → 面板」里改（`SettingsService.SetPanelName`，最多 64 个字符，留空恢复主机名，记审计）；改了以后各手机下次查到（`Info`）时顶部栏跟着变。
- 「添加手机」只能在网页上做，App 里不能再添加别的手机：手机被人拿走、锁屏密码也被看到时，不能借它给另一台手机留下登录。
- 配对链接（`nagi-app://pair?…`）接收带 `BROWSABLE` 的 VIEW：系统相机、Google Lens 这类扫码器打开链接时通常带它，不声明就打不开 App。网页里的链接因此也能拉起 App，靠下面几条把关：
  - 只在还没有添加面板、停在欢迎页时接收；扫码页、确认页打开期间来的链接不理，别的 App 不能悄悄换掉确认页。
  - 处理完清掉 intent 的链接；界面重建、从最近任务重新打开时不再处理最初的链接。有面板时不留着链接，退出手机后不会自动打开旧链接。
  - 确认页注明「名称、账号和头像由下方地址的面板提供」，不显示二维码里没有核对过的域名；从链接打开时另外提醒「此链接来自其他应用或网页，请确认来自你自己的面板」。

### 用密码登录

在 App 里点「用密码登录」，填面板地址、用户名、密码，开了两步验证的再填验证码。

- 用 IP 访问时，App 显示面板证书的公钥指纹，要和面板启动日志或网页「设置 → 面板访问」里的指纹一致才能继续。绑定了域名时用系统信任的证书校验，不用核对。
- 登录请求同时带上三把密钥的公钥和证明（`AppService.Login`），登录成功和登记密钥在同一个请求里完成，没有网页那样「登录后 2 分钟内登记会话密钥」的窗口。
- 限速、锁定、管理员登录地址、新网段登录告警和网页登录一样（见 [panel.md](panel.md#登录)）。
- 通行密钥登录以后再做：需要面板在绑定的域名下提供 `/.well-known/assetlinks.json`，自己编译 App 的人签名证书不同，要另外处理。

### 添加以后

- 面板记下设备：`app_devices (id, user_id, name, model, android_version, app_version, device_key, confirm_key, push_key, security_level, boot_locked, patch_level, revocation_checked, dev_keys, created_at, last_used_at, last_ip, last_unlock_at, sig_failures, attestation_serials, revoked_reason)`（迁移 `0025_app_devices.sql`、`0026_app_device_revocation.sql`，查询手写在 `store/app_devices.go`，和通行密钥、会话一样不放进 queries.sql）。设备 ID 是 16 字节随机数（base64url）。安全级别取三把密钥里最低的。删除成员时级联删除，备用面板复制数据库时一起带过去。
- 每个成员最多 10 台手机。
- 添加时已经用确认密钥验证过一次身份，面板把这次算作解锁（`last_unlock_at` 记为添加时间）；App 添加成功后直接进首页，不再显示解锁页、不再弹第二次验证框。
- 添加手机是一次性通知，不能关（和添加通行密钥一样，见 [audit.md](audit.md#安全告警)）：账号、手机名称、系统版本、是否锁定 bootloader、来源。

## 请求

### 换取令牌

1. App 调用 `AppService.Challenge`（带设备 ID），面板返回挑战。挑战和通行密钥登录的一样不占面板的存储：随机数、过期时间和设备 ID 用进程内存里的密钥做 HMAC，只能用一次，也只能由这台手机用。`Challenge` 发的 1 分钟内有效；`Token` 一起返回的下一次用的挑战 15 分钟内有效（App 每 4 分钟换一次，令牌 10 分钟过期）。设备 ID 不认识时返回 404。
2. App 用设备密钥签名 `nagi-app-token\n<连接的主机>\n<设备 ID>\n<挑战>`，调用 `AppService.Token`。
3. 面板核对签名，返回令牌 `nagi_app_<43 位 base64url>`、过期时间、下一次用的挑战和解锁时长。之后每次换取只要一次请求。请求里带上签名用的主机（`host`），面板只认自己的对外地址:端口和域名；开发模式下不检查主机（模拟器用 `10.0.2.2` 连面板）。

- 令牌 10 分钟过期，App 在前台时每 4 分钟换新的。令牌只在面板进程的内存里（存哈希），面板重启后 App 自动重新换取，不用操作。
- 签名的内容里有连接的主机：面板只认自己的地址和域名，别的服务器骗 App 签的挑战拿到这里用不了。
- 令牌绑定换取时的网段（IPv4 /24、IPv6 /48）。从别的网段使用时返回 `unauthenticated`，响应头 `Nagi-App-Retoken: network`，App 自动重新换取，用户看不到。这样 Wi-Fi 和移动数据之间切换不打扰用户，偷到令牌的人换个地方就用不了。
- 请求带 `Authorization: Bearer nagi_app_…`。Connect 接口、终端和日志的 WebSocket、上传、下载签名链接都接受 App 令牌，和网页会话一样检查角色、访问范围、备用面板只读。`/mcp` 不接受。
- 打开着的终端和日志流每 30 秒重查一次：手机还在（没有被退出，成员没有被删除、没有改密码），成员当前的角色和访问范围仍然允许，管理员还从允许的地址来，否则断开。日志流还按打开时的令牌重查：令牌过期或换了网段时结束，返回 `unauthenticated` 和 `Nagi-App-Retoken`，App 换取新令牌后重新打开，所以一条日志流最长用到令牌过期。终端不看令牌是否过期：重新打开会丢掉终端里的进程。终端另外要求手机还在解锁时长内、签名失败次数没到上限（和换取令牌的要求一致；每次换取令牌都把解锁时间往后延，App 退到后台、锁屏以后不再换取，超过解锁时长断开，提示「App 已超过解锁时长」），并且从打开起最长用到会话设置里的「最长登录时间」，和网页会话的绝对上限一致（`auth.UnlockedDeviceUser`）。
- 不带 cookie，所以不检查 `Sec-Fetch-Site` 和 `Origin`（见 [panel.md](panel.md#会话) 的请求来源）。
- 设置了[管理员登录地址](panel.md#管理员登录地址)时，管理员的手机只能从这些地址换取和使用令牌，否则拒绝、记审计（`admin_network_denied`）并告警。
- 签名不对时记审计（`app_signature_invalid`），连续 5 次后这台手机要先解锁 App（见下一节）才能继续换取。
- 令牌过期、换了网段、面板重启过时，接口返回 `unauthenticated` 和响应头 `Nagi-App-Retoken`（`expired`、`network`），App 重新换取后再试一次。需要解锁时 `Token` 返回 `failed_precondition` 和 `Nagi-App-Retoken: unlock`。
- 开了安全入口时，只放行 App 拿到令牌之前要调用的四个方法：`AppService.GetPairing`、`Pair`、`Challenge`、`Token`，而且只认 App 发的格式——`POST` 加 `Content-Type: application/proto`（Connect 协议的一元调用、protobuf 编码、请求不压缩，connect-kotlin 的默认做法）。别的请求方法、JSON 编码、`AppService` 的其他方法和不认识的路径，和别处一样返回 404。其他请求带着面板发过的 App 令牌（过期的也算）时放行，交给接口检查（`Info`、`Logout` 和其他接口）。
  - 残余：这四个方法对不认识的配对码、设备 ID 仍然返回 Connect 的 `not_found`（带中文提示），不是 HTTP 层的 404，所以知道 Nagi 接口格式的扫描者发一个格式正确的请求，仍能认出这是 Nagi 面板（进不了接口，这些接口按 IP 限速，和登录共用计数）。没有改成 HTTP 404 的原因：App 靠 `Challenge` 返回的 `not_found` 判断「这台手机已退出」（回到欢迎页），靠 `GetPairing`、`Pair` 的提示告诉用户二维码已失效；connect-kotlin 把 HTTP 404 当作 `unimplemented`，App 会一直重试、显示不出原因。以后 App 能把 HTTP 404 当作「已退出」时再改。

### 解锁 App

打开 App、或者 App 离开前台超过一段时间后回来，要验证指纹、面容或锁屏密码。时长默认 15 分钟，管理员可以在「设置 → 安全 → 会话」的「App 解锁」里改为 5 到 60 分钟（存在 settings 表的 `app_unlock_minutes`）。修改记审计。不提供「每次打开都验证」：面板只能看到两次换取令牌的间隔，看不出 App 有没有离开过前台，比换取间隔还短的时长没法强制。这一步由面板强制，不只是 App 的界面：

- 距离这台手机上次解锁（`last_unlock_at`）超过这个时长时，`AppService.Token` 只认确认密钥的签名，设备密钥的签名返回 `failed_precondition`。
- App 在前台时每 4 分钟用设备密钥换一次令牌，同时把解锁时间往后延，连续使用时不会反复要求验证。App 在后台不换取令牌，推送用的是另一把密钥。回到前台时接着上一次换取算，已经过了 4 分钟就马上换：频繁在 App 之间切换、每次停留不到 4 分钟时，解锁时间也照常往后延。
- 用确认密钥换取成功时记审计（`app_unlocked`）；需要解锁时记 `app_unlock_required`。
- App 一侧：冷启动时总是先显示解锁页；离开前台超过解锁时长后回来时也显示。解锁页进入时自动弹出系统验证框。
- 最近任务里不显示 App 的截图，免得锁着时也能看到上次离开时的首页：Android 13 起 `setRecentsScreenshotEnabled(false)`；更早的版本（Android 9 到 12）`setDisablePreviewScreenshots(true)`，缩略图按主题画成空白窗口；这个方法不在 SDK 里，按名字调用。两种都在 `onCreate` 里设：手势导航进最近任务时缩略图在 `onPause` 之前就截好了，离开前台时再加 `FLAG_SECURE` 来不及。平时照常能截屏、录屏。个别系统上调不到这个方法时，退回离开前台时加 `FLAG_SECURE`、回来再去掉的做法：手势导航时挡不住，App 暂停但还看得见时（分屏、被系统验证框盖住）录屏和投屏里是黑的。`MainActivity` 设 `taskAffinity=""`，别的 App 不能把自己的界面放进 Nagi 的任务里。
- 解锁时长在「设置 → 安全 → 会话」里的设置项还没有做，现在只能直接改 settings 表的 `app_unlock_minutes`（5–60，超出时按 15）。
- 确认密钥每次使用都要用户验证，由硬件保证，App 被篡改也绕不过去。

### 高权限确认和重新验证

- App 里需要高权限确认的操作（见 [node-access.md](node-access.md#权限)），用确认密钥签名面板给的挑战完成（`AppService.Elevate`）：面板拒绝并说明要先验证身份时，App 弹出系统验证框，通过后自动再做一次刚才的操作。挑战用 `AppService.Challenge` 取，签的是 `nagi-app-elevate\n<连接的主机>\n<设备 ID>\n<挑战>`。记在这台手机上（面板内存里），有效期和网页一样是 15 分钟，只对做确认时的 IP 有效，手机退出后作废；记审计（`app_elevated`）。`Info` 返回 `elevated_until`。
- 给自己留下登录凭据的操作仍然要密码或验证码，不接受确认密钥：生成访问令牌、OAuth 授权、添加通行密钥、开启两步验证、添加手机、生成备用面板的配对码、移交节点、提升备用面板、新建成员、修改成员（`auth.passwordElevation`，OAuth 授权在自己的处理函数里检查）。原因和不能在 App 里添加手机一样。App 里碰到这类操作时提示到网页上做。
- 面板要求重新验证时（见 [panel.md](panel.md#会话) 的处置），App 弹出系统验证框，用确认密钥完成。

### 手机确认

网页上要验证身份的两处可以改在手机上确认：**高权限确认**（代替密码或验证码），和**登录的第二步**（开了两步验证的账号，代替验证码）。手机上用确认密钥签名，每次都要验证指纹、面容或锁屏密码。给自己留登录凭据的操作（见上）不认手机的确认，对话框里也不给这个选项。

1. 网页点「在手机上确认」，面板登记一个请求，返回请求 ID 和**两位数字**，网页把数字显示出来。
   - 高权限确认：`AuthService.BeginPhoneApproval`，记在发起的会话上。
   - 登录：`AuthService.BeginLoginApproval`（用户名、密码）。和登录一样核对密码（同样限速、计失败），账号要开了两步验证、添加过手机；另外返回一个只给发起的浏览器的凭据（ticket）。
2. App 在前台时每 3 秒查一次等确认的请求（`AppService.ListApprovals`，只有本人账号的），有就弹出对话框：是登录还是验证身份、发起的 IP 和浏览器，提示「不是你本人发起的，请点拒绝」。
3. 成员照着网页输入两位数字，点「确认」，过系统验证框。App 用确认密钥签 `nagi-app-approve\n<连接的主机>\n<设备 ID>\n<请求 ID>\n<种类>\n<数字>`，调用 `AppService.Approve`。面板核对数字、主机和签名。
4. 网页每 1.5 秒查一次结果：
   - 高权限确认：`AuthService.GetPhoneApproval`。确认后这个会话记为做过高权限确认（`elevated_by` 为 `app`），15 分钟内有效。
   - 登录：`AuthService.CompleteLoginApproval`（凭 ticket）。确认后返回会话 cookie，和验证码登录一样检查管理员登录地址、新网段告警，审计的 `Login` 里写明第二步是手机和哪台手机。

规则：

- **两位数字**是为了防止随手点了别人发起的请求：知道密码的人可以反复发起登录请求等成员误点，要输数字就必须看得到发起人的屏幕。数字签在确认里；输错 3 次这个请求作废。
- 请求只在面板进程的内存里，2 分钟内有效；手机确认后网页要在 1 分钟内取结果，结果只给一次。同一个成员、同一种、同一个来源（IP）的请求同时只有一个，新的让旧的作废；别的来源发起的留着，同时有几个时手机上先列出来（种类、来源、发起时间），由成员选自己发起的那个再确认，可以「全部拒绝」；不直接弹最早的，免得成员把自己屏幕上的数字输进别人的请求。每个成员每种请求同时最多 4 个别的来源的（只算还在等确认、或确认了还没取走的，拒绝掉和输错作废的不算；登录和高权限确认分开算），满了就拒绝新的（不丢已有的：成员正在等的、手机上已经确认还没取走的不会被别处的顶掉）。10 分钟内最多发起 10 个，按成员、种类、来源分开算，被限额拒绝时不动已有的请求。
- 只认发起的那个会话（高权限确认）或浏览器手里的凭据（登录），IP 要和发起时一样。
- 签名里有用途和种类：换取令牌、高权限确认、登录确认的签名不能互相冒用。别的成员的手机看不到、也确认不了。
- 在手机上点「拒绝」不用验证。拒绝登录请求时发告警（有人知道这个账号的密码），记审计（`app_approval_denied`）；确认记 `app_approved`，网页的高权限确认记 `elevated_by_phone`。
- 手机丢了、没带时照常用验证码、通行密钥登录，用密码或验证码做高权限确认。
- 手机在后台时收不到：现在要先打开 App。等推送的长连接做了再发通知（见[告警推送](#告警推送)）。
- 接口登记（`auth/perms.go`）：`BeginLoginApproval`、`CompleteLoginApproval` 不用登录；`BeginPhoneApproval`、`GetPhoneApproval`、`AppService.ListApprovals`、`Approve`、`Elevate` 所有成员都能用，只涉及自己的账号。实现在 `auth/approval.go`，测试在 `auth/approval_test.go`。

## 管理和撤销

- 「设置 → 账号安全 → 已登录的设备」里列出手机（`ListSessions` 里 `kind` 是 `app`，ID 是 `app-<设备 ID>`，`RevokeSession` 用它退出手机）：名称（默认是手机型号，可以改）、App 版本、Android 版本、安全级别、最近的 IP 和活动时间，bootloader 没有锁定、证明证书已被吊销、没检查吊销的标明。点「退出」后删除设备记录，内存里的令牌立即作废，推送连接立即断开。
- 管理员在「设置 → 成员」的成员菜单里也能看到、退出这个成员的手机（还没有做）。
- 改自己的密码时，其他手机和其他网页登录一起退出。管理员重置成员的密码、删除成员、在面板机器上执行 `nagi reset password` 时，这个成员的手机全部退出。
- 30 天没有换取过令牌的手机自动退出，可以在「设置 → 安全 → 会话」改短。没有从添加起算的最长期限：每次换取都要硬件密钥，长期不退出不会增加被盗用的风险。
- 卸载 App 或清除数据后密钥随之删除，设备记录留到 30 天后自动退出，也可以手动退出。

## 审计

- App 的操作照常记审计，来源 `via` 是 `app`，`client` 是手机名称，审计页显示「App（手机名称）」。`session` 字段是 `app:<设备 ID>` 的哈希前 12 位，同一台手机的操作串在一起。配对、换取令牌、退出不按接口记，按下面的安全事件记。
- 安全事件记为 `security` 类：`app_paired`、`app_removed`、`app_attestation_failed`、`app_attestation_revoked`、`app_signature_invalid`、`app_unlock_required`、`app_approved`、`app_approval_denied`；手机确认和高权限确认另记 `elevated_by_phone`、`app_elevated`（登录类）。添加手机、证明不通过和证明证书被吊销发通知，其余只记审计。

## 告警推送

App 在后台和面板保持一条长连接，面板有告警时立即推给手机，不经过 Google 或其他第三方服务。

### 连接

- App 用前台服务保持连接（Android 14 起类型是 `specialUse`），通知栏常驻一条「正在接收告警」，可以在系统设置里把这条通知隐藏。
- 连接是 Connect 的服务端流 `AppService.WatchAlerts`。打开时用推送密钥签名挑战（`nagi-app-push\n<连接的主机>\n<设备 ID>\n<挑战>`），之后这条流不需要令牌。流最长 24 小时，到时 App 重新连接。
- 面板每 60 秒在流上发一次心跳，App 150 秒收不到任何消息就断开重连。重连间隔从 5 秒开始翻倍，最长 5 分钟；网络恢复时立即重连。
- 连不上面板超过 5 分钟时，App 自己发一条本地通知「连不上面板 <面板名称>」，恢复时发「已恢复」。有备用面板时附上备用面板的地址。
- 国内的手机系统会限制后台应用。App 第一次打开推送时引导用户关闭这个应用的电池优化、允许自启动和后台运行，并说明不开的后果：手机休眠后可能收不到告警。

### 内容

- **来源**：节点发出告警时已经通过 `ReportAlert` 告诉面板（见 [monitoring.md](monitoring.md#告警)），面板自己发的告警（节点失联、安全告警、一次性通知）也经过 `Service.Alert`。面板在这两处把告警转给在线的推送连接。
- **按权限过滤**：项目和容器的告警只推给能访问这个项目的成员，节点的告警只推给能看到这个节点的成员（见[访问范围](panel.md#访问范围)）；安全告警和一次性通知只推给管理员，和本人账号有关的（例如自己的账号从新网段登录）推给本人。
- **漏掉的告警**：面板在内存里保留最近 24 小时、最多 1000 条告警，每条有递增的序号。App 重连时带上收到的最后一个序号，面板补发之后的。面板重启过时序号对不上，App 提示「面板重启过，期间的告警可能没有收到」，并打开活动记录。
- **手机上的设置**：每台手机可以按类别（节点、容器、安全）和按项目关闭推送，设置存在面板的设备记录上（`app_devices.push_settings`），面板按它过滤，关掉的不发到手机。告警恢复的消息默认推送，可以关闭。
- **摘要**：需要处理的数量、节点在线数、容器运行数变化时，面板在流上发一条摘要，给小组件和面板列表用；连接时先发一条。
- **局限**：面板不可用时，节点直接发到告警渠道的告警 App 收不到；备用面板不发告警，也不推送。所以重要的集群仍然要配置 webhook 或 Telegram 渠道，App 推送是补充。

## 面板地址和备用面板

- 绑定了域名时，App 优先用域名连接，按系统信任的证书校验；连不上时改用对外地址，按公钥指纹校验。只有对外地址时一直按公钥指纹校验，和节点一样（见 [control-plane.md](control-plane.md#连接)）。
- 面板换了域名或对外地址时，已连接的 App 从 `AppService.Info` 拿到新地址并保存。
- **长连接**：推送、终端和日志的 WebSocket 都是长连接。CDN 会断开长时间不结束的请求（Cloudflare 约 100 秒），还可能缓冲流式响应，所以面板记下域名是否经过 CDN：经域名来的请求带着 CDN 的请求头（`Cf-Ray`、`Cdn-Loop` 等，面板本来就会识别，见 [panel.md](panel.md#会话)）时记为经过 CDN，`Info` 里返回。经过 CDN 时，App 的长连接改走对外地址，按公钥指纹校验；对外地址从手机连不上时退回域名，连接断开后按退避重连，并在推送设置里提示「面板域名经过 CDN，推送可能不稳定」。普通请求照常走域名。
- App 记下面板告诉它的备用面板的名称、地址和公钥指纹。主面板连不上时，App 提示可以切换到备用面板，切换后只能查看，和网页一样（见 [standby.md](standby.md)）。设备记录已经复制到备用面板，在备用面板上照常换取令牌，但不更新最近活动时间（备用面板不写数据库）。提升备用面板后照常使用。

## 接口

App 和网页用同一套接口、同一套权限检查，不为 App 另写业务接口。现有的 `AuthService`、`ProjectService`、`NodeService`、`SettingsService` 全部可以用 App 令牌调用，终端、日志的 WebSocket、上传和下载签名链接也接受 App 令牌（见[换取令牌](#换取令牌)）。新增的只有 App 会话和推送（新服务 `AppService`）以及现有服务里的几处改动；页面的数据和网页查同样的接口（见[数据刷新](#数据刷新)），不为 App 另加查询或订阅接口。

### AppService

| 方法 | 凭据 | 作用 |
| --- | --- | --- |
| `GetPairing(code)` | 配对码 | 返回面板名称、成员的显示名称、面板版本，App 据此显示「添加到 <面板名称>，成员 <显示名称>」 |
| `Pair(code, keys, device)` | 配对码 | 提交三把密钥的公钥和证明、手机信息（型号、Android 版本、App 版本），返回设备 ID |
| `Login(username, password, code, keys, device)` | 密码 | 用密码登录并登记密钥，开了两步验证时没带验证码返回 `failed_precondition`，和网页一样 |
| `Challenge(device_id)` | 设备 ID | 返回挑战。设备 ID 不认识时 404 |
| `Token(device_id, challenge, key, signature)` | 设备密钥或确认密钥的签名 | 返回令牌、过期时间和下一次用的挑战。`key` 写用的是哪把密钥；需要解锁 App 时设备密钥的签名返回 `failed_precondition` |
| `Elevate(challenge, signature)` | 令牌加确认密钥的签名 | 高权限确认，返回有效期 |
| `Reverify(challenge, signature)` | 令牌加确认密钥的签名 | 面板要求重新验证时用 |
| `Info()` | 令牌 | 面板名称、版本、支持的功能列表、对外地址和域名、域名是否经过 CDN、备用面板（名称、地址、公钥指纹）、各节点直连下载用的证书指纹、最新的 App 版本和下载地址、解锁时长、这台手机的设置 |
| `UpdateDevice(name, push_settings)` | 令牌 | 改本机在面板上的名称和推送设置 |
| `Logout()` | 令牌 | 退出：删除这台手机的设备记录 |
| `WatchAlerts(device_id, challenge, signature, after_seq)` | 推送密钥的签名 | 服务端流，见下面 |

挑战（`Challenge`、`Token` 和推送里的）、`Elevate`、`Reverify` 的挑战都由面板给出，签名的内容开头写用途（`nagi-app-token`、`nagi-app-elevate`、`nagi-app-reverify`、`nagi-app-push`），一种用途的签名不能拿去做另一种。

`WatchAlerts` 的消息是下面几种之一：

- **告警**：序号、面板收到的告警（见下面的「告警」改动）、是否严重。
- **摘要**：需要处理的数量、节点在线数和总数、容器运行数和总数。
- **心跳**：每 60 秒一次。
- **缺口**：`after_seq` 早于面板保留的最早一条，或者面板重启过，App 据此提示可能漏了告警。

`GetPairing`、`Pair`、`Login`、`Challenge`、`Token`、`WatchAlerts` 不需要令牌，不受安全入口限制（和备用面板配对一样，不认识的配对码、设备 ID 返回 404），按 IP 限速并和登录共用计数。

### 数据刷新

App 不另加查询或订阅接口，页面的数据和网页查同样的接口、按同样的算法在手机上算，刷新间隔也和网页一样。

- **首页**：和网页的全局概览一样（`core/data` 的 `HomeData.kt`，算法同 `web/src/pages/overview.tsx`），每 10 秒查一次：
  - `NodeService.ListNodes`、`ProjectService.ListProjects`：关键数字和需要处理（见[首页](#首页)）。
  - 每个在线节点最近 1 分钟的监控（`NodeService.QueryNodeMetrics`，前缀 `node:net_`、`m:`，各节点、各类同时问，单个节点最多等 5 秒，问不到的不算）：对外入站和出站（网卡减去节点网络，不小于 0）、实时流量的路径。
  - 流量最大的端口映射：每个在线节点最近 24 小时、按 10 分钟聚合的 `r:` 监控（速率乘时长再相加），各节点合计，每分钟查一次，单个节点最多等 15 秒。
  - 节点网络的公钥对应（`NodeService.GetNodeMesh`、`GetPanelMesh`，每分钟查一次）：节点之间的流量对应到节点，哪些路径经面板中转。没有权限查时只算对外的。
  - 流量趋势：打开首页和切换时间范围时查一次，同样按节点查带步长的 `QueryNodeMetrics` 再合计；最后一个时刻只有部分节点上报时不画。
  - 权限（决定行尾的按钮：「批准」要「节点管理」，「更新」要「部署」）用 `AppService.Info` 查，1 分钟查一次。没有「查看节点」「查看」权限时不查节点、项目，当作空的。
- **只在前台查**：页面离开 5 秒后、App 退到后台时停，回来时马上查一次。
- **出错**：查不到时退避重试（1、2、5、10 秒，之后每 30 秒）；有数据时先静默重试，连续 5 秒以上查不到才显示「连不上面板」。令牌在请求时过期或换了网段，按现有的规则换取新令牌后重试。
- **权限**：查的都是网页的接口，权限、访问范围、备用面板只读照常检查，每次都按成员当前的设置。回复按权限清理（见 [panel.md](panel.md#访问范围)）：看不到的节点 ID 为空，显示「其他节点」，不显示是否在线；节点、面板的 IP 只给管理员。
  - 「流量最大的映射」：没有「查看访问地址」时不显示 `IP:端口`，有域名显示域名，没有域名显示「节点名:端口」；节点看不到时显示「其他节点:端口」，不退回显示面板地址。到看不到的节点的流量（`m:other`）只从对外流量里扣，不画进桑基图。
  - 非管理员的设置页不显示面板地址；面板绑了域名时 `Info.public_address` 为空，只用 `domain`。
- 以后的页面（项目、容器、节点）也一样：查网页同样的接口，按网页的刷新间隔。告警由推送的长连接送来（见[告警推送](#告警推送)），「需要处理」里的未恢复告警等推送做了再加。

### 现有接口的改动

- **生成配对码**：`AuthService.CreateAppPairing()` 返回配对码、二维码内容和过期时间，登记在 `elevationRequired`；`GetAppPairing(code)` 返回是否已经用掉、用它添加的手机名称，网页每 2 秒查询一次，直到添加完成或过期。
- **已登录的设备**：`ListSessions` 的 `LoginSession` 加 `kind`（`web`、`app`）和手机的字段（型号、Android 版本、App 版本、安全级别、bootloader 是否锁定、是否检查过吊销）；`RevokeSession` 可以退出手机。管理员查看成员的设备同样。
- **会话策略**：`SessionPolicy` 加 App 解锁时长（5–60 分钟）和手机空闲多久自动退出（默认 30 天）。
- **高权限确认的方式**：会话记下这次确认用的是密码或验证码，还是确认密钥（`sessions.elevated_by`）。`CreateAccessToken`、`BeginPasskeyRegistration`、`BeginTOTP`、`CreateAppPairing` 只认密码或验证码的确认，在 `elevationRequired` 旁边另登记一张表，`auth.User.ElevatedFor` 一并判断，测试逐个检查这张表。
- **身份**：`auth.User` 加 `DeviceID`，`Via` 是 `app`；审计的 `session` 字段用设备 ID 的哈希。
- **告警**：`Alert` 加 `container`（容器 ID，节点知道是哪个容器），通知和深链接能直接打开容器页。是否严重由面板按告警的 `key` 判断，一张表写清哪些算严重。
- **未恢复的告警**：面板要知道当前有哪些告警还没恢复，推送的摘要要用它（「需要处理」里的告警等推送做了再加）。现在面板按收到的 `ReportAlert`（触发、恢复）在内存里记着（`nodes.Registry.ActiveAlerts`），面板重启后要等节点再发一次才知道。告警来自节点，被攻破的节点可以每次换一个 key：只记 key（截到 200 字）和标题（截到 120 字，和活动记录一样），不记正文；每个节点最多 200 条，满了以后新的 key 不再记，已经记着的照常更新和恢复；节点被移除、撤销时清掉它的告警。以后节点在 `Report` 里带上本节点当前未恢复的告警（只有 key 和开始时间），面板重启、节点重连后都能对上，不依赖 `ReportAlert` 有没有送到。

### 版本兼容

- proto 只加字段、加方法，不改已有字段的含义。
- App 不靠比较版本号判断面板能做什么，而是看 `Info` 返回的功能列表（例如 `app-push`、`node-images`）。面板没有的功能不显示入口。
  - 例外：添加和修改成员、添加备用面板、提升为主面板从 v0.35.0 起只能在网页上做，功能列表里没有对应的项，App 按版本号判断（见[本机设置](#本机设置)里「手机上不做的」）。以后这类变化在功能列表里加一项。
- 面板比 App 新时照常能用，「需要处理」里提示更新 App；App 用到面板没有的方法时（面板太旧），显示「面板版本较旧，不支持这项功能」。
- 例外：v0.34.0 之后删掉了只给 App 用的 `WatchOverview`、`GetAttention`、`QueryTraffic`，首页改用网页同一套接口。面板升级后 v0.34.0 的 App 首页打不开，要同时更新 App；这一版的更新日志在「升级说明」里写明。以后不再删已发布的方法。

## 工程

- **目录**：`android/`，Gradle（Kotlin DSL）多模块：

  | 模块 | 内容 |
  | --- | --- |
  | `app` | 入口、导航、深链接、依赖组装 |
  | `core:proto` | 由 proto 生成的代码（protobuf-javalite 和 connect-kotlin），和 `web/src/gen` 一样提交进仓库 |
  | `core:network` | OkHttp、证书指纹校验、令牌管理、WebSocket |
  | `core:security` | Keystore 密钥、生物识别验证框、缓存加密 |
  | `core:data` | 各类数据的仓库、内存状态、加密缓存 |
  | `core:ui` | 主题（颜色、字体、间距）、通用组件、图表、编辑器和终端的封装 |
  | `feature:home`、`feature:projects`、`feature:nodes`、`feature:settings`、`feature:pairing` | 各部分的页面和 ViewModel（首版只有 `feature:home` 和 `feature:pairing`，其余三个标签是 `app` 里的占位页） |
  | `push` | 前台服务、推送连接、通知、小组件 |

- **生成代码**：`buf.gen.yaml` 加 Java（lite，`protoc_builtin: java`）和 connect-kotlin 两个插件，输出到 `android/core/proto/src/main/{java,kotlin}`。需要 `protoc`（36.x，和 protobuf-javalite 4.36 对应）和 `protoc-gen-connect-kotlin`（0.10，和 connect-kotlin 运行库版本一致）在 PATH 里。proto 文件都加了 `java_multiple_files` 和 `java_package = ink.sipc.nagi.proto.v1`。改了 proto 以后和 Go、网页的代码一起重新生成。
- **版本**：AGP 8.13、Kotlin 2.4（connect-kotlin 0.10 用 Kotlin 2.4 编译，要求 2.3 以上）、Compose BOM 2026.03（Compose 1.10；更新的 BOM 要求 AGP 9.1 和 compileSdk 37）、compileSdk 和 targetSdk 36、Gradle 8.14。字体是 MiSans 的子集（`core/ui/fonts/subset.py`：拉丁、标点和 GB2312 汉字，每种字重约 1.4 MB），缺的字由系统字体补上。
- **主要依赖**：Jetpack Compose、Navigation Compose、Material 3 的自适应布局（只用窗口尺寸和导航栏，不用它的视觉风格）、OkHttp、connect-kotlin、protobuf-javalite、Vico、Termux 的终端库、Sora Editor、Jetpack Glance、AndroidX Biometric。依赖注入手写，不用 Hilt。
- **系统版本**：`minSdk` 28，`targetSdk` 跟随当年 Google 要求的版本。
- **测试**：
  - 面板：证明链的校验用真机生成的证明做测试数据（模拟器的证明是软件级别的，正好用来测拒绝的情况）；令牌、解锁、高权限确认方式、推送过滤的权限按现有的 `auth` 测试的写法。
  - **开发模式**：`nagi server --dev-app-keys` 启动的面板接受软件密钥和模拟器的证明，开发和自动化测试可以用模拟器。只能用启动参数开，界面、接口、MCP 都改不了；开着时面板启动日志每次打印警告，设备列表里这些手机标明「开发模式」，添加时记审计。正式发布的安装方式不带这个参数。
  - App：令牌管理、重连、缓存加密写单元测试；主要页面用 Compose 的界面测试在模拟器上跑。每个阶段完成后在真机上实际操作一遍，脚本测试只是补充。
- **崩溃日志**：只存在本机，不上报任何地方（自托管、不依赖外部服务）。最多保留最近 10 次，去掉地址、令牌、设备 ID 和集群数据；「设置 → 关于」里可以查看和分享。实现在 `core/data` 的 `CrashLog`：只记异常和调用栈。调用栈的每一帧不动；其余的行里，任意协议的网址、IPv4 和 IPv6（含压缩写法和网卡后缀）、域名（包名除外）、`nagi_app_` 令牌和 20 个字符以上的随机串替换掉，面板返回的错误（`ink.sipc.nagi.network` 下的异常）只留类型、不留说明。脱敏是尽力而为，界面上提示分享前检查。
- **构建和发布**：推送 `v*` 标签时 `release.yml` 编译 release 包（R8 裁剪和混淆、资源裁剪），用仓库 Secrets 里的签名密钥签名，以 `nagi-android.apk` 和面板的二进制一起上传到 Release，详见 [development.md](development.md#发布)。签名密钥只放在 CI 的 Secrets 和维护者自己的备份里。

## 进度

首版（`android-v1` 分支）：

- **面板**：`AppService` 的 `GetPairing`、`Pair`、`Challenge`、`Token`、`Info`、`Logout`；密钥证明的校验（`auth/attestation`）；App 令牌、网段绑定、解锁规则、开发模式；`AuthService.CreateAppPairing`、`GetAppPairing`；已登录的设备里的手机。测试在 `auth/app_test.go`、`api/app_test.go`。
- **网页**：「设置 → 账号安全 → 手机 App」和「添加手机」对话框；已登录的设备里的手机；审计来源「App」。
- **App**：欢迎、扫码（CameraX 和 ZXing）、确认添加、系统验证、解锁 App；首页概览（需要处理、关键数字、实时流量桑基图、流量趋势、流量最大的映射）、加载、出错和连不上面板的状态；胶囊导航（项目、节点是占位页）；设置（账号、本机一组、面板设置的入口）；崩溃日志；点顶部栏的面板名称可以退出这台手机。

和上面的设计不同、还没有做的：

- 只连对外地址（按公钥指纹校验），绑定了域名时还不优先用域名。
- 没有加密的状态缓存：连不上面板时显示的是这次打开 App 以来最后收到的数据。
- 没有用密码登录、多个面板、推送、终端、文件、搜索、引导、宽屏、下拉刷新。
- 流量趋势用 Canvas 画，按住看数值还没有做；以后换成 Vico。
- 「需要处理」里的「更新」只打开一个占位的容器页。
- 吊销列表、成员页里管理员退出别人的手机、解锁时长的设置界面。
