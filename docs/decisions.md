# 技术决策

各模块文档中的关键决策汇总在这里，方便查阅理由。新增决策时同时更新对应模块的文档。

## 架构

| 问题 | 决定 | 理由 | 详见 |
| --- | --- | --- | --- |
| 数据归属 | **配置在面板，数据在节点；节点缓存自己那部分容器的配置** | 项目跨节点，只有面板看得到整个项目；面板挂了容器照常运行和顶替，面板丢了能从节点缓存拼回来 | [panel.md](panel.md#项目数据) |
| 多面板 | **一个节点同一时间只归一个面板，只保留移交** | 配置以面板为准，两个面板同时管理就有两份配置 | [control-plane.md](control-plane.md#信任的面板列表) |
| 项目标识 | **全局唯一的项目 ID，项目名只用于显示；每个项目一个面板内唯一的网络名** | 项目名可以重名、可以改；连接的项目用"容器.网络名"访问，不会撞 | [agent.md](agent.md#标识与名字) |
| 项目结构 | **项目 = 一组容器，项目不属于哪台机器；每个容器（单个容器或容器组）指定一个节点，各自部署、记版本、回滚、快照、迁移、顶替** | 前端、后端、数据库一起管理，又能按需要放在不同机器上；一台机器坏了只影响它上面的容器 | [agent.md](agent.md#项目与容器) |
| 项目内网 | **一直开着，不论容器在哪个节点都用"容器名"或"容器.容器组"互相访问；没有开关** | 开箱即用，又不会因为两份 compose 都有 db 而冲突；要隔离就拆成两个项目 | [agent.md](agent.md#项目内网) |
| 接入内网 | **容器组由节点用 `network connect --alias` 接入，不写进 override** | compose 会把服务原名注册到它加入的每个网络上，写进 override 就会撞名 | [agent.md](agent.md#网络) |
| 项目之间 | **默认隔离，两个项目之间单独连接，用"容器.网络名"访问；不传递** | 取代节点上的共享网络；A 连 B、B 连 C 时 A 看不到 C | [agent.md](agent.md#项目连接) |
| 节点坏了且没有副本 | **把容器重新部署到其他节点，还是原来那个容器；原节点回来时停掉它的容器、目录改名保留** | 配置在面板上，换个节点部署就行；面板是准的，不会两份同时跑 | [failover.md](failover.md#节点坏了且没有副本重新部署到其他节点) |
| 跨节点容器通信 | **别的节点上的容器在本节点的项目内网里有一个同名的代理容器，经 mesh 转发，只转发 TCP；代理名单由面板下发** | 不建网卡、不改路由和 iptables，网段重叠无所谓，名字照常靠 Docker DNS；代理连接时才确定对方在哪个节点，顶替后自动跟随 | [agent.md](agent.md#项目内网) |
| 导入 compose | **整份作为一个容器组：组里的容器单独看状态、日志、终端、监控，一起部署和回滚** | 拆开要处理 depends_on、共用 volume、共用 .env 等，容易出错；自己的系统可以一个个容器地加 | [agent.md](agent.md#创建方式) |
| 叫法 | **项目 → 容器 / 容器组；代码里叫 `Container`（`kind`: single、group），Docker 实际运行的容器叫 `docker.Instance`** | 和 Zeabur 一样只看到"项目 → 容器"两层，compose 整份放进来也不用拆；代码和界面用同一个词 | [agent.md](agent.md#项目与容器) |
| 一起部署 | **可以一次部署多个容器，按容器设置的"先部署的容器"排序；每次部署在项目上记一条部署记录，可以整个项目回到某次部署时的状态** | 前后端一起改的东西要一起上线、一起回滚 | [agent.md](agent.md#版本与回滚) |
| 变量 | **项目共享变量 + 容器组变量 + 容器的环境变量，同名以更具体的为准；共享变量也走草稿，容器版本记下当时用的值** | 数据库密码之类的不用在多个容器里各填一遍；自动部署不会悄悄带上没部署的改动，回滚能回到当时的值 | [agent.md](agent.md#环境变量) |
| 修订号 | **按容器，项目设置另有一个，在面板上检查** | 两个窗口同时改不同的容器不会误报冲突；节点缓存也按修订号取新的 | [agent.md](agent.md#修改与部署) |
| 修改与部署 | **先存草稿，点部署才生效并生成版本** | 可以改好几处再一起上线，不会反复重启 | [agent.md](agent.md#修改与部署) |
| 删除项目 | **删除所有容器，容器目录默认保留** | 没说要动的就不动；删目录需输入项目名确认 | [agent.md](agent.md#删除) |
| 容器目录 | **节点设项目根目录（默认 `/srv/nagi`），容器目录默认 `<根目录>/<项目名拼音>/<容器名>`，可以改** | 容器多了以后每个都手填太麻烦；按网络名分开，一眼看出属于哪个项目 | [agent.md](agent.md#容器目录) |
| 格式版本号 | **容器目录和副本都带格式版本号，看不懂就拒绝** | 容器会在不同版本的节点之间搬，以后改目录结构不会被旧节点用错 | [agent.md](agent.md#容器目录) |

## 项目与部署

| 问题 | 决定 | 理由 | 详见 |
| --- | --- | --- | --- |
| 创建方式 | **写 compose，或填镜像表单（文件可选）** | 只有两种入口，底层都是 compose | [agent.md](agent.md#创建方式) |
| 镜像更新 | **每天检查并提醒，手动更新；版本记录镜像摘要** | 不会半夜自动升级导致业务挂掉；回滚能回到当时那份镜像 | [agent.md](agent.md#镜像) |
| 镜像加速 | **按节点配置，用户配置后才写入 Docker 配置** | 国内外节点需求不同；不擅自改 Docker | [agent.md](agent.md#镜像) |
| host 网络 | **允许，界面醒目提示** | 部分应用只能用 host 网络 | [agent.md](agent.md#部署方式) |
| 对外访问 | **全部经 Caddy（含 layer4），容器不映射端口** | 出口统一，不会绕过 ufw；以后切换流量只改 Caddy | [exposure.md](exposure.md) |
| 端口映射 | **属于容器，存在面板上，开在容器所在的节点上，只在面板修改，立即生效；部署时只导入 compose 新增的端口** | 有些镜像要手动加映射；映射不动容器，不必重新部署；用户改过或删掉的不会被覆盖 | [exposure.md](exposure.md#端口映射) |

## 通信与网络

| 问题 | 决定 | 理由 | 详见 |
| --- | --- | --- | --- |
| 控制面协议 | **gRPC**（跑在 mTLS 上） | 双向流和多路复用是现成的；proto 自带版本演进，新功能不容易弄坏旧 agent | [control-plane.md](control-plane.md) |
| 面板调用 agent | **反向 gRPC，底层 yamux 复用一条 TLS 连接** | 每个操作都是独立的强类型接口，日志、终端是普通流式接口，加功能只需加方法 | [control-plane.md](control-plane.md#接口设计) |
| 浏览器接口 | **Connect-RPC，终端用 WebSocket** | 和节点共用 proto，自动生成 TypeScript 类型；支持普通 JSON，可用 curl 调用 | [control-plane.md](control-plane.md#接口设计) |
| 版本兼容 | **面板兼容旧一个大版本的节点，可一键升级节点** | 升级时不用所有机器同时停；proto 只加字段不改删 | [control-plane.md](control-plane.md#接口设计) |
| WireGuard 实现 | **全部用用户态 wireguard-go，自己实现直连 / UDP 中转 / TLS 中转** | 一套代码路径；内核版做不到套 TLS 中转 | [mesh.md](mesh.md#实现全部使用用户态-wireguard-go) |
| mesh 地址 | **由 WireGuard 公钥推导的 IPv6** | 不用分配，mesh 合并不冲突，无法冒用他人地址 | [mesh.md](mesh.md#地址) |
| 容器网段 | **节点本地分配，默认 `10.200.0.0/16`，项目内网 /24、容器组 /26** | 不需要全局协调；项目内网里还要放代理，留大一点 | [mesh.md](mesh.md#容器网段只在节点内分配) |
| 租约投票通道 | **全部走 WireGuard mesh，面板加入 mesh** | 投票只有一套代码；面板在 mesh 里也负责上传容器文件、中转 mesh 流量 | [mesh.md](mesh.md) |

## 高可用与备份

| 问题 | 决定 | 理由 | 详见 |
| --- | --- | --- | --- |
| 灾备单位 | **顶替、迁移、备份节点、快照都按容器** | 项目的容器本来就分散在不同节点上 | [failover.md](failover.md) |
| 租约时长 | **默认 30 秒，每 10 秒续约一次，可按容器调整** | A 挂掉后大约 40 秒内 B 顶上 | [failover.md](failover.md) |
| 副本里的配置 | **热备、备份节点、迁移目标的配置一律由面板下发，副本只带数据** | 源节点被攻破也没法借副本让别的节点启动特权 compose，不再需要"特权配置"检查 | [failover.md](failover.md#数据和热备) |
| 租约安全余量 | **A 在到期前 5 秒已停完，B 在到期后 5 秒启动** | 中间留 10 秒空档，即使两边计时有误差也不会同时运行 | [failover.md](failover.md) |
| 快照工具 | **kopia，作为 Go 库内嵌** | 增量、去重、自带加密，以后接 S3 是现成的；仍然只有一个二进制 | [snapshot.md](snapshot.md) |
| 快照一致性 | **暂停快照，30 秒上限；不针对具体数据库做导出导入** | 恢复、迁移和顶替都只是拷文件，快且通用，不用为每种数据库做适配 | [snapshot.md](snapshot.md#一致性) |
| 快照同步频率 | **设了顶替的容器最长每 15 分钟，其余默认每小时** | kopia 是增量的，频率高也不会占用太多资源 | [snapshot.md](snapshot.md#频率) |
| 异地副本 | **顶替节点，或只同步不顶替的备份节点** | 复用同步代码；S3 以后再加 | [snapshot.md](snapshot.md#异地副本) |
| 版本记录 | **版本的配置记在面板上（节点缓存），版本文件在容器的快照仓库里，随副本走** | 顶替、迁移以后还能接着回滚 | [agent.md](agent.md#版本与回滚) |
| 面板上的密钥 | **面板主密钥加密** | 数据库文件泄露也读不出密钥；需提醒用户单独备份主密钥文件 | [panel.md](panel.md#项目数据) |
| 监控数据 | **存在节点本地，面板按需查询** | 面板不会变重 | [monitoring.md](monitoring.md) |

## 开发

| 问题 | 决定 | 理由 | 详见 |
| --- | --- | --- | --- |
| 运行平台 | **Linux（amd64 / arm64），systemd** | Caddy 直接访问容器 IP、WireGuard 等都依赖 Linux | [development.md](development.md) |
| Docker 交互 | **部署用 compose 命令，其余用 Docker Engine API** | 部署行为和用户手动操作完全一致；状态、日志、监控需要结构化数据 | [development.md](development.md#依赖库) |
| 数据库访问 | **sqlc** | 写 SQL 生成强类型代码，没有运行时魔法 | [development.md](development.md#依赖库) |
| 前端 | **Vite + React + TS + TanStack Router/Query + shadcn/ui** | 纯静态输出可打包进二进制；路由类型安全 | [development.md](development.md#依赖库) |
| 许可证 | **Apache-2.0** | 宽松，允许商用，带专利授权条款 | [development.md](development.md) |
