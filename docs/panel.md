# 面板

面板由 `nagi server` 启动，是项目配置的主人：保存所有项目和容器的配置、版本记录和部署记录，把容器分配到节点上运行，并负责 UI 和见证人投票。容器的运行文件、数据和快照在节点上，见 [agent.md](agent.md)。

## 职责

- 监听一个**面板端口**：首次启动时随机选一个高位端口并持久化，之后重启不变，也可以用 `--port` 指定。Web UI 和 agent 的控制通道共用这个端口
- Web UI（前端构建产物通过 `embed` 打包进二进制）与 Connect-RPC 接口（见 [control-plane.md](control-plane.md#接口设计)）
- SQLite 存储（modernc 纯 Go 实现，无需 CGO）：保存节点信息、面板自身的设置，以及所有项目的数据（见下文，密钥用面板主密钥加密）
- 把容器的配置下发给它所在的节点执行，更新节点上的配置缓存和代理名单；一起部署、迁移、回到某次部署这类涉及多个节点的操作由面板指挥
- 汇总各节点上报的容器状态，供 UI 显示
- 自签 CA：为 agent 签发客户端证书
- 加入 WireGuard mesh：把上传的项目文件传给节点，直连不通时替节点中转 mesh 流量（见 [mesh.md](mesh.md)）
- 可以担任顶替机制中的见证人（见 [failover.md](failover.md)）
- 发现节点失联时发送告警（见 [monitoring.md](monitoring.md)）
- 一键更新自己（见[更新面板](#更新面板)）

## 项目数据

面板数据库里存着：

- 项目：名称、网络名、共享变量（含草稿）、镜像仓库认证、项目连接、内部端口、快照间隔、部署记录、修订号；
- 容器：所在节点和容器目录、配置和草稿、版本记录（配置、镜像摘要、提交、部署时间）、端口映射、deploy key 和 webhook 令牌、快照仓库密码、顶替和备份节点设置、修订号。

容器的运行文件、数据、快照和版本文件不在面板上，在容器所在的节点（和它的热备、备份节点）上。

**节点缓存**：每次修改或部署，面板把容器的完整记录和所属项目的信息推给容器所在的节点（见 [agent.md](agent.md#节点目录-varlibnagi)），顶替节点和备份节点也各推一份。节点离线时，等它连上后补推。所以：

- **面板挂了**：容器照常运行、重启、快照、顶替，只是不能修改和部署。面板回来后照常。
- **面板彻底丢失**（机器坏了、没有备份）：装一个新面板，在各节点上用 `nagi panel add` 加入它（见 [control-plane.md](control-plane.md#在节点上操作)）。新面板按项目 ID 收集各节点上报的缓存，把项目拼回来：节点上报了面板不知道的容器时，面板向它要全部缓存（`AgentService.GetCache`），容器取当前部署的版本（配置、共享变量、镜像摘要）、端口映射、deploy key、快照仓库密码、备份节点、顶替设置，项目信息取项目修订号最大的那份，内部端口和项目连接取节点的代理计划。拼回来以后照常使用，不用重新部署。拼不回来的：草稿、旧版本和部署记录（旧版本的文件还在节点的快照仓库里，但面板上没有记录，不能选它回滚）、项目的创建时间；webhook 令牌只在面板上，会重新生成，git 那边的 webhook 地址要更新。顶替的见证人原来是旧面板的，新面板自动换成自己（换之前 A、B 两票照常构成多数）。
- **旧面板回来**（面板离开期间节点归别的面板管过、改过东西）：面板下发的配置里带着自己的指纹（`ContainerSpec.panel`），节点上报时带回来。面板看到节点上的配置是别的面板写的，就知道自己的记录可能旧了：不把旧配置推下去，在节点页列出这些项目（"项目记录可能已过期"），管理员确认后以节点为准，删掉自己关于这个项目的记录（草稿、版本历史、部署记录、路由、成员范围；保留 webhook 令牌），按节点缓存重新拼回来。节点可能被攻破，所以不自动重建：否则一个节点随便报一个面板指纹，就能让面板清空项目、改用它缓存里的共享变量；拼回以后把配置重新推一次，节点缓存里记上本面板（否则面板每次重启都会再拼一遍）。节点刚连上、第一次上报处理完之前，面板也不给它推代理计划。
- **不轻信节点**（节点可能被攻破）：
  - 只有面板记录里本来就在这个节点上（或者这个节点是它的顶替参与方）的容器，节点说"配置是别的面板写的"才算数，节点不能借此让面板删掉别的节点上的项目；
  - 面板上本来就有的项目，节点缓存里多出来的容器不自动加进去（否则一个节点能把自己的容器塞进别的项目，拿到它的共享变量、连进它的内网）；只有从节点缓存拼回的项目，拼回后 24 小时内接受别的节点缓存里的容器（项目记着 `rebuilt_at`）；其余的列在节点页上（"节点上有面板不认识的容器"），管理员确认是自己的以后点"加入项目"，按节点缓存加入；
  - 节点同时信任着写它缓存的那个面板时（两个面板同时管着这个节点，例如面板丢了以后让节点加入了新面板，旧面板又回来了），本面板不以节点为准删记录，也不把自己的配置推过去覆盖，只记警告，等用户在节点上移除不用的那个面板（节点上报时带着它信任的面板列表）；
  - 拼回的端口映射只取这个容器自己的、名字没被占用、和别的映射不冲突的；
  - 项目连接只在两边都是拼回后 24 小时内的项目、代理所属的项目在面板记录里就在这个节点上时才连回去（节点的代理计划只给它上面的项目放代理），否则一个节点只要知道两个项目的 ID，就能让面板把它们连起来；
  - 同一个容器在两个节点上都有一份时（例如在备份节点上恢复过，原节点后来又回来了），按先报上来的拼回，记下那份的修订号；拼回后 10 分钟内另一个节点报上来更新的一份，改用那一份，旧的那份等它的节点下次上报时停掉、目录改名保留；
  - 项目刚拼回的 10 分钟内，面板不让节点删掉顶替设置（容器可能还没从持有者那里拼回来，先从热备拼回时会看不到）。
- 建议定期备份面板的数据目录（数据库和主密钥文件），恢复更完整（含草稿）。

**面板主密钥**：数据库里的密钥（容器的变量和密钥、镜像仓库认证、deploy key 私钥、快照仓库密码、告警配置里的 Telegram 令牌、两步验证密钥）用主密钥加密。主密钥单独存成一个文件，数据库文件泄露也读不出密钥，面板仍能自动重启、查看和编辑密钥。需要提醒用户单独备份主密钥文件。节点缓存里的密钥由节点保存在本机（权限 0600），和容器目录里的 `.env` 一样。

**主密钥文件不见了**（例如只恢复了数据库、忘了放回密钥）：数据库里有加密数据时面板**拒绝启动**，提示把备份的密钥放回原处。不悄悄生成新密钥，否则这些数据就再也解不开了。确实丢了，用 `nagi server --new-master-key` 启动：

- 生成新的主密钥；
- 关闭所有用户的两步验证（登录后可以重新开启）；
- 清掉数据库里加密的项目密钥，由在线节点从缓存重新上报（和面板丢失时拼回项目一样），离线节点的要等它回来；
- 清掉告警配置，设置页提示重新填写。在那之前面板不给节点下发告警配置，节点继续按原来的配置发告警，只是面板负责的"节点失联"告警发不出去。

## 访问

- **默认**：用 `https://IP:面板端口` 访问，使用自签证书。带内嵌 agent 和用 `--no-agent` 的纯面板都一样。
- **对外地址**：面板有一个"对外地址"设置（自动检测，可修改），安装命令和节点连接都使用它，必须能被所有节点访问（见 [control-plane.md](control-plane.md#连接)）。
- **绑定域名**：之后在面板设置里绑定，自动申请正式证书。
  - 带内嵌 agent 时：由本机 Caddy 反代到面板端口，证书由 Caddy 申请。Caddy 到面板这一段用面板的公钥指纹校验，不需要信任自签证书。
  - 纯面板（`--no-agent`）时：本机没有 Caddy，由面板自己申请证书并提供服务。
- **绑定域名的实现**：在设置页的「面板访问」里填域名（填空取消）。域名删掉以后，节点上这个域名"申请证书失败"的告警自动恢复。
  - 带内嵌节点（有 Caddy）时，面板把域名告诉自带节点（节点上报里带 `embedded`、从本机 127.0.0.1 连上来的那个；主备面板时别的面板自带的节点也连着本面板，不推给它。连上时和修改时都会推送），节点的 Caddy 加一条规则把这个域名反代到 `https://127.0.0.1:<面板端口>`，用面板的 CA 校验面板证书（证书里有 `localhost`）。证书由 Caddy 申请，和项目域名一样，拿到证书以后 HTTP 跳转到 HTTPS。项目的映射不能再用这个域名。
  - 纯面板（`--no-agent`，或者内嵌节点用 `--no-proxy` 不启动 Caddy）时，面板用 certmagic（Caddy 的证书库）自己申请 Let's Encrypt 证书，在 443 上提供服务；80 用于 HTTP 验证，其余请求跳转到 HTTPS。证书存在面板数据目录的 `certificates/`。
  - 节点的控制连接和安装命令仍然用"对外地址:面板端口 + 公钥指纹"，不经过域名。
  - 经本机 Caddy 转发的请求，来源都是本机；登录限速对这些请求改用 `X-Forwarded-For` 里的第一个地址。只看来源是不是本机不够（本机上的其他程序，例如 host 网络的容器，可以随便填 `X-Forwarded-For` 绕过限速）：面板随推送域名给自带节点一个随机值，Caddy 转发时带上请求头 `X-Nagi-Proxy`（覆盖客户端带的同名请求头），面板核对对上了才采用 `X-Forwarded-For`。Caddy 反代的是本机的面板（自带节点信任列表里地址是 127.0.0.1 的那个）。
  - 实测：带内嵌节点时用 `nagi.localhost`（Caddy 对 .localhost 用本地 CA 签发）能通过域名访问和登录；纯面板时 80 正确跳转、443 在监听并开始申请证书（没有公网域名，无法实测签发）。

## 登录

- **初始化**：首次启动时在日志里打印一个带一次性令牌的初始化链接，打开后设置管理员账号和密码。没有令牌的人无法抢先初始化。
- **登录**：密码登录，可在设置里开启 TOTP 两步验证（首页提醒开启）。绑定域名后可以添加 Passkey（Passkey 不支持纯 IP 访问；还没做）。MVP 只有一个管理员账号。
- **防护**：
  - 登录失败限速和锁定：同一 IP 连续输错时逐步延长等待时间。
  - 安全入口：可选开启，开启后必须在地址后加上一段随机路径才能打开登录页。
- **找回**：忘记密码、丢了两步验证设备或者忘了安全入口时，在面板所在机器上用 root 执行本地命令重置。和节点一样，能登录机器 root 的人本来就拥有这台机器。

### 实现

- **修改密码**：需要当前密码，新密码至少 8 位；改完后其他地方的登录全部失效，当前会话保留。
- **两步验证**：标准 TOTP（RFC 6238：30 秒一步、6 位、HMAC-SHA1），和常见的验证器 App 兼容。开启时先生成密钥（10 分钟内有效），用验证器显示的验证码确认才生效。密钥用面板主密钥加密后存在数据库里。登录时允许前后各 30 秒的时间误差，同一个验证码只能用一次。关闭需要验证码或密码。开启后登录不带验证码时接口返回 `failed_precondition`，界面据此显示验证码输入框。Passkey 还没有做。
- **安全入口**：开启时生成一段随机路径。开启后，没登录的访问者必须先打开一次 `https://<面板>/<路径>`（设置一个 30 天的 cookie，然后跳到登录页），否则面板的页面和接口一律返回 404，看起来就像这个地址上没有面板。已登录的会话、项目 webhook（`/hooks/`）、节点安装脚本（`/install.sh`）不受影响，节点的控制连接按 ALPN 分流，也不经过它。面板启动日志里会打印带入口的地址。
- **本地命令**（直接改面板数据库，面板运行中也能用）：

  ```
  nagi reset password [--user 用户名]   # 生成一个新的随机密码并打印，所有登录失效
  nagi reset 2fa                        # 关闭两步验证
  nagi reset entrance                   # 关闭安全入口（会打印原来的路径）
  ```

  默认数据目录 `/var/lib/nagi`，和 `nagi server` 一样用 `--data-dir` 指定。

## 成员和角色

面板可以有多个账号，在「设置 → 成员」管理。角色由面板按接口方法判断（`internal/server/auth/roles.go`），界面隐藏入口只是为了好用：

| 角色 | 能做什么 |
| --- | --- |
| 管理员 | 全部，包括成员、节点和面板设置、节点的终端和文件（[node-access.md](node-access.md)） |
| 操作员 | 管理项目和容器（部署、终端、数据），不能保存带特权的 compose，也不能进入管理员部署的特权容器（[说明](node-access.md#操作员不能借-compose-拿到节点-root)），节点只能查看，看不到面板设置 |
| 只读 | 只能查看项目和节点；回复里去掉容器配置、共享变量、deploy key 和 webhook 令牌，不能打开终端，不能浏览和下载卷里的文件 |

- 没有写明的修改接口只有管理员能调用。终端和上传不走 Connect，单独检查角色。
- 打开着的容器终端和日志每 30 秒重查一次会话、角色和项目范围，被踢出、降权或者移出范围就断开。
- 所有角色都能改自己的密码、两步验证，查看自己已登录的设备并让其他设备退出，也能改自己的显示名称和头像（点导航底部的用户卡片）。登录和活动记录仍然用用户名。头像在浏览器里裁成 128×128 后存进面板数据库，面板只接受不超过 256 KB 的 PNG、JPEG、WebP。没有上传头像时显示一个渐变色圆形，颜色按用户名算出，改显示名称不变。
- 至少保留一个管理员，不能删除当前登录的账号。管理员重置别人的密码后，那个账号已有的登录和访问令牌（[mcp.md](mcp.md#登录)）全部失效。
- 升级前已有的账号都是管理员。

### 访问范围

操作员和只读成员可以限定只能访问哪些项目、哪些节点。管理员始终能访问全部。

**设置**：在「设置 → 成员」添加成员时，或者从成员的 ⋯ 菜单打开「访问范围」，项目和节点各选「全部 / 指定」，选指定时勾选具体的项目或节点。默认都是全部，升级前已有的成员不受影响。成员列表显示每个人的范围（全部，或者几个项目、几个节点）。

**规则**：

- **项目范围**决定能看到和管理哪些项目。项目里的所有容器都可以按角色操作，不论容器在哪个节点上；容器在范围外的节点上时，也能把它迁移到范围内的节点。
- **节点范围**决定能看到哪些节点（节点页、监控、mesh），以及添加、迁移容器，设置顶替、备份节点和映射的入口节点时能选哪些节点。操作员和只读成员都一样。操作员对节点本来就只能查看，节点范围不额外放开任何修改。
- **两者交叉**：
  - 项目里的容器在范围外的节点上时，项目页照常显示这个容器和它的状态、占用，节点只显示名称，不能点进节点页。
  - 范围内的节点上有范围外项目的容器时，节点页不显示这些容器，容器数也只算范围内的；节点整体的占用照常显示。
- **新建项目**：指定了项目范围的成员新建的项目，自动加进他的范围。容器只能放在他范围内的节点上。
- **项目连接**：两个项目都在范围内才能连接或断开。已连接的项目不在范围内时，只显示「另一个项目」和它的网络名（配置里要用网络名访问对方的容器），不能断开。
- **全局概览**：只显示范围内的数据：范围内的节点、项目、端口映射，节点之间的流量只画范围内节点之间的。到范围外节点的流量不显示是哪个节点，只用来从网卡流量里减掉，所以「对外流量」仍然是真正对外的部分。
- **搜索、需要处理的提示**：只出现范围内的项目和节点。
- 删除项目、移除节点时，从所有成员的范围里去掉。

**实现**（`internal/server/api/scope.go`）：

- 数据库：`users` 的 `all_projects`、`all_nodes`（默认 1），表 `user_projects`、`user_nodes`；删除成员、项目时级联删除，移除节点时另外删除（节点只是标记为已移除）。备用面板复制数据库时一起带过去。
- 检查是 Connect 的一个拦截器，放在角色检查之后，处理函数不用管：
  - 请求最外层的 `project_id`、`other_project_id` 核对项目范围，`node_id`、`node_ids`、`standby_node_id`、`witness_node_id` 核对节点范围。范围外的项目一律返回"项目不存在"，不暴露项目是否存在；节点返回"节点不存在"。
  - 另外处理的：`SaveRoute`、`CheckDomains` 核对映射里的入口节点（`route.entry_nodes` 不在最外层），这个映射原来就有的入口节点可以留着，管理员设的入口节点不妨碍操作员改别的设置；`RestoreFromBackup` 核对容器的备份节点，`PingNodeMesh` 核对对方公钥所属的节点。`QueryNodeMetrics` 的前缀限定在一个范围内的项目（如 `c:<项目 ID>/`）时，范围外的节点也放行，项目页才能显示容器的占用。
  - 回复里去掉范围外的内容：项目列表、节点列表（范围内项目用到的范围外节点放在 `other_nodes`，只有名称和是否在线；不认识的容器不给）、mesh 成员、副本、监控序列（容器、端口映射等以项目 ID 开头的序列只留范围内的项目，形式不认识的序列也去掉），已连接项目的名称。
  - 新建项目成功后加进成员的范围。
- 终端 `/ws/exec`、上传 `/api/upload`、卷文件 `/api/volume-file` 不走 Connect，单独核对项目范围。
- `scope_test.go` 列出 `ProjectService`、`NodeService` 里操作员、只读成员能调用的方法，每个都必须在请求里带项目或节点，或者登记为靠过滤回复，新增接口忘了处理时测试失败。
- 节点文件、节点终端仍然只有管理员能用，不受范围影响。

## 活动记录

会改变状态的接口调用记入 `activity` 表（`internal/server/api/activity.go`），包括失败和被拒绝的调用，查询不记。只取项目、容器、节点、名称这几个固定字段，请求里的密码、令牌、环境变量不会写进去。节点发出告警时通过 `PanelService.ReportAlert` 告诉面板，面板自己发的告警（节点失联）也记录；上报有频率限制，长度有上限。保留最近 5000 条。

## 更新面板

在设置页"关于"里一键更新本面板（只有管理员能检查和更新，其他角色只看到版本和状态），内嵌的节点在同一个进程里，一起更新。其他节点之后在节点页单独升级（[control-plane.md](control-plane.md)）。

- **检查**：跟随 `github.com/SIPC/Nagi/releases/latest` 的重定向得到最新版本号（不含预发布版），不用 GitHub API，不占它的限额。结果缓存 1 小时，界面显示查询的时间（"刚刚检查"）；有新版本时侧栏和二级菜单的"关于"上显示小圆点；点"检查更新"不用缓存。
- **更新日志**：有新版本时，"关于"的版本下面列出最新版本日志的前三条；点"更多信息"就地展开本面板到最新版本之间各版本的全部日志（`SettingsService.GetPanelReleaseNotes`）。点"更新"只弹确认框。日志随发布文件上传（`CHANGELOG.md`，英文界面取 `CHANGELOG.en.md`），和新版本走同一个下载地址，安装时用了镜像就从镜像取；按版本缓存在内存里。取不到时不显示日志，照常可以更新。
- **更新**：版本由面板自己决定（最新发布的版本，只升不降），不从请求里取。下载和节点升级走同一段代码（`internal/pkg/release`）：从 GitHub Release 或镜像下载，按 `SHA256SUMS` 核对，试运行一次 `version` 确认能在本机运行且版本对得上，替换可执行文件，然后原地重启（`exec`，进程号不变）。任何一步失败都不影响正在运行的面板。
- **镜像**：安装时用了 `--download-url` 的，地址记在 `<面板数据目录>/download-url`，从这里下载。版本号仍要问 GitHub：连不上 GitHub 时检查不到新版本，要重新执行安装脚本升级。
- **重启**：登录会话在数据库里，不用重新登录。更新在后台进行，界面每 2 秒查一次进度，面板用新版本回来后刷新页面；3 分钟没恢复时显示失败，要到服务器上看日志。进行中的部署等操作会中断（和手动重启一样）；项目容器由 Docker 运行，不受影响。
- **不能退回**：新版本启动时会迁移数据库，没有自动回滚。要回到旧版本，得用安装脚本的 `--version` 并恢复备份的数据库。
- 本地编译的版本（`dev`）和非 Linux 上的面板不能一键更新，页面上说明原因。

### 更新状态

面板和节点的更新进度记在面板的 `settings` 表（`update_state`，每个面板自己的，不同步），由 `SettingsService.GetUpdateStatus` 读取，只有管理员能查。刷新页面、换浏览器、面板重启后都还在，进行中不能再点一次。

- **阶段**：排队（一键升级时轮到它之前）、下载和替换、等它用新版本回来、失败。成功后记录删除；失败的记录留到下一次尝试或者节点已经是目标版本。
- **超时和打断**：下载和校验 10 分钟没完成算失败（面板取消请求，节点停止下载）；替换后 3 分钟没用新版本回来算失败。面板重启后，上一个进程的后台任务已经没了：下载中的算失败，排队的回到可以升级，已经在重启的节点接着等。
- **一键升级全部节点**：节点页的按钮把所有落后于面板、能升级的节点逐个升级，每个节点用新版本回来后才开始下一个，同时重启可能让顶替的租约续不上。顺序是只做热备或备份的节点、既有容器又做热备或备份的节点、只有容器的节点、其余节点（见 [control-plane.md](control-plane.md)）。下载阶段失败（包括超时）时节点还是原来的版本，记下原因后跳过，接着升级下一个；替换后没有用新版本回来时停下，后面的回到可以升级，以免新版本有问题时影响更多节点。
- **取消**：管理员可以在节点页取消全部升级，或在节点详情取消这个节点的升级（`NodeService.CancelNodeUpgrade`）：排队的不再升级；下载中的由面板通知节点停止（agent 的 `CancelUpgrade`：面板发给节点的请求不跟着面板取消，见 `internal/agent/detach.go`），节点确认后才算取消，节点还是原来的版本。已经替换、正在重启的不能取消。v0.20.0 以前的节点没有 `CancelUpgrade`，正在下载时不能取消（界面上不显示取消按钮），只能等它完成或超时。节点同一时间只做一次升级，取消的那次收尾之前再点升级，节点会拒绝。
- **右下角提示**：管理员在任何页面都能看到新版本、更新进度和失败原因，可以点进去查看。关掉的提示记在浏览器里，同一件事不再弹。面板有新版本时先提示更新面板，更新好以后才提示升级节点。

## webhook

每个容器的 webhook 地址带有独立的随机密钥，不经过登录和安全入口。需要面板能被公网访问，建议绑定域名。
