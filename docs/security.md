# 主动安全与审计

本文分两部分：**主动安全检测**发现正在发生的攻击并告警；**审计日志**记下谁在什么时候、从哪里、通过什么做了什么，事后可以查，被删改能发现。审计是检测的基础：安全事件先写成审计记录，再由检测规则判断要不要告警。

状态：实施中，进度见[实施顺序](#三实施顺序)。已实现的部分拆进对应模块的文档（审计日志、面板、节点访问、MCP、mesh、监控），本文只留总览和还没实现的设计。

## 要防什么

下表列出本方案针对的场景，以及现在已有的防护。

| 场景 | 现在 | 本方案补上 |
| --- | --- | --- |
| 账号密码泄露 | 登录限速、两步验证、高权限确认，但只拦不报 | 验证码连续错误、敏感变更即时告警 |
| 会话 cookie 被盗（电脑中了窃密木马、钓鱼代理） | cookie 7 天内在任何地方都能用，和设备、网络无关 | 令牌轮换和重用检测、设备和网络变化检测、空闲超时 |
| 容器里的服务被攻破 | mesh 只放行有关项目；普通网络不限制，容器能连宿主机、局域网和云元数据地址 | 容器出站限制，拦下的连接告警 |
| 节点被拿到 root | mesh 上每个请求校验调用方，但被拒绝的请求不记录 | 越权识别、一键隔离 |
| 面板或管理员账号被攻破 | 等于拿到所有节点的 root，无法阻止 | 敏感变更告警发往变更前的渠道；日志外送保证留痕 |
| 机器被格式化、日志被删 | 活动记录在面板数据库里，一起丢失 | 外送到外部存储，哈希链发现删改 |

## 一、主动安全检测

### 原则

- **由不受影响的一方判断**：节点被攻破后自己报的内容不可信，越权由其他节点和面板发现；面板上改告警配置时，告警发往修改前的渠道。
- **只用误报低的信号**：正常使用不会触发的行为才告警。不做基于特征的检测。
- **不自动处置**：隔离、拦截以外的处置由管理员确认，遵循「没说要动的就不动」。
- **复用现有告警**：安全事件写入审计日志（类别 `security`），告警走现有渠道、重复告警规则（出现一次、恢复一次、每 4 小时提醒）和面板代发。

### 账号与凭据

见 [audit.md](audit.md#安全告警)。

### 会话加固

令牌轮换和重用检测、会话密钥、TLS 指纹、设备和网络检测、有效期、`__Host-` 前缀、来源检查见 [panel.md](panel.md#会话)。

**管理员登录地址**：见 [panel.md](panel.md#管理员登录地址)。和设计稿的差别：放在「设置 → 安全」的「会话」里；从范围以外的地址用正确的凭据登录时另外告警。

**访问令牌**：见 [mcp.md](mcp.md#网段)。和设计稿的差别：从允许范围以外的地址使用时也告警。

**Passkey**：见 [panel.md](panel.md#通行密钥)。

### 集群变更

见 [audit.md](audit.md#安全告警)。隔离和解除隔离节点也会通知（见 [mesh.md](mesh.md#隔离)）。

### 节点越权识别

见 [mesh.md](mesh.md#越权识别) 和 [mesh.md](mesh.md#隔离)。

### 容器出站限制

见 [agent.md](agent.md#出站限制)。和设计稿的差别：被拦下的连接不经内核日志（nflog）交给节点，改为写进 nftables 的动态集合由节点读取（有的内核和容器里的网络命名空间不输出 netfilter 日志）；本机地址不用 `fib`，由节点列出；告警的开关放在容器的告警规则里。

### 资源与流量规则

见 [monitoring.md](monitoring.md#告警)。和设计稿的差别：阈值固定，只有开关；请求量突增和过去 24 小时的整体平均值比，不按同时段。

### 不做

- **木马扫描**：病毒库体积大、要持续更新，扫描占 CPU 和磁盘；节点被拿到 root 后可以篡改扫描结果。交给云厂商的主机安全或 ClamAV 这类专门工具。
- **DDoS 防护**：流量型攻击在到达节点之前就把带宽占满了，只有 CDN 或云厂商的清洗能扛。Nagi 只提供上面的请求量突增告警。
- **WAF 特征规则**：误报多、维护成本高。需要时在前面加 CDN 或 WAF。
- **流量基线**：攻击者只用本来就有的权限时（例如连接本项目容器开放的端口），和正常流量没有区别。识别这种情况需要学习基线，误报高。

### 部署建议

以下建议不需要改代码，写进使用教程：

- 面板所在的机器不运行对外的业务。面板内嵌一个节点，这台机器被攻破就是整个面板被攻破。
- 所有管理员开启两步验证，开启安全入口。
- 不需要远程终端的节点，在节点上执行 `nagi node access disable`。
- 云服务器限制元数据访问，例如使用 IMDSv2 并把跳数限制设为 1。
- 配置日志外送（见下文），外送目标和 Nagi 管理的机器分开。

## 二、审计日志

### 目标

- 谁、什么时候、从哪里、通过什么、对什么、做了什么、结果如何，每一项都能查到。
- MCP 的每次工具调用都有记录（包括查询），能看到参数和它触发的操作。
- 终端和命令执行可以回放输出。
- 面板被攻破、机器被格式化以后，日志在别处还有一份；记录被删改能发现。

### 记录范围、字段、脱敏

见 [audit.md](audit.md)。

### MCP 调用

见 [audit.md](audit.md#mcp-调用)。

### 终端与命令录制

见 [audit.md](audit.md#终端与命令录制)。

### 节点本地审计

面板被攻破时，面板上的记录不可信，所以节点自己也记一份：

- 写在 `<数据目录>/audit/` 下，JSON Lines 格式，按 10 MB 轮换，保留 10 个文件。
- 内容：节点终端的开始和结束（面板指纹、用户名、IP），`node_exec` 的命令和退出码，面板下发的修改类指令（部署、删除、升级、信任列表、告警配置、节点文件），被它拒绝的越权请求。
- 节点也按面板下发的外送配置直接外送（和告警配置一样按面板指纹保存）。节点被攻破后可以删掉本地文件，但已经外送的记录还在。

## 三、实施顺序

审计存储是后面各步的基础，所以先做。容器出站限制直接堵住最常见的横向路径，排在检测规则之前。

| 步骤 | 内容 | 完成标准 | 状态 |
| --- | --- | --- | --- |
| 1 | 审计存储：`audit.db`、字段、脱敏、迁移、新的查询接口和界面 | 旧记录全部迁移；测试证明所有密码、令牌、变量值都不出现在 `params` 里；界面能按每个条件筛选 | 已完成 |
| 2 | 会话加固：令牌轮换和重用检测、会话密钥、TLS 指纹、设备和网络检测、空闲超时、`__Host-` 前缀、来源检查、高权限确认绑定 IP | 把 cookie 复制到另一台机器上使用，15 分钟内会话被退出并告警；只复制 cookie、主人不再使用时，15 分钟内要求重新验证；用 curl 带上 cookie 请求会被直接退出；手机在 Wi-Fi 和移动网络之间切换一次不被退出；打开着的终端在令牌轮换后不断开；兄弟子域名写的同名 cookie 不起作用 | 已完成 |
| 3 | MCP 全量记录和上下级关联 | 用 Claude Code 跑一次部署，界面上一条工具调用下面能看到它触发的接口调用 | 已完成 |
| 4 | 终端录制和回放 | 节点终端里执行 `sudo` 输入密码，回放里看不到密码；刷屏超过 64 MB 后，最后的命令仍在录制里 | 已完成 |
| 5 | 外送、哈希链、备用面板增量同步 | 删掉 `audit.db` 中间的一条记录，`nagi audit verify` 报错；外送端收到锚点；提升备用面板后哈希链连续 | 已完成 |
| 6 | 账号、凭据和集群变更的告警 | 在测试环境里逐项触发，渠道收到告警；改告警配置时旧渠道收到通知 | 已完成 |
| 7 | 容器出站限制 | 容器里连宿主机 22 端口、`169.254.169.254` 和局域网地址被拦下并告警；项目内网、跨节点代理和公网不受影响；机器上非 Nagi 的容器不受影响 | 已完成（跨节点代理没有实测） |
| 8 | 节点越权识别和一键隔离 | 用一台测试节点伪造各类越权请求，面板汇总告警；隔离后其他节点 5 秒内断开和它的 mesh 连接 | 已完成（伪造越权请求没有实测，部分信号未接） |
| 9 | CPU 和流量规则 | 用压测工具分别触发四条规则 | 已完成（节点 CPU 没有实测） |
| 10 | Passkey | 绑定域名后能用 Passkey 登录；经钓鱼代理转发的登录页上 Passkey 无法完成验证 | 已完成（用页面里注入的软件验证器实测，没有用真实的验证器和真实的域名） |
