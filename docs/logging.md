# 统一本地日志（逐步接入）

日志和告警分开：日志库保存事实、统计、来源和已清理范围，不发通知、不调用模型、不负责 mesh 选路。
告警的既有新鲜度/有效性保护不变。这里只是新日志的分批接入，不代表日志清单已经全部完成。

## 已接入与暂未接入

- 面板所有 HTTP 请求的完成事实（包括认证前拒绝、普通查询、静态资源、404、跳转、流式响应）：方法、接口/安全路径、实际来源、HTTP 状态、耗时、实际读取/写出字节、中断/取消。此处不把 HTTP 状态解释成接口业务码或故障原因。
- 面板本机操作/安全/告警审计：从已有脱敏、规范化后的记录接入。备用面板只记录自己的操作，不把旧主备审计同步误当成新日志复制。
- 节点本机审计：从已有写入入口接入，保留已认证面板、面板声称的操作者、动作和结果；自由格式命令/detail 在新库保守隐藏。
- Nagi 面板/节点的结构化运行日志：保留等级、组件、分组和原有终端输出。Caddy 自己的非访问运行日志、外部程序直接写 stderr 的内容还不是统一采集。
- Caddy 逐请求访问事实：状态码、耗时、字节、规则、方法、域名、直接来源、协议。包括访问输入中没有业务规则的请求；不改变旧告警只统计业务规则的口径。只保存路径摘要，不保存请求头、查询串、任意业务路径或正文。
- 现有指标采集器的全部有限数值：CPU/内存/磁盘/网络、服务资源、HTTP/L4 汇总和已有 mesh 速率等，按原时间分块入库。新库不会执行旧指标的 24 小时原始点降采样/30 天过期策略；无效数值单独留痕，不补零，不捏造尚未采集的细分指标。
- 本机全部 Docker 容器 stdout/stderr 后台持续采集（含未托管容器），不依赖查看页面；默认 15 秒发现容器并保存状态快照，5 秒重连。按实际实例分别保存读取位置，同一时间的重复行照记，正常时间顺序下重连只跳过已保存边界。TTY 合并输出记为 stdout；未托管容器没有项目归属，未来只能按节点权限查询。
- Docker 引擎事件：容器/镜像/网络/卷等事件的类型、动作、对象、时间，以及项目、名称、镜像、退出码、信号等白名单属性。exec 事件不保留内嵌命令，健康事件不复制任意检查输出，不复制全部标签。
- 项目任务：部署、整个容器/组内服务的启停重启、删除/退役、迁移停止/撤销、从副本恢复、定时/手动快照、从快照恢复、仓库维护/立即回收。记录每次执行的关联编号、项目和容器、开始、现有进度输出、结束结果和用时；定时任务也保存，不依赖有人查看。只保存执行中实际发出的进度，不复制配置/环境变量/命令；未完成的任务只有开始而不会补一个成功结束。租约到期的紧急停机路径不额外插入同步日志写入。
- 独立镜像拉取：执行关联编号、镜像、开始、Docker 原有节流进度（字节/层数）、结束、耗时和错误；分别标记拉取是否完成与调用结果，避免把已拉下镜像但回传失败写成镜像没拉到。容器镜像检查记录任务及实际仓库查询的服务/镜像/摘要和 unchanged/update_available/unknown，仓库不可用不冒充“没有更新”；没有可检查仓库摘要的本地镜像/固定摘要仍按原行为跳过。
- 备份/迁移/切回共用的副本传输：拿到执行名额后，记任务编号、项目/容器、目标节点编号/名称、开始、定期进度、每次连接重试和结束。计划/已完成字节与本次实际发送字节分开；错误、用户停止和退出中断不记成功，已经确认成功的传输不会仅因之后上下文取消被改写成失败。进度默认 5 秒一条，结束前等待采集退出，最后一条之后不再写进度；不额外采集文件清单/正文、仓库配置或公钥。

**审计过渡边界：** 已打开的旧节点文件或面板审计库后来写入失败时，新库仍独立采集本机审计事实；反过来新库失败也不改变旧库和业务结果。旧审计的读取、哈希链、检测和既有外送仍只认旧库实际提交成功的记录，不能拿新库采集成功冒充旧链已提交。MCP 收集阶段不重复采集，最终父子记录分别保存。此处不改变旧审计初始化失败时的行为，也不把新日志正文当成完整的防篡改审计链。

**新旧副本的保密差异：** 新 `logs.db` 的统一写入入口会尝试把 `params` 等字符串中的 JSON 再解析，递归隐藏 password/secret/token/authorization/cookie/private_key/credential/key/api_key/command 等敏感字段；保留普通字段、引用编号和整数精度。解析失败的手工参数，以及 `error`、任务输出等文本，统一保守隐藏密码/令牌/密钥参数、`mysql -pXXX` / `-p XXX` / `--password XXX`、带引号或转义的参数、连接串 user:pass@、Bearer/Basic 和私钥正文。不能由此保证任意程序、任意命令语言或编码后的秘密都可识别；命令/detail 字段仍整体隐藏，源采集入口也必须避免输出秘密。新规则覆盖后续实时副本与尚未导入的旧历史，不会回写已入库副本，也不改旧审计原文、原链或哈希。旧库仍可能含旧规则漏掉的操作参数、命令密码和错误正文，须按敏感证据限制访问；新副本携带的原哈希只是来源关联，不是对脱敏后正文的链验证。

镜像删除/清理的逐项执行事实与预拉取、备份接收端/排队阶段的完整任务、终端录制正文迁移、新的系统/内核/客户端采集器，以及清单中标记“待补”的细分指标，仍须逐项接入。已有面板审计中的录制关联编号已纳入统一查询，原加密录制继续由原模块读取、计入共享容量。应用自行写入文件或不支持 Docker 读取的日志驱动不会被擅自绕过读取业务卷；采集失败会留中断记录。

**容器来源的完整性边界：** 记录与读取位置同事务提交；写入失败立即停读重试，不确认未保存的尾部。读取位置不是可轮换历史，不能随删旧日志而删除或倒退；位置也占数据库页数额度。Docker 只有时间过滤而没有持久行号，日志轮换、有限事件回放、断联和时钟回拨都可能造成不可补回的历史，因此每次接入明确记录历史不保证完整；不伪造恢复。正常连接中已观察到的乱序记录照记。输出每行默认最多保留 8 KiB 原始前缀（含 Docker 时间前缀，可配 1～8 KiB），超出显式标记截断及原字节数，仍消费完整行并继续采后面的行；无换行的尾部在正常 EOF 时保存。不会承诺任意应用文本均能自动脱敏。

## 本机配置与容量

独立节点读取 `<data-dir>/logs/config.json`，库为同目录 `logs.db`。面板也在自己的顶层 `<data-dir>/logs/` 保存本机记录，不放进会被主备配置快照替换的 panel 目录；面板与内嵌节点共享同一库和容量，角色变化不重建该库。未配置文件时默认如下，修改后重启生效：

```json
{
  "capacity_gib": 5,
  "metrics_every_seconds": 10,
  "container_rescan_seconds": 15,
  "container_retry_seconds": 5,
  "container_line_bytes": 8192,
  "transfer_progress_seconds": 5,
  "runtime_level": "INFO"
}
```

容量只接受 5～10 GiB。指标入库间隔在 10～86400 秒之间且为 10 的倍数；增大间隔会减少统一库中的原始点，告警不会回退读取当前内存值冒充完整历史，窗口证据不足时保持未知。原指标索引库仍按 10 秒采样，为图表与旧历史提供兼容查询。容器发现/状态快照和重试间隔可配 1～3600 秒；行前缀上限可配 1024～8192 字节，保留 JSON 转义与元信息空间。

副本传输进度入库频率 `transfer_progress_seconds` 可配 1～3600 秒，默认 5 秒；只调本地历史，不改变备份带宽、重试/取消或既有界面状态更新。开始、每次重试和结束始终尝试记录，不受此频率限制；库不可写只计写入失败，不改变实际传输结果。

额度按统一库及已登记的旧历史 DB/索引/WAL/SHM、节点审计 JSONL、面板审计和录制文件的实际占盘共同控制，不是只加正文长度；20% 留给事务/回收空间，主库页数有硬上限。活动页达到主库预算约 90% 时，清理到约 80%。先清运行日志，再清访问/容器输出，再清原始指标、一般任务，最后才是审计/安全/告警。统一库同级按本机采集序号清最旧的，旧存储按自身历史顺序分批清理；不承诺跨不同存储实现严格全局最旧排序。普通流量不能为自己清掉更重要的记录，重要记录过多时最终也会淘汰可清理的旧审计，并留下清理摘要。

每类别一条累计清理摘要，包含编号包络和数量；包络不表示中间每条都丢失，不能拿它直接宣布某一段完整。来源编号、只增序号和清理摘要跨重启保留。每条正文最多 64 KiB，超长记录显式标记截断；不保留无限正文。读取最多 1000 条，按独占序号游标分页，可筛事件时间的闭开区间、类别、项目和对象。

采集写入失败不改变业务操作的成功/失败：最多使用 500ms 的数据库写入上下文，失败有当前进程计数和每分钟限频的独立 stderr 错误输出，不递归写自己。初始化失败也不会仅因新日志库不可写就停止面板/节点，而是明确输出新日志未入库的错误；内嵌节点不会擅自另开第二份额度。当前直接事务落盘，尚未做高吞吐批写；不能宣称请求洪峰下全部不丢。同步写入成功后本库已提交；机器被 root 攻破、物理磁盘写失败、断电或进程崩溃窗口不在“绝不丢”的承诺内。

**过渡期额度边界：** 已登记旧指标、节点 audit JSONL、面板 audit.db/旧角色归档/副本和录制的物理占盘。未导入的审计源、迁移中的混合 node.db、旧角色归档/旧主备副本和正在录制的文件只计数不擅删；如果保护文件已经占满额度，明确拒绝新增历史并保留源文件，不以“为迁移腾位置”为由先删待迁移历史。因此升级时已有超额文件不承诺立即压到 5 GiB 以下。配置、网段、当前状态和断点不是可淘汰历史。Docker 自身管理的日志文件和业务卷不属于本额度；不会为了凑额度删除容器运行数据。

**监控库分离：** 将 `node.db` 的 `metrics_raw` / `metrics_m5` 分批复制到节点自己的 `logs/metrics.db`；两张表逐条核对、目标提交落盘后，才在一个事务内清空旧指标表，配置与网段不动。迁移源/目标同时计入共享额度；额度不足、取消或值冲突时保留源表和已提交目标，重试不覆盖不同值。采集和图表查询使用分离后的索引库；失败回退混合库时保护配置与网段。旧库整理前检查剩余空间，空间不足不整理。指标历史不再仅按旧的 24 小时/30 天计时删除，而是加入统一空间预算；已被旧版本删除的明细不能补造。

**审计历史导入：** 节点 JSONL 和面板自己的旧审计库在启动时取有界历史快照，逐批导入统一库，记录和读取位置同事务提交；重启接续。已有独立采集的相同历史事实经规范化正文和原始身份/时间对账，毫秒精度的面板旧库不会重复导入纳秒时间的实时副本；正常实时输出绝不据此去重。源文件坏行、查询失败或额度不足时停在已提交位置、保留源库；旧编号缺口明确记录，不伪称所有过去明细完整。面板旧库用持久来源标识区分角色库替换，不依赖文件名；原哈希链、墓碑、加密录制和其验证/回放方式不重签、不覆盖。旧角色归档及备用面板收到的旧同步链尚不自动导入。

## 按需查询与告警

`LogService.QueryLogs` 和 `LogService.QueryMetrics` 只注册在现有 mesh 服务上；面板的 `NodeLogService.QueryNodeLogs` 及原图表查询都经 mesh 取数，不回退控制 RPC。日志查询支持来源核对、序号分页、时间/类别/项目/对象过滤，并返回清理摘要和写入失败计数。统一日志查询目前保守限制为管理员；原项目图表继续按现有项目权限开放。节点端仍核对可信面板、指标项目归属与信任撤销。备用面板暂无新 mesh 授权，不擅自开通。

节点告警从日志模块读取完整、近期采样及本地历史指标；采样缺块、过期或不存在时不靠内存值判恢复。规则关闭/对象移除暂保留未知事件而非伪造恢复。通知待发队列只持久化当前事件的发送意图，不保存旧正文或密钥；重试前重新核对事件、阶段、渠道、目标及当前权限，恢复会替代积压的故障通知，旧格式队列舍弃。此处没有调整阈值、调用模型或实际对外发送；面板告警生命周期和聚合通知仍需后续完善。

## 接下来与 mesh 的边界

1. 继续接入录制正文、镜像删除/清理与预拉取、备份接收端等剩余本地来源，逐项核对日志清单；补旧角色审计归档的只读导入。
2. 统一查询/指标历史已接 mesh；旧专用审计与录制阅读器继续兼容，不能把关联编号导入称为录制正文全部迁移。
3. 做主面板近期副本（24 小时目标、每面板最多 1 GiB），所有传输经 mesh；旧控制通道和主备 TLS 同步不能作为新日志的兜底。
4. 备用面板入 mesh 后再接其独立接收/确认/补缺、切换衔接；继续完善面板告警生命周期和汇总通知。

需要 mesh 提供而日志模块不自行实现的能力：备用面板独立身份和可信成员资格；节点向主/备分别建立连接且主故障后仍有可用的直连/中转路径；按用户/项目/角色校验查询、接收、补缺权限；信任撤销和只读备用授权；独立重连事件。每个面板的持久确认由日志模块负责；数据不得回落公网面板端口。日志模块提供稳定来源、序号、正文和清理摘要，不改变身份/选路文件。新增协议集中在 `logs.proto`，复用原指标查询消息，未修改 `common.proto` / `panel.proto` 的字段。
