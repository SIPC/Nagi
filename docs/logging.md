# 统一本地日志（逐步接入）

日志和告警分开：日志库保存事实、统计、来源和已清理范围，不发通知、不调用模型、不负责 mesh 选路。
告警的既有新鲜度/有效性保护不变。这里只是新日志的分批接入，不代表日志清单已经全部完成。

## 已接入与暂未接入

- 面板所有 HTTP 请求的完成事实（包括认证前拒绝、普通查询、静态资源、404、跳转、流式响应）：方法、接口/安全路径、实际来源、HTTP 状态、耗时、实际读取/写出字节、中断/取消。此处不把 HTTP 状态解释成接口业务码或故障原因。
- 面板本机操作/安全/告警审计：从已有脱敏、规范化后的记录接入。备用面板只记录自己的操作，不把旧主备审计同步误当成新日志复制。
- 节点本机审计：从已有写入入口接入，保留已认证面板、面板声称的操作者、动作和结果；自由格式命令/detail 在新库保守隐藏。
- Nagi 面板/节点的结构化运行日志：保留等级、组件、分组和原有终端输出。Caddy 自己的非访问运行日志、外部程序直接写 stderr 的内容还不是统一采集。
- Caddy 逐请求访问事实：状态码、耗时、字节、规则、方法、域名、直接来源、协议。包括访问输入中没有业务规则的请求；不改变旧告警只统计业务规则的口径。只保存路径摘要，不保存请求头、查询串、任意业务路径或正文。
- TCP/UDP 映射的逐会话打开/结束：关联编号、入口规则、本端/来源地址、协议、时间、持续时长及双向字节；UDP 按 Caddy 会话，不逐包落库。不保存业务载荷。结束只表示入口观察器已返回，不能冒充远端应用成功；代理返回错误单独记录。长连接进行中仍由原十秒汇总保存流量；进程强停只有打开而无结束，不补造关闭。
- 现有指标采集器的全部有限数值：CPU/内存/磁盘/网络、服务资源、HTTP/L4 汇总和已有 mesh 速率等，按原时间分块入库。新库不会执行旧指标的 24 小时原始点降采样/30 天过期策略；无效数值单独留痕，不补零，不捏造尚未采集的细分指标。
- 本机全部 Docker 容器 stdout/stderr 后台持续采集（含未托管容器），不依赖查看页面；默认 15 秒发现容器并保存状态快照，5 秒重连。按实际实例分别保存读取位置，同一时间的重复行照记，正常时间顺序下重连只跳过已保存边界。TTY 合并输出记为 stdout；未托管容器没有项目归属，未来只能按节点权限查询。
- Docker 引擎事件：容器/镜像/网络/卷等事件的类型、动作、对象、时间，以及项目、名称、镜像、退出码、信号等白名单属性。exec 事件不保留内嵌命令，健康事件不复制任意检查输出，不复制全部标签。
- 项目任务：部署、整个容器/组内服务的启停重启、删除/退役、迁移停止/撤销、从副本恢复、定时/手动快照、从快照恢复、仓库维护/立即回收。记录每次执行的关联编号、项目和容器、开始、现有进度输出、结束结果和用时；定时任务也保存，不依赖有人查看。只保存执行中实际发出的进度，不复制配置/环境变量/命令；未完成的任务只有开始而不会补一个成功结束。租约到期的紧急停机路径不额外插入同步日志写入。
- 独立镜像拉取：执行关联编号、镜像、开始、Docker 原有节流进度（字节/层数）、结束、耗时和错误；分别标记拉取是否完成与调用结果，避免把已拉下镜像但回传失败写成镜像没拉到。容器镜像检查记录任务及实际仓库查询的服务/镜像/摘要和 unchanged/update_available/unknown，仓库不可用不冒充“没有更新”；没有可检查仓库摘要的本地镜像/固定摘要仍按原行为跳过。
- 镜像删除与清理：记录整批任务开始、每个请求的镜像/标签和实际结果、构建缓存释放字节及错误、整批结束和耗时。逐项完成后先尝试持久记录，再执行下一项；受保护/不存在镜像的删除拒绝保留原因，清理时不再符合条件的项与重复项记跳过。部分失败不写成整批成功，读取 Docker 现状失败也有失败结束；不改变非强制删除、预览标签核对和受保护镜像检查。无配置/命令正文，错误仍经统一脱敏；进程被强杀时不伪造结束。
- 热备预拉取：复用项目任务日志记录项目/容器、执行编号、开始、compose 原有输出、结束和耗时；临时配置准备阶段出错也记录失败。未部署版本仍跳过，不捏造执行；输出订阅者拿到的原文和失败不影响顶替的原行为不变，日志副本统一脱敏，不复制配置、环境和仓库凭据。租约续约/紧急停止路径不额外插入这类同步写入。
- 节点和面板升级：本机记录旧新版本、任务编号、下载来源安全名称、下载字节、校验/试运行阶段、取消/失败、已替换等待重启；原实时进度不受替代。普通下载进度默认每秒保存，阶段/来源切换及下载完成另记；回调通过 32 条有界队列，不阻塞下载，溢出计入最终摘要，结束先排空再重启。崩溃时不补造任务结束；“等待重启”不是新版本已经运行成功。最早的节点回退保护仍先于日志库初始化，彼时异常只保留原终端输出，不能声称该启动前日志一定入库。
- 备份/迁移/切回共用的副本传输：拿到执行名额后，记任务编号、项目/容器、目标节点编号/名称、开始、定期进度、每次连接重试和结束。计划/已完成字节与本次实际发送字节分开；错误、用户停止和退出中断不记成功，已经确认成功的传输不会仅因之后上下文取消被改写成失败。进度默认 5 秒一条，结束前等待采集退出，最后一条之后不再写进度；不额外采集文件清单/正文、仓库配置或公钥。
- 备份队列和接收端：实际入队、重复请求合并、取得执行名额、再次排队和最终结果；等待时停止或移除目标也保存结束，不伪造传输开始。接收节点在来源鉴权及接收名额检查通过后记录接收开始、默认每 5 秒的实收正文大小与结束；收到文件只标记“文件已收到”，不代表整个快照已提交。另在实际提交操作结束、释放副本锁后记录提交结果；传输字节不是已落盘字节，既有文件校验/续传与提交语义不变。不保存文件路径或正文，库失败不影响业务结果。

**审计过渡边界：** 已打开的旧节点文件或面板审计库后来写入失败时，新库仍独立采集本机审计事实；反过来新库失败也不改变旧库和业务结果。旧审计的读取、哈希链、检测和既有外送仍只认旧库实际提交成功的记录，不能拿新库采集成功冒充旧链已提交。MCP 收集阶段不重复采集，最终父子记录分别保存。此处不改变旧审计初始化失败时的行为，也不把新日志正文当成完整的防篡改审计链。

**新旧副本的保密差异：** 新 `logs.db` 的统一写入入口会尝试把 `params` 等字符串中的 JSON 再解析，递归隐藏 password/secret/token/authorization/cookie/private_key/credential/key/api_key/command 等敏感字段；保留普通字段、引用编号和整数精度。解析失败的手工参数，以及 `error`、任务输出等文本，统一保守隐藏密码/令牌/密钥参数、`mysql -pXXX` / `-p XXX` / `--password XXX`、带引号或转义的参数、连接串 user:pass@、Bearer/Basic 和私钥正文。不能由此保证任意程序、任意命令语言或编码后的秘密都可识别；命令/detail 字段仍整体隐藏，源采集入口也必须避免输出秘密。新规则覆盖后续实时副本与尚未导入的旧历史，不会回写已入库副本，也不改旧审计原文、原链或哈希。旧库仍可能含旧规则漏掉的操作参数、命令密码和错误正文，须按敏感证据限制访问；新副本携带的原哈希只是来源关联，不是对脱敏后正文的链验证。

宿主机 journal 的已选范围见下节；客户端采集器及清单中标记“待补”的细分指标仍须逐项接入。已有面板审计中的录制关联编号已纳入统一查询。应用自行写入文件或不支持 Docker 读取的日志驱动不会被擅自绕过读取业务卷；采集失败会留中断记录。

### 宿主机日志

Linux 节点通过只读 `journalctl --system` 接入已有 journal，不安装或开启系统服务、不改日志权限、不扫描 `/var/log`，也不同时读 syslog 文件。默认安装以宿主机 root 运行；自定义非 root 部署需要系统 journal 的读取授权。journalctl 不存在、无权限、没有可读记录、版本不支持所需选项或读取出错时保存 `host.journal.unavailable`；恢复重连留下 attaching 记录，但不声称历史完整。非 systemd/非 Linux 环境明确不可用，不悄悄换来源。

接入范围：Docker/containerd 警告错误；内核内存/OOM、磁盘/文件系统、网卡关键故障及链路变化；所有系统服务失败与相关服务启停；启动/关机事实；已选网络/DNS、时间同步、日志服务异常。按可信 journal 来源筛选，再以等级与关键事件共同判断，低等级的网卡断连、时间跳变、服务失败不会仅因等级被丢弃。文本模式依赖常见英文消息模式，不声称识别所有发行版、驱动或自定义服务；未知任意服务输出不收。

Nagi 单元接入 panic、原始 stderr 和日志库失败等补漏；已识别的正常 slog JSON/文本输出不再重复入库。启动前未保存、源 journal 已轮换、机器突然断电的日志不能补造，正常 slog 样式的启动前日志也不能仅凭格式证明曾入库。现有容器输出继续由 Docker API 单独采集，不复制容器 journal 输出；不接全量 auditd、防火墙逐包日志、内存转储正文或任意业务文件。

首次与游标失效时默认只回看 journal 仍保留的最近 24 小时；正常重连按持久游标续读，不限为最后十条。选中记录和游标同事务提交，失败不推进；游标已轮换明确留缺口，回看不保证补齐。记录保留原时间、启动批次、服务、优先级和来源游标，消息最多保留 8 KiB 并标记截断，经统一脱敏后写入现有 Runtime 类别，计入共享容量和既有 mesh 查询/近期副本。单条 journal JSON 超过 1 MiB 时停止并标不可用，避免无界内存；不擅自跳过故障位置。

SSH 与 sudo/su 认证另有 `host_ssh`、`host_sudo` 两个开关，默认均关闭，需 `host_journal` 同时开启。启用后从同一 journal 流按服务或内核提供的进程名选取，不额外读 auth.log/secure；不以调用者可自填的 syslog 标签识别来源。只采 SSH 登录接受/断开及识别的认证失败，sudo/su 记录已有认证/提权消息。sudo 的 `COMMAND=` 及其后正文整体隐藏，其他含 command 的非标准消息保守整体隐藏，再经过统一脱敏；不收交互输入或会话录屏。用户名、来源 IP 和会话路径仍属敏感数据，认证记录归 Security 类别，沿用管理员日志查询限制及重要副本通道。

SSH 失败默认每个采集进程的固定一分钟窗口最多保留 100 条明细（`host_ssh_failures_per_minute`，1～1000），其余只累加计数，不建立可被任意 IP 撑大的内存分组；默认每 10 秒尝试保存累计摘要（`host_ssh_summary_seconds`，1～60）。后续其他选中记录推进游标前、重连前及正常关闭时也先保存待写计数，因此摘要可能提前产生。明细和摘要的 count 相加是**观察到的失败日志条数**，不是唯一登录次数：同一次认证可能被 PAM/sshd 分别记多条，源 journal 限流丢弃的消息不能推算进来。原始失败消息被省略的数量另留痕；摘要本身、选中记录和对应读取位置均持久提交后才确认，写失败不越过待保存计数。

一分钟明细窗口在进程重启后重新开始。被强杀时尚未提交的摘要靠未推进的旧游标重读原 journal；若原 journal 同时轮换或被删，只能标缺口，不能承诺找回计数。后期开启认证开关不自动回补已越过共享游标的旧认证记录；关闭开关不删除已经入库的历史。没有新增通知或认证告警规则。

容器终端/命令及节点终端/命令已在实际执行节点录制：面板显式传递既有录制开关，没有开关或开关关闭时节点不擅自录制；兼容旧面板，旧节点则继续原面板录制。新节点即使录制不可用也不让面板偷偷保存正文副本，不阻断终端操作。节点将加密正文存入 `<节点数据目录>/logs/recordings.db`，独立密钥在 `identity/recording.key`；有历史而密钥丢失时停止新增录制、保留原库，不生成替代密钥覆盖。节点内嵌在面板机器时也按节点自己的数据目录保存。

正文沿用 AES-GCM 的录制编号/块号绑定、压缩和摘要格式，FULL 同步提交，默认每 5 秒或 256 KiB 切块，单会话仍保留开头 8 MiB 与结尾 56 MiB、显式标记中间截断；无回显输入只记录字数。数据库/索引/WAL/SHM 计入共享额度，普通录制先于审计清理，活动会话不删。命令、输出、目录可能含秘密，**加密录制不是脱敏文本**，仍要求原审计权限和高权限确认；密钥与数据库必须分开保管，但不承诺抵抗已取得节点 root 权限的攻击者。摘要进入本机审计，新面板只保存节点引用；结束摘要丢失明确标记截断，不能冒充完整落盘。

回放新引用只走 `LogService.ReadRecording` 的 mesh 加密通道，不回退公网控制连接；节点核对现任可信主面板，传输中重查撤权，面板沿用既有审计回放权限。正文不进入普通日志脱敏/近期副本管道，也不进入旧主备 TLS/审计外送路径。节点离线或正文已清理时明确失败。旧正文只在原面板机器导入本地数据库，**不自动转送到历史执行节点**；备用面板回放新正文仍等待其独立 mesh 身份和授权。

**旧录制迁移：** 主面板启动后逐个扫描原 `audit/recordings/`，把原密文原样存进本机顶层 `logs/panel-recordings.db`，继续使用原面板密钥和录制编号/块号；每块先验证认证标签和压缩格式，再把正文与迁移位置同事务 FULL 提交。重启逐块核对已提交前缀并接续；单个源损坏不阻止其他录制。正文不重加密、不重签旧审计链，原哈希仍可关联原密文。读库前只读旧文件，完整导入后从数据库回放；坏块、缺开头、超大块（密文/解压上限 128 MiB）、冲突、取消或空间不足均保留源和未完成位置，不冒充成功。

源文件与目标库同时计入共享额度。迁移未完成的源和数据库块受保护，不能为完成迁移先删唯一原件；完整导入后旧文件才允许按容量回收，导入过程本身不删除源。导入凭据不随正文清理，避免重启把已过期正文从旧文件灌回来。旧节点兼容录制也改写此数据库，不继续生产新的面板录制文件；新数据库正文不通过旧 TLS/外送路径复制。备用面板仍在接收的旧文件不自动迁移，避免把半截同步当成完整历史。原面板已丢失的正文、先前已经清理的块不能补造。

**容器来源的完整性边界：** 记录与读取位置同事务提交；写入失败立即停读重试，不确认未保存的尾部。读取位置不是可轮换历史，不能随删旧日志而删除或倒退；位置也占数据库页数额度。Docker 只有时间过滤而没有持久行号，日志轮换、有限事件回放、断联和时钟回拨都可能造成不可补回的历史，因此每次接入明确记录历史不保证完整；不伪造恢复。正常连接中已观察到的乱序记录照记。输出每行默认最多保留 8 KiB 原始前缀（含 Docker 时间前缀，可配 1～8 KiB），超出显式标记截断及原字节数，仍消费完整行并继续采后面的行；无换行的尾部在正常 EOF 时保存。不会承诺任意应用文本均能自动脱敏。

```json
  "host_lookback_hours": 24,

  "host_sudo": false,
  "host_ssh_failures_per_minute": 100,
  "host_ssh_summary_seconds": 10
}
```

容量只接受 5～10 GiB。指标入库间隔在 10～86400 秒之间且为 10 的倍数；增大间隔会减少统一库中的原始点，告警不会回退读取当前内存值冒充完整历史，窗口证据不足时保持未知。原指标索引库仍按 10 秒采样，为图表与旧历史提供兼容查询。容器发现/状态快照和重试间隔可配 1～3600 秒；行前缀上限可配 1024～8192 字节，保留 JSON 转义与元信息空间。

`host_journal` 默认开启上述最小范围；`host_retry_seconds` 默认 30 秒，可配 1～3600 秒；`host_lookback_hours` 默认 24 小时，可配 1～168 小时。回看范围不代表源或新库承诺保留时长。当前无需、也不会安装额外 journal 服务或提权。

副本传输进度入库频率 `transfer_progress_seconds` 可配 1～3600 秒，默认 5 秒；只调本地历史，不改变备份带宽、重试/取消或既有界面状态更新。开始、每次重试和结束始终尝试记录，不受此频率限制；库不可写只计写入失败，不改变实际传输结果。

录制正文切块间隔 `recording_flush_seconds` 可配 1～60 秒，默认 5 秒；达到 256 KiB 或正常结束仍立即切块。进程崩溃可能丢失尚未提交的尾部；这不是逐字符落盘保证。

升级下载进度入库 `upgrade_progress_seconds` 默认 1 秒，可配 1～3600 秒；不改变下载本身、校验、界面更新和升级权限。配置项不意味着允许自动升级或触发真实下载/重启。

节点/卷文件的复制、移动、改名、压缩和解压任务记录开始、已处理文件/字节、完成/跳过/同名冲突数量、失败或取消；进度 `file_progress_seconds` 默认 1 秒，可配 1～3600 秒。文件实际完成和最终响应回传失败分开，不因浏览器没收到响应就把已完成改成失败。不保存文件正文或全部路径；权限、租约、暂存清理和原 500ms 界面进度不变，拒绝入口仍由原审计记录。

分块上传另存开始/恢复、每块校验与落地结果、提交及放弃事件；成功块才记录新的已存位置，校验失败不确认进度，最终响应丢失不改写本地执行结果。每块是一个有界记录，不逐字节写；不复制文件正文、完整请求参数或用于恢复匹配的文件指纹。授权/租约拒绝仍由原审计留痕，错误文本仍按统一规则脱敏。

额度按统一库及已登记的旧历史 DB/索引/WAL/SHM、节点审计 JSONL、面板审计和录制文件的实际占盘共同控制，不是只加正文长度；20% 留给事务/回收空间，主库页数有硬上限。活动页达到主库预算约 90% 时，清理到约 80%。先清运行日志，再清访问/容器输出，再清原始指标、一般任务，最后才是审计/安全/告警。统一库同级按本机采集序号清最旧的，旧存储按自身历史顺序分批清理；不承诺跨不同存储实现严格全局最旧排序。普通流量不能为自己清掉更重要的记录，重要记录过多时最终也会淘汰可清理的旧审计，并留下清理摘要。

每类别一条累计清理摘要，包含编号包络和数量；包络不表示中间每条都丢失，不能拿它直接宣布某一段完整。来源编号、只增序号和清理摘要跨重启保留。每条正文最多 64 KiB，超长记录显式标记截断；不保留无限正文。读取最多 1000 条，按独占序号游标分页，可筛事件时间的闭开区间、类别、项目和对象。

采集写入失败不改变业务操作的成功/失败：最多使用 500ms 的数据库写入上下文，失败有当前进程计数和每分钟限频的独立 stderr 错误输出，不递归写自己。初始化失败也不会仅因新日志库不可写就停止面板/节点，而是明确输出新日志未入库的错误；内嵌节点不会擅自另开第二份额度。当前直接事务落盘，尚未做高吞吐批写；不能宣称请求洪峰下全部不丢。同步写入成功后本库已提交；机器被 root 攻破、物理磁盘写失败、断电或进程崩溃窗口不在“绝不丢”的承诺内。

**过渡期额度边界：** 已登记旧指标、节点 audit JSONL、面板 audit.db/旧角色归档/副本和录制的物理占盘。未导入的审计源、迁移中的混合 node.db、旧角色归档/旧主备副本和正在录制的文件只计数不擅删；如果保护文件已经占满额度，明确拒绝新增历史并保留源文件，不以“为迁移腾位置”为由先删待迁移历史。因此升级时已有超额文件不承诺立即压到 5 GiB 以下。配置、网段、当前状态和断点不是可淘汰历史。Docker 自身管理的日志文件和业务卷不属于本额度；不会为了凑额度删除容器运行数据。

**监控库分离：** 将 `node.db` 的 `metrics_raw` / `metrics_m5` 分批复制到节点自己的 `logs/metrics.db`；两张表逐条核对、目标提交落盘后，才在一个事务内清空旧指标表，配置与网段不动。迁移源/目标同时计入共享额度；额度不足、取消或值冲突时保留源表和已提交目标，重试不覆盖不同值。采集和图表查询使用分离后的索引库；失败回退混合库时保护配置与网段。旧库整理前检查剩余空间，空间不足不整理。指标历史不再仅按旧的 24 小时/30 天计时删除，而是加入统一空间预算；已被旧版本删除的明细不能补造。

**审计历史导入：** 节点 JSONL 和面板自己的旧审计库在启动时取有界历史快照，逐批导入统一库，记录和读取位置同事务提交；重启接续。已有独立采集的相同历史事实经规范化正文和原始身份/时间对账，毫秒精度的面板旧库不会重复导入纳秒时间的实时副本；正常实时输出绝不据此去重。源文件坏行、查询失败或额度不足时停在已提交位置、保留源库；旧编号缺口明确记录，不伪称所有过去明细完整。面板旧库用持久来源标识区分角色库替换，不依赖文件名；原哈希链、墓碑、加密录制和其验证/回放方式不重签、不覆盖。

启动时另逐个只读导入 `audit-term*.db` 与 `audit-standby-*.imported.db` 旧角色归档；一个失败不跳过其他归档。已有来源标识则沿用，没有时从首个现存链哈希/墓碑派生稳定标识，不向归档添加元数据，改名/重启不会从头重灌。只读连接仍读取残留 WAL，不用忽略 WAL 的 immutable 模式；读失败显式保留未完成状态。原归档继续算容量并保护、不因正文导入就删除或重签原链；尚未迁移的旧版本 schema 明确报错，不擅自升级原件。备用正在收到的旧同步链不当成本机新事实自动导入。

## 按需查询与告警

### 节点细分运行统计

`node_details` 默认开启，可关闭新增的 Linux 内核/进程细分来源；采集仍随原指标每 10 秒运行，统一日志按 `metrics_every_seconds` 保存。包含总计和各核 CPU 模式、负载与运行/阻塞进程、缓存/交换区/脏页、各网卡字节/包/错误/丢包与速率、各块设备读写量/次数/耗时/队列、CPU/内存/I/O 压力、TCP 重传/监听溢出及 UDP 缓冲错误、连接跟踪用量、Nagi CPU/内存/线程/文件描述符。各已选文件系统另保存容量与 inode。磁盘分区/映射设备可能重叠，不能直接相加当作物理总量；CPU guest 已含在 user/nice 中，不重复加入利用率分母。

缺失的内核功能、权限不足或读错会记录来源不可用，缺字段不补零；首次、重置、断档后的计数器不计算速率。不修改原告警指标含义，不把细分观测自动变成新规则。不读取进程命令行、环境变量、网络载荷或业务文件；非 Linux 开发机不伪造这些数据。Windows 编译/回归与隔离 Linux 容器内的真实 `/proc`、夹具中的单位换算/断档/重置分别验证。

### 容器实例资源明细

受 Nagi 管理的运行中容器每 10 秒随原指标读取一次实例明细：CPU 累计用户/内核时间与限流次数/时间、进程数与上限、内存原始用量/峰值/上限/触限次数、各网卡包/字节/错误/丢包，以及各块设备读写字节/次数/服务和等待时间。实例编号独立保存，服务汇总及告警原口径不变；设备 Total 不再与 Read/Write 相加。Docker/cgroup 未返回的字段保持缺失，不补零；读取失败单独标不可用。非托管容器的输出和事件已采集，但资源明细仍只针对托管实例。历史沿用指标入库间隔和共享容量，不采进程命令或环境。

### 具体响应码与延迟证据

部署 webhook 另存已接受、排队/重复触发合并、后台部署开始/输出/最终结果；每次真正执行有独立任务编号。202 只表示入口已接受或排队，后台可能仍失败；不改原内存队列、合并逻辑和重启后不续跑的边界，不把它当持久任务队列。记录归面板本机，执行节点仍保留自己的任务事实，不将两边输出算成两次部署；不保存 hook 令牌、完整 URL 或请求正文，输出和错误沿用统一脱敏及长度限制。

业务 HTTP 规则在原十秒统计中补记各具体状态码的区间次数、区间秒数、请求数、参与耗时的请求数、实际保留的延迟样本数和全部非 WebSocket 请求的最大耗时；只有分位数使用原来的最多 2048 个等概率样本，次数与最大值不抽样。已出现的状态码在后续无请求区间明确记零，规则一天无活动后停止；尚未见过的状态码不建立序列。原速率/状态码段与告警契约不变，不将各节点分位数直接平均。未匹配规则的请求仍只记录逐请求事实，不混入业务规则统计；面板自身请求也各自保存实际状态和耗时，未伪称已增加面板聚合统计。

节点日志库打开后记录启动中、初始化完成和退出/启动失败，保留版本、内嵌角色、持续时长及错误；未初始化完成不会记 ready，进程被强杀不会伪造退出。控制连接记实际建立及每次尝试结束（可能未连接就失败），含面板指纹、时长和取消/错误。代理规则应用结果与证书申请成功/失败也直接入库，不依赖告警开关；不复制代理配置、证书私钥或挑战正文。最早的升级守护/日志库打开之前仍是原终端输出范围。

### 内网转发与出站观察

内网计划成功保存后只记录摘要和代理/放行/入口数量，不复制完整计划。TCP 记录代理连接的开始、观察结束和每次远端握手的拒绝/接受/连接失败；接受只表示对方接受转发，不代表应用请求成功。UDP 记录复用通道的建立、结束和远端握手结果，不把一条复用通道算成一个客户端或逐包日志。保留项目、目标服务、端口、公开节点标识、耗时；不采集数据载荷。

出站限制的可用性变化和已观察到的目标写入安全类别，不依赖告警开关。命中来源沿用内核集合每 5 秒读取、同容器/目标 10 分钟去重；记录当时策略而不声称它证明某个包已被丢弃，也不是完整连接流水。读取失败、内核限速、集合过期及观察前容器消失仍可能缺失，不能据此推导没有出站行为。以上历史仍受本机共享容量限制，不修改 mesh 身份、选路、转发或原告警语义。

### 租约与顶替决策

持有租约时的容器代管重启使用同一后台队列，记录实际启动尝试、退出码、策略、实例和 Docker 返回结果；成功只称“接受启动”，不称应用健康。退避等待、已运行和策略不允许时不逐轮刷记录。重启次数与退避算法不变；启动调用前后两条都受队列缺口约束，强杀可能只留下尝试而没有结果，不据此推断失败或成功。

投票方记录自己同意/拒绝的轮次、调用节点、持有者及转让目标；请求方另记实际收到的投票或通信错误。续约记录票数、是否续上及有效期；等待/接受/撤销人工顶替确认、停止/恢复尝试、接手恢复、切回步骤和本地转为热备另记事件。接手租约不等于应用已经恢复，切回本地步骤完成不代表远端应用已验证成功；租约的权威仍是原投票文件与既有规则。

这些事件不能同步写盘拖延租约：使用有界后台队列，`decision_queue_entries` 默认 256，可配 1～4096。入队不等于持久保存，满队列或写入失败计入缺口，存储恢复后记录不完整标记；正常关闭最多尝试排空约 2 秒，剩余向独立 stderr 报告。进程强杀可丢失未落盘队列，不能声称关键决策历史绝不丢。队列不保留外部命令/配置/文件正文，不改变投票、续约、停止截止时间或任何 mesh 身份/选路。

### 主面板近期副本

mesh 本机与逐成员的只读状态随 `metrics_every_seconds` 留史：路径/直连端点/中转者、本地端口、握手时间、累计字节、RTT、FEC/QUIC、双向丢包及是否测到、探测数量与是否听到。逐成员单独成记录，保留未知标记和 64 位计数；没有启用额外探测或测速。它是定期观察，不承诺捕捉两次观察之间的短暂切换，也不能把缺少成员记录当成移除/离线；mesh 未启动时明确记录不可用。复用现有公开状态，不改 mesh 选路和身份。

手动 mesh 探测/测速在节点的既有 RPC 记录入口保存调用面板、对端、所选模式、实际 RTT/上下行字节速率、QUIC 与 WireGuard 对照是否测到及失败结果；失败不填零吞吐，未测到的对照不造数。旧操作审计仍跳过这些只读方法，不重签旧链；只观察用户实际发起的请求，不额外测速，不改并行开发中的 mesh 文件。该测试以隔离 gRPC 返回夹具核对日志契约，不是实际链路性能实测。

节点主动经 mesh 向每个已信任、可用的主面板发送本机统一日志；不使用公网面板 TLS/控制连接，也不启用节点互备。主面板只接受 mesh 已认证公钥对应的已批准、未撤销、未隔离的登记节点，不信任请求中声称的节点编号。数据库或隔离状态无法读取时拒绝接收。所有九类已有统一日志都纳入；各类别独立确认，普通输出不能靠占用序号阻塞审计。审计/安全/告警/日志库事件默认每秒尝试，其余每 10 秒尝试；均可配 1～300 秒。这是正常可达时的尝试频率，不是断网/过载时的送达保证。

面板在自己的顶层 `logs/recent.db` 保存已脱敏副本，记录与确认位置同一事务、FULL 同步提交后才确认；确认应答丢失、节点或面板重启后重新读取面板位置并补传。重复批次不覆盖已确认的事实。发送分批限量（每类别每轮最多 128 条，重要类约 64 KiB、普通类约 256 KiB；单条上限保留），优先重要类，持续积压时逐轮接续，不承诺瞬间补齐；节点已经清掉的原件仅发送清理摘要，不补造正文。面板分别保存源端清理摘要与自己淘汰副本的摘要。节点重建库时使用新来源，不复用旧序号。

副本按面板实际收到的时间保留目标 24 小时，不用远端事件时间判断过期；复制迟到的旧事实时仍能保留证据。每分钟及读写时检查过期。`recent_hours` 可配 1～24 小时、`recent_capacity_mib` 可配 16～1024 MiB（默认 1 GiB），索引/WAL/SHM 都计入，另留事务余量；这是本机共享 5～10 GiB 内的子额度，绝非再加一份额度。达到空间上限可以早于 24 小时清理，先普通后审计，审计最终也有界；只保留确认元数据以防重新灌回已删副本。缩小副本配置时按同样顺序收缩并保留删除摘要，不改已确认位置。当前没有额外的每节点副本限额，单个高流量节点仍可能挤占普通副本。

管理员可在 `NodeLogService.QueryNodeLogs` 显式选择 `recent_copy`，按节点、**单个类别**、来源及原序号查询，即使节点离线也能读。首屏可省略来源以取该类别最近接收的来源，翻页必须固定来源；不同类别各有确认位置，不混用一个分页游标。返回值标记这是有限副本，未收到与已过期/清理分开，不自动拿副本冒充在线节点完整历史。普通实时查询失败仍明确失败。面板「日志」页面已接入这些查询。

备用面板可打开自己先前留下的副本并保留读取边界，但不会从主备 TLS 同步接新副本；节点暂不向 standby 发送，备用接收端明确拒绝。待 mesh 支持备用独立成员身份及权限后再接独立确认/补传，不由日志模块擅自授予身份；主备切换后的完整副本连续性目前**尚未实现**。发送前重查信任和角色，mesh 不可达时保留节点本地原件并重试，原件仍受节点本身容量限制，不保证长期断线后可补齐。

`LogService.QueryLogs` 和 `LogService.QueryMetrics` 只注册在现有 mesh 服务上；面板的节点日志与原图表查询经 mesh 取数，不回退控制 RPC。`NodeLogService.QueryNodeLogs` 另可显式选 `panel_local` 读取当前面板本机的 `logs.db`，不经网络且不能同时指定节点或近期副本。日志查询支持来源核对、序号分页、时间/类别/项目/对象过滤、字面关键字子串及事件种类前缀，并返回清理摘要和写入失败计数；过滤在分页前执行。统一日志查询仍仅管理员可用；原项目图表继续按现有项目权限开放。节点端仍核对可信面板、指标项目归属与信任撤销。备用面板暂无新 mesh 授权，不擅自开通。

节点告警从日志模块读取完整、近期采样及本地历史指标；采样缺块、过期或不存在时不靠内存值判恢复。规则关闭/对象移除暂保留未知事件而非伪造恢复。通知待发队列只持久化当前事件的发送意图，不保存旧正文或密钥；重试前重新核对事件、阶段、渠道、目标及当前权限，恢复会替代积压的故障通知，旧格式队列舍弃。此处没有调整阈值、调用模型或实际对外发送；面板告警生命周期和聚合通知仍需后续完善。

## 日志页面

导航与主路由使用「日志」（`/logs`），替换原审计页面；`/audit`、旧活动及设置书签跳转到新页面的「审计与录制」，保留原审计查询、父子详情、导出、哈希链校验及高权限确认后的回放。原链和统一日志的脱敏副本不混称为同一份可验证证据。

- **权限**：入口仍要 `panel.audit`，原审计 API 的权限及范围不变；「全部日志」与 `NodeLogService` 仍仅管理员可用，即使筛选单个项目也不放宽。界面不因项目筛选而授予额外权限。
- **查询**：默认读取当前面板本机；可选节点原始日志（mesh）或显式选该节点的面板近期副本。按类别、项目、事件时间的闭开区间及关键字筛选，每页最多 50 条并按采集序号从早到晚读取；实际页大小还受已有字节上限约束。时间输入使用浏览器本地时区，结束时间不含。条件写入地址，翻页固定库来源与原序号，刷新重新从头查询；不会静默切到另一个来源。
- **类别**：包括审计、访问、容器输出、任务与事件、安全、告警、运行、宿主机、指标样本及日志库与采集。宿主机使用 `host.` 前缀；近期副本一次只读一个类别，宿主机选项只读运行类别的宿主机记录，SSH/sudo 应选安全类别。
- **缺口**：始终说明“无记录不代表无事”。分别查询运行及日志库类别的 `history_complete:false` 边界证据，沿用所选时间窗口，但不受主列表的项目、类别或关键字过滤，避免把采集失败隐藏成正常空白；证据可分页、点开看原始时间及 `since` 等字段。没有边界记录、或未收到某类别副本，都不能证明完整。清理摘要分别标明源端清理与副本过期/清理，显示累计数量与序号包络；现有 API 没有确切清理时间区间，页面明确标成时间未知，不按序号伪造时间段。写入失败计数也单独警示。
- **详情与回放**：条目详情展示来源、序号、类别、项目、对象、事件/接收时间及已保存脱敏 JSON；不完整、截断与副本边界不会被当成完整正文。原审计的 `recording_id` 与节点 `terminal.recording` 摘要均复用已有回放及高权限确认，节点正文仍经 mesh 获取；不能确定执行节点的本机摘要不猜远端节点。手机筛选单列，时间并入日志次行，详情使用底部 Sheet。

本次仅增加 `LogQuery.search = 9`、`LogQuery.kind_prefix = 10`、`NodeLogQuery.panel_local = 4`，同步生成 Go、Web TypeScript 与 Android Java 消息；没有新增 RPC、改变 mesh 身份/角色或启用备用接收。

## 接下来与 mesh 的边界

### 来源覆盖与明确未接入的范围

| 来源 | 当前可查事实 | 没有承诺的部分 |
| --- | --- | --- |
| 面板请求与操作 | 所有经过面板请求中间件的 HTTP 结束事实、旧审计的脱敏副本、webhook 接受/合并/后台结果 | 进程强杀前未结束的请求；逐个认证分支的新增专用证据；请求正文 |
| 容器 | Docker 可读输出、引擎事件、状态快照；托管实例资源明细；代管重启尝试与结果 | Docker 已轮换的旧输出、自动删除前未读到的尾部；任意应用文件和外部日志驱动；非托管实例资源明细 |
| 指标与请求 | 原始指标、Linux 细分资源、具体 HTTP 状态/延迟样本证据、L4 会话 | 所有磁盘/接口都不遗漏的保证；完整延迟分布或逐包载荷；面板专用聚合统计 |
| 任务 | 部署/快照等节点任务输出，文件操作/分块上传，镜像检查/拉取/清理，升级，备份发送/接收/排队 | 旧版本从未存下的输出；入口接受等于远端完成；业务任务持久队列 |
| 网络与租约 | mesh 定期状态与手动诊断结果、内网握手/连接、出站可用性/有界命中、投票/续约/接管/切回 | 每次瞬时路径切换、内核每个连接/丢弃包、远端应用实际健康；这些需要所属模块提供额外事实 |
| 录制 | 执行节点加密录制、mesh 回放、原面板机器旧录制有断点导入 | 不把面板旧录制冒称已搬回历史执行节点；不自动复制大附件到近期副本 |
| 程序与安全 | 已接入 logger 的运行输出、节点生命周期、代理/证书结果、既有安全/审计入口；已选宿主机 journal 与可选 SSH/sudo | 未保留的启动早期输出、未选系统服务、完整宿主机 journal、全部客户端崩溃 |
| 主面板副本 | 已批准节点 mesh 身份校验、持久确认/补传、有界近期副本、明确选择副本的离线查询与日志页面 | 备用独立接收/主备对账和切换连续性；每来源 128 MiB 子限额 |
| 告警 | 节点从本地日志取统计、证据不足不恢复、当前发送意图替换旧队列 | 面板完整告警生命周期、人工处理界面、聚合通知和模型报告 |

原日志清单中的三类候选入口现按以下范围处理，不能因“记录所有类别”就遍历业务卷或采集全机所有用户的活动：

- **宿主机服务/内核日志**：已按用户确认的最小范围接入 journal，SSH/sudo 已提供默认关闭的独立开关；范围与完整性边界见“宿主机日志”，不做全量系统审计。非 systemd 环境暂标不可用，不擅自扫描文件。
- **应用文件/外部日志驱动**：建议只接显式登记的节点、目录或驱动，以普通文件/安全路径和轮转断点读取；需要实际允许名单，不能猜一个业务目录递归扫描。
- **浏览器/Android 诊断**：建议仅用户主动提交脱敏异常，不采输入/剪贴板，不默认后台遥测；是否需要这一入口仍需确认。

应用文件/外部日志驱动与客户端诊断仍未接入，等待用户另行决定，不因宿主机最小范围获准而一并开启。备用 mesh 独立身份和授权仍由 mesh 模块提供，日志模块不自行绕过；候选范围确认也不会自动解锁备用接收。

1. 继续逐项核对剩余本地来源；备份接收/排队、旧角色审计归档导入、节点录制和原面板机器旧录制正文导入已接入。
2. 统一查询/指标历史及新节点录制回放已接 mesh；旧专用审计阅读器继续兼容，不能把本机旧录制导入称为已把历史转送至原执行节点。
3. 主面板近期副本已接通（上述容量/确认/补传/查询边界）；旧控制通道和主备 TLS 同步不作为新日志的兜底。
4. 备用面板入 mesh 后再接其独立接收/确认/补缺、切换衔接；继续完善面板告警生命周期和汇总通知。

需要 mesh 提供而日志模块不自行实现的能力：备用面板独立身份和可信成员资格；节点向主/备分别建立连接且主故障后仍有可用的直连/中转路径；按用户/项目/角色校验查询、接收、补缺权限；信任撤销和只读备用授权；独立重连事件。每个面板的持久确认由日志模块负责；数据不得回落公网面板端口。日志模块提供稳定来源、序号、正文和清理摘要，不改变身份/选路文件。新增协议集中在 `logs.proto`，复用原指标查询消息，未修改 `common.proto` / `panel.proto` 的字段。
